### 2.1 关键字段说明

| 字段 | 为什么这么设 |
|---|---|
| `dragDropEnabled: false` | **锁死。** TipTap 块把手（FR-311）要求它，见 [ADR-014](05-ADR/ADR-014-拖放机制取舍.md)。改成 `true` 会静默破坏块拖拽排序 |
| `decorations: false` | 自绘标题栏（FR-610）。Windows 上这是唯一途径 —— `titleBarStyle` **仅 macOS 生效** |
| `visible: false` | 前端就绪后 `window.show()`，消除白屏闪烁 |
| `withGlobalTauri: false` | 两个参考项目都设了 `true`，我们不需要往 `window` 上挂全局对象 |
| `csp` 显式设置 | note-gen 与 TMD 都用 `null`（不设 CSP）。我们设死，其中 `connect-src 'none'` 是 NFR-601「无网络」的技术保障 |
| `assetProtocol.scope: []` | 启动时空 scope，用户选定目录后动态授权（NFR-604），不用 `["**"]` |
| `installMode: "currentUser"` | 免管理员权限安装，注册表写 `HKCU` |

## 3. 图标

### 3.0 现状：已生成，可直接用

`src-tauri/icons/` 已备好，**不需要再跑 `tauri icon`**：

```
src-tauri/icons/
├── icon.ico            ★ 图层 [32,16,24,48,64,128,256]，32px 在首位，alpha 完整
├── icon.png            256×256 RGBA
├── icon-source.png     256×256 RGBA（母版）
├── 32x32.png
├── 128x128.png
└── 128x128@2x.png      256×256
```

全部由 **`logo.ico` 的 256×256 图层**下采样而来。

### 3.0.1 三个必须知道的事实

| # | 事实 |
|---|---|
| 1 | **`logo.png` 不能作为图标源。** 它是 8-bit **RGB 无 alpha**（压白底导出版），喂给 `tauri icon` 会得到白底方块图标。用户指定的 `logo.ico` 才是真源，其 alpha 通道完整 |
| 2 | **原 `logo.ico` 首项是 16x16，不合规。** Tauri 要求 32px 排第一，已在生成时修正 |
| 3 | ⚠️ **logo 的文档内页是透明的。** 深色背景（Win11 深色任务栏、墨夜主题 `#0f172a`）下深色文字线条与笔身几乎不可见，读起来像空框。设计层面问题，留待实现阶段按需处理 |

> ⚠️ `logo.png` 与 `logo.ico` **几何不对齐**（归一到 256 后，png 非白内容 bbox `(63,47,209,208)` vs ico 不透明 bbox `(25,15,231,241)`），是两次不同尺度的导出。**不要试图合并两者的 RGB 与 alpha。**

### 3.1 如需重新生成

```bash
# 注意：不要用 logo.png 作为输入（无 alpha）
# 正确做法是从 logo.ico 提取 256 层作为母版，或提供一张带透明通道的方形 PNG
pnpm tauri icon <带透明通道的方形PNG>
```

若用 ImageMagick 从头做 ico，**32 必须放在 auto-resize 列表首位**：

```bash
magick source.png -define icon:auto-resize=32,16,24,48,64,256 src-tauri/icons/icon.ico
```


### 3.2 `.ico` 硬要求（官方）

> 必须包含 **16 / 24 / 32 / 48 / 64 / 256** 六个尺寸，且 **32px 层必须排在第一个**（dev 期渲染最佳）。

校验脚本（阶段 0 加进 `gate:0`）：

```js
// scripts/verify-ico.mjs —— 解析 ICO 目录项，断言尺寸集合与首项
const REQUIRED = [16, 24, 32, 48, 64, 256];
// ICONDIR: 6 字节头，之后每项 16 字节 ICONDIRENTRY
// entry[0]=width (0 表示 256), entry[1]=height
```

若 `logo.ico` 不满足，用 `tauri icon` 生成的版本，或用 ImageMagick 从 `logo.png` 重新生成：

```bash
magick logo.png -define icon:auto-resize=32,16,24,48,64,256 src-tauri/icons/icon.ico
```

注意 `auto-resize` 列表的**第一个是 32**，以满足「32px 在首位」。

### 3.3 三种图标是分开解析的

| 图标 | 取自 | 失败后果 |
|---|---|---|
| **exe 图标** | `bundle.icon` 中**第一个 `.ico` 结尾的条目**，兜底 `icons/icon.ico`（`tauri-build` 经 `tauri_winres`） | **文件不存在直接构建失败** |
| **默认窗口图标** | Windows 上先找第一个 `.ico`，没有再找第一个 `.png`（`tauri-codegen`） | 窗口显示默认图标 |
| **安装包图标** | `bundle.windows.nsis.installerIcon` / `uninstallerIcon` / `headerImage` / `sidebarImage` | ⚠️ 默认全为 `null`；**为 null 时是否回落到 app 图标，官方文档未说明** → 显式指定 |

### 3.4 NSIS 图片规格

| 文件 | 尺寸 | 格式 |
|---|---|---|
| `nsis/header.bmp` | **150 × 57** | BMP（24 位，无 alpha） |
| `nsis/sidebar.bmp` | **164 × 314** | BMP（24 位，无 alpha） |

### 3.5 每窗口图标

`app.windows[]`（`WindowConfig`）**没有 `icon` 字段**。运行时设置：

```rust
use tauri::include_image;
WebviewWindowBuilder::new(&app, &label, url)
    .icon(include_image!("./icons/32x32.png"))?   // 路径从 CARGO_MANIFEST_DIR 解析
    .build()?;
```

本项目所有窗口用同一图标，所以依赖默认行为即可（FR-1007）。

## 4. WebView2 分发

`bundle.windows.webviewInstallMode` 全部可选值：

| `type` | 需联网 | 体积增量 | 说明 |
|---|---|---|---|
| **`downloadBootstrapper`** | 是 | **0 MB** | **默认，本项目采用** |
| `embedBootstrapper` | 是 | ~1.8 MB | Win7 + MSI 场景更好 |
| `offlineInstaller` | 否 | **~127 MB** | 离线环境 |
| `fixedRuntime` | 否 | **~180 MB** | 需配 `path`；**安全补丁要自己跟** |
| `skip` | 否 | 0 MB | 不推荐（用户没装就打不开） |

除 `skip` 外都有 `silent`（默认 `true`）。另有 `bundle.windows.minimumWebview2Version`。

**选 `downloadBootstrapper`**，理由：NFR-110 要求安装包 ≤ 30MB，其余选项都会爆预算。官方称 WebView2 Runtime 自 Windows 10 2018年4月发行版（≈1803）及 Win11 起「distributed as part of the operating system」；Win10 靠 Microsoft Update 推 Evergreen。企业/精简镜像仍可能缺失 → 首启动检测缺失时给友好提示（阶段 14.12）。

## 5. 文件关联

### 5.1 `fileAssociations` 完整 schema

| 字段 | 类型 | 默认 | Windows 语义 |
|---|---|---|---|
| **`ext`（必填）** | `string[]` | — | 前导 `.` 自动剥离 |
| `name` | `string?` | `ext[0]` | **就是 ProgID**（macOS 上同字段是 `CFBundleTypeName`，一字段双语义） |
| `description` | `string?` | `"{EXT} File"` | **Windows-only**，显示在资源管理器「类型」列 |
| `role` | enum | `Editor` | **macOS-only** |
| `rank` | enum | `Default` | **macOS-only** |
| `mimeType` | `string?` | — | **Windows 完全不用** |

> **务必显式写 `name`。** 不写会创建一个字面量叫 `md` 的 ProgID，极易与其他软件冲突。

### 5.2 为什么用 NSIS 而不是 MSI

| | NSIS | MSI (WiX v3) |
|---|---|---|
| 机制 | `APP_ASSOCIATE` 宏直接 `WriteRegStr` | WiX `<ProgId Advertise="yes">` 广告式 |
| ProgID 生成 | `association.name \|\| ext` | `{{product_name}}.{{ext}}`（与 NSIS 不一致） |
| 双击打开 | ✅ 开箱可用 | ✅ |
| **右键「打开方式」** | 🔴 不出现 | 🔴 **完全不出现** |
| 交叉编译 | ✅ | ❌ 只能在 Windows 构建 |

[tauri#9803](https://github.com/tauri-apps/tauri/issues/9803)（至今 OPEN，报告者是 Tauri contributor）原文：NSIS「doesn't list the app on right click」；MSI「With msi it doesn't list it at all.」

**➜ MSI 在文件关联上明确更差，不用。`bundle.targets: ["nsis"]`。**

### 5.3 两条打开路径

| 路径 | 走什么注册表 | NSIS 是否自动写 |
|---|---|---|
| **双击文件** | `HKCU\Software\Classes\.md` 默认值 = ProgID → `HKCU\Software\Classes\NoteBoard.Markdown\shell\open\command` | ✅ **已自动写好，开箱可用** |
| **右键 → 打开方式** | `OpenWithProgids` / `Applications\<exe>` | 🔴 **完全没写** |

Tauri NSIS bundler 源码中，`OpenWithProgids`、`OpenWithList`、`Applications\<exe>`、`SupportedTypes`、`FriendlyAppName`、`Capabilities`/`RegisteredApplications` **全部缺失**；且 `SHChangeNotify` 宏存在但**从不被调用**。

### 5.4 `nsis/hooks.nsh`（必须手写）

```nsis
; NoteBoard —— 补齐 Tauri NSIS bundler 未写入的「打开方式」注册项
; 依据：https://learn.microsoft.com/en-us/windows/win32/shell/how-to-include-an-application-on-the-open-with-dialog-box
; MS 原文：'For each file type, add your application to the OpenWithProgIds registry subkey'
;          'The OpenWithProgids subkey is preferred to OpenWithList'

!macro NSIS_HOOK_POSTINSTALL
  ; ── 应用自身的 Applications 项 ──
  WriteRegStr SHCTX "Software\Classes\Applications\${MAINBINARYNAME}.exe\shell\open\command" "" \
    "$\"$INSTDIR\${MAINBINARYNAME}.exe$\" $\"%1$\""
  WriteRegStr SHCTX "Software\Classes\Applications\${MAINBINARYNAME}.exe" \
    "FriendlyAppName" "${PRODUCTNAME}"

  ; ── SupportedTypes：让「打开方式」知道我们支持哪些扩展名 ──
  WriteRegStr SHCTX "Software\Classes\Applications\${MAINBINARYNAME}.exe\SupportedTypes" ".md" ""
  WriteRegStr SHCTX "Software\Classes\Applications\${MAINBINARYNAME}.exe\SupportedTypes" ".markdown" ""
  WriteRegStr SHCTX "Software\Classes\Applications\${MAINBINARYNAME}.exe\SupportedTypes" ".txt" ""
  WriteRegStr SHCTX "Software\Classes\Applications\${MAINBINARYNAME}.exe\SupportedTypes" ".json" ""
  WriteRegStr SHCTX "Software\Classes\Applications\${MAINBINARYNAME}.exe\SupportedTypes" ".yaml" ""
  WriteRegStr SHCTX "Software\Classes\Applications\${MAINBINARYNAME}.exe\SupportedTypes" ".yml" ""
  WriteRegStr SHCTX "Software\Classes\Applications\${MAINBINARYNAME}.exe\SupportedTypes" ".xml" ""
  WriteRegStr SHCTX "Software\Classes\Applications\${MAINBINARYNAME}.exe\SupportedTypes" ".excalidraw" ""

  ; ── OpenWithProgids：把我们的 ProgID 挂到各扩展名下 ──
  WriteRegStr SHCTX "Software\Classes\.md\OpenWithProgids"         "NoteBoard.Markdown" ""
  WriteRegStr SHCTX "Software\Classes\.markdown\OpenWithProgids"   "NoteBoard.Markdown" ""
  WriteRegStr SHCTX "Software\Classes\.txt\OpenWithProgids"        "NoteBoard.Text"     ""
  WriteRegStr SHCTX "Software\Classes\.json\OpenWithProgids"       "NoteBoard.Json"     ""
  WriteRegStr SHCTX "Software\Classes\.yaml\OpenWithProgids"       "NoteBoard.Yaml"     ""
  WriteRegStr SHCTX "Software\Classes\.yml\OpenWithProgids"        "NoteBoard.Yaml"     ""
  WriteRegStr SHCTX "Software\Classes\.xml\OpenWithProgids"        "NoteBoard.Xml"      ""
  WriteRegStr SHCTX "Software\Classes\.excalidraw\OpenWithProgids" "NoteBoard.Board"    ""

  ; ── 刷新 Shell 缓存（Tauri 从不调用，必须自己来）──
  ; SHCNE_ASSOCCHANGED (0x08000000) | SHCNF_FLUSH (0x1000)
  System::Call "shell32::SHChangeNotify(i,i,i,i) (0x08000000, 0x1000, 0, 0)"
!macroend

!macro NSIS_HOOK_POSTUNINSTALL
  DeleteRegKey SHCTX "Software\Classes\Applications\${MAINBINARYNAME}.exe"
  DeleteRegValue SHCTX "Software\Classes\.md\OpenWithProgids"         "NoteBoard.Markdown"
  DeleteRegValue SHCTX "Software\Classes\.markdown\OpenWithProgids"   "NoteBoard.Markdown"
  DeleteRegValue SHCTX "Software\Classes\.txt\OpenWithProgids"        "NoteBoard.Text"
  DeleteRegValue SHCTX "Software\Classes\.json\OpenWithProgids"       "NoteBoard.Json"
  DeleteRegValue SHCTX "Software\Classes\.yaml\OpenWithProgids"       "NoteBoard.Yaml"
  DeleteRegValue SHCTX "Software\Classes\.yml\OpenWithProgids"        "NoteBoard.Yaml"
  DeleteRegValue SHCTX "Software\Classes\.xml\OpenWithProgids"        "NoteBoard.Xml"
  DeleteRegValue SHCTX "Software\Classes\.excalidraw\OpenWithProgids" "NoteBoard.Board"
  System::Call "shell32::SHChangeNotify(i,i,i,i) (0x08000000, 0x1000, 0, 0)"
!macroend
```

四个可用 hook 名：`NSIS_HOOK_PREINSTALL` / `POSTINSTALL` / `PREUNINSTALL` / `POSTUNINSTALL`。

### 5.5 hooks.nsh 的两个坑

| 坑 | 说明 |
|---|---|
| 🔴 **不能 `!include` 外部 nsh** | [tauri#11837](https://github.com/tauri-apps/tauri/issues/11837)（OPEN）。所有内容必须写在这一个文件里 |
| ⚠️ **可用变量未文档化** | `${MAINBINARYNAME}` / `SHCTX` / `${PRODUCTNAME}` 官方只列了 4 个 hook 名，没列可用变量。**必须实测确认**（阶段 0 验证 C 顺带验） |

### 5.6 Win11 新式右键菜单

进「打开方式」子菜单**不需要** MSIX。只有想在**顶层**右键菜单加自定义命令才需要 `IExplorerCommand` + sparse package，而 **Tauri bundler 完全不支持这套** → 不做。

### 5.7 取启动参数

Windows 上**只能读 argv**：

- `RunEvent::Opened { urls }` **仅 macOS/iOS/Android**
- [tauri#13615](https://github.com/tauri-apps/tauri/issues/13615) 请求桌面 open-file 事件已 **closed as not planned**

```rust
// bootstrap/cli_args.rs
pub fn parse_paths_from_args() -> Vec<PathBuf> {
    std::env::args_os()          // ★ 用 args_os() 而非 args()，避免非 UTF-8 路径被 lossy 替换
        .skip(1)                 // argv[0] 是 exe 自身
        .filter_map(|a| {
            let s = a.to_string_lossy();
            if s.starts_with('-') { return None; }        // 跳过开关
            // 文件可能以 file:// 形式到达
            if let Ok(url) = url::Url::parse(&s) {
                if url.scheme() == "file" {
                    return url.to_file_path().ok();
                }
            }
            Some(PathBuf::from(a))
        })
        .collect()
}
```

**不用 `tauri-plugin-cli`** —— 它是 clap 封装，参数必须预声明，对「任意文件路径」这个场景不合适。
**不用 `tauri-plugin-deep-link`** —— 它只管 URL scheme，不管文件关联。

## 6. 单实例

```toml
[target."cfg(windows)".dependencies]
tauri-plugin-single-instance = "2"
```

```rust
tauri::Builder::default()
    // 🔴 必须第一个注册。官方原文：
    // "The Single Instance plugin must be the first one to be registered to work well."
    .plugin(tauri_plugin_single_instance::init(|app, argv, _cwd| {
        let paths: Vec<PathBuf> = argv.iter().skip(1)      // argv[0] 是 exe 自身
            .filter(|a| !a.starts_with('-'))
            .map(PathBuf::from).collect();

        let handle = app.clone();
        // 🔴 回调运行在 WM_COPYDATA 同步窗口过程里；
        //    直接建窗会死锁（wry#583）。必须切线程。
        std::thread::spawn(move || {
            route_open_paths(&handle, paths);   // 转发到已有窗口 or 建新窗口
        });
    }))
    .plugin(/* 其余插件 */)
    .run(tauri::generate_context!())
```

### 6.1 底层机制（源码 `platform_impl/windows.rs`）

不是 named pipe：

- **检测**：`CreateMutexW(null, true, "{identifier}-sim")` + `GetLastError() == ERROR_ALREADY_EXISTS`
- **传参**：`FindWindowW("{id}-sic", "{id}-siw")` → **`SendMessageW(hwnd, WM_COPYDATA, ...)`**，payload = `"{cwd}|{env::args() 用 | 连接}"`，魔数 tag `1542`
- 第二实例执行 `app.cleanup_before_exit()` + `std::process::exit(0)`

### 6.2 与多窗口共存

**单实例只拦进程，不拦窗口。** 它做的是 `CreateMutexW` 进程级互斥，对窗口数量零限制。多窗口 = 同一进程里 N 次 `WebviewWindowBuilder`。

> ⚠️ v2.tauri.app 的示例把它放在 `.setup()` 里注册 —— 那不可能是「第一个」。**按 README 写法放 builder 链首。**

### 7.1 两条红线

| 红线 | 说明 |
|---|---|
| 🔴 **运行时建的窗口默认无 IPC 权限** | 官方原文：「If a webview or its window is not matching any capability then it has **no access to the IPC layer at all**.」→ `windows` 必须用 `nb-*` 覆盖 |
| 🔴 **`core:webview:default` 不含 `allow-create-webview-window`** | 必须显式加，否则前端建窗调用被拒 |

### 7.2 fs scope 的动态授权（NFR-604）

**不用编译期 `fs:scope: ["**"]`**（note-gen 与 TMD 都这么干了，安全上很激进）。做法：

1. `capabilities` 里不给静态路径 scope
2. 用户通过对话框选定文件/目录后，Rust 侧调用 `fs_scope.allow_directory(path, recursive)` 动态授权
3. 命令行参数传入的路径同样动态授权
4. 授权记录不持久化 —— 每次启动重新按实际打开的文件授权

> 这样即使前端被注入恶意脚本，也只能访问用户本次会话主动打开过的路径。

## 8. Vite 配置要点

```ts
// vite.config.ts
export default defineConfig({
  base: './',                       // ★ Tauri 用 file:// 加载，必须相对路径
  plugins: [react(), tailwindcss()],
  server: { port: 1420, strictPort: true },   // ★ 必须与 devUrl 一致
  build: {
    target: 'chrome105',            // WebView2 基线
    rollupOptions: {
      output: {
        manualChunks: {
          // 强制重模块独立成 chunk，配合动态 import
          katex: ['katex'],
          mermaid: ['mermaid'],
          excalidraw: ['@excalidraw/excalidraw'],
          highlight: ['lowlight', 'highlight.js'],
        },
      },
    },
  },
  worker: { format: 'es' },         // ★ sectionWorker 需要
});
```

> ⚠️ TMD 仓库里有一处配置不一致：`tauri.conf.json` 的 `devUrl` 是 `1420` 而 `vite.config.ts` 的 `server.port` 是 `3000`。**我们两处必须一致**，并用 `strictPort: true` 让不一致时直接报错而非静默换端口。
