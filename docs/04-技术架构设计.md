### 1.1 分层规则（强制）

| 层 | 可以依赖 | 禁止依赖 |
|---|---|---|
| `app/`（Shell） | `features/` `stores/` `core/` `ui/` | — |
| `features/` | `stores/` `core/` `ui/` | 其他 `features/`（横向依赖走事件总线） |
| `stores/` | `core/` | `features/` `app/` `ui/` |
| `core/` | 无（纯函数 + IPC 封装） | 一切上层 |
| `ui/`（shadcn 原子组件） | 无 | 一切业务 |

**违反示例**：`editor-md` 直接 `import { explorerStore }` 去改资源管理器 → 错。应该 `emitter.emit('document:activated', ...)`，由 `app/` 层的编排器去改 store。

> ⚠️ `extension-drag-handle@3.x` 把 `@tiptap/y-tiptap` 与 `@tiptap/extension-collaboration` 声明为**非 optional peer**。不做协同编辑时它们是否运行时必需**未验证** —— 安装期先加进去消除 peer warning，然后在 P1 阶段做一次移除实验，能移除则移除（省约 300KB）。

## 4. 关键流程

### 4.1 冷启动

```
NoteBoard.exe [path?]
  │
  ├─ ① tauri_plugin_single_instance::init(...)   ★ 链首注册
  │     └─ 已有实例？ → WM_COPYDATA 转发 argv → cleanup_before_exit() → exit(0)
  │
  ├─ ② 注册其余插件（fs[watch] / dialog / opener / window-state / os）
  │
  ├─ ③ .manage(Mutex::new(AppState::default()))
  │
  ├─ ④ setup()
  │     ├─ 解析 args_os()：跳过 argv[0]、跳过 - 开头、file:// → 本地路径
  │     ├─ intents["nb-main"] = OpenFiles{paths} 或 Empty
  │     └─ 创建 nb-main（visible: false，避免白屏）
  │
  └─ ⑤ 前端 main.tsx
        ├─ 同步注入主题（在渲染前读设置写 data-theme，防闪烁）
        ├─ invoke('window_ready', { label })  ← 握手 + 取意图，一次调用
        ├─ 按意图打开文件
        └─ window.show()
```

**为什么 `window_ready` 把握手与取意图合并成一个命令**：少一次往返，且天然消除「已 ready 但还没取意图」的中间态。

### 4.2 已运行时双击文件（FR-110/111）

```
资源管理器双击 a.md
  │
  ├─ Windows 按 ProgID 启动 NoteBoard.exe "D:\a.md"
  │
  ├─ 新进程的 single-instance 检测到互斥体已存在
  │     └─ SendMessageW(WM_COPYDATA, "{cwd}|{argv...}") → 自己退出
  │
  └─ 已有进程的回调（app, argv, cwd）
        ├─ argv.skip(1) 取路径              ← argv[0] 是 exe 自身
        ├─ 查 registry：文件已打开？
        │     ├─ 是 → emit_to(owner, 'nb://focus-tab', {key}) + set_focus()
        │     └─ 否 → 找 last_active_at 最大的窗口
        │              → emit_to(label, 'nb://open-files', {paths}) + set_focus()
        │
        └─ 🔴 若需新建窗口，必须 std::thread::spawn
              （回调运行在 WM_COPYDATA 同步窗口过程内，直接建窗会死锁）
```

### 4.3 打开文档（唯一性协商）

```
openDocument(path)
  │
  ├─ key = normalizeKey(path)
  ├─ 本窗口已有此 tab？ → 激活它，结束
  │
  ├─ invoke('register_document', { label, key, kind })
  │     ├─ Ok                          → 继续
  │     └─ AlreadyOpen { label: other } → 请求 Rust 让 other 窗口聚焦，本窗口结束
  │
  ├─ invoke('read_document', { path })
  │     └─ 返回 { content, encoding, eol, mtime, size }
  │
  ├─ 建 Document（Loading → Clean）
  ├─ 跑 largeDoc 判定 → 决定初始 viewMode
  ├─ 建 Tab，激活
  └─ activateTab 副作用：资源管理器跟随到 dirPath + reveal
```

### 4.4 在新窗口中打开（FR-606）

```
moveToNewWindow(tabId)
  │
  ├─ 从 documentStore 取出完整状态
  │     └─ { key, content(未保存的), isDirty, viewMode, viewState }
  │
  ├─ invoke('open_in_new_window', { docs: [transferred] })   ← async 命令
  │     │
  │     │  Rust 侧：
  │     ├─ label = 'nb-{seq++}'
  │     ├─ intents[label] = AdoptDocuments { docs }
  │     ├─ registry: 改 owner_window 为新 label
  │     ├─ std::thread::spawn(|| WebviewWindowBuilder::new(...).build())
  │     └─ 返回 label
  │
  ├─ 等待 Rust 确认新窗口已取走意图（invoke 返回后轮询 or 事件）
  │     └─ 🔴 在此之前不动本地状态（不变式 I-10）
  │
  └─ 确认后：移除本地 tab + Document
```

**失败处理**：建窗失败或超时（3s）→ Rust 回滚 registry 归属 → 源窗口保持原状 + 提示。

### 4.5 主题切换（FR-1003/1004）

```
用户在设置里选「琥珀」
  │
  ├─ settingsStore.setTheme('hu-po')          本窗口立即生效
  ├─ applyTheme(): documentElement.dataset.theme = 'hu-po'
  │     └─ 全部颜色由 CSS 变量驱动，无需重建任何组件
  │
  ├─ invoke('save_settings', settings)
  │     └─ Rust 落盘 + emit('nb://settings-changed', settings)  ★ 广播
  │
  └─ 其他窗口收到广播 → applyTheme()
```

**三个内核的主题适配方式不同**：

| 内核 | 机制 |
|---|---|
| TipTap | 纯 CSS 变量。`.hljs-*` 类消费 `--hljs-*` |
| CodeMirror | `Compartment` 热切 `HighlightStyle` + `EditorView.theme`，二者都读 CSS 变量 |
| Excalidraw | `theme` prop（`'light'`/`'dark'`）+ 覆盖它的 CSS 变量 |

> Excalidraw 只有明暗两档，晨光与琥珀都映射到 `'light'`，差异靠覆盖 Excalidraw 的 CSS 变量实现。

### 4.6 文件监听与降级

```
setExplorerRoot(dir)
  ├─ invoke('unwatch_dir', 上一个 root)
  └─ invoke('watch_dir', { path: dir, recursive: true, delayMs: 500 })
        │
        │  Rust 侧：notify + notify-debouncer-full
        │  （delayMs 走 debouncer → Windows 上重命名会被合并成单个 rename 事件）
        │
        ├─ 普通事件 → emit_to(label, 'nb://explorer-refresh', { dir })
        │
        └─ Flag::Rescan（缓冲区溢出，16KiB 硬编码，不可配）
              └─ emit_to(label, 'nb://explorer-rescan', { root })
                    └─ 前端必须全量重扫，否则漏改动
```

**一个窗口同时只监听一个目录**（就是当前 `explorerRoot`）。切根就换监听目标。

## 5. 状态管理约定

### 5.1 Store 边界

```ts
// windowStore：只管 tab 列表与激活项，不碰内容
interface WindowStore {
  tabs: Tab[];
  activeTabId: TabId | null;
  addTab / removeTab / moveTab / setActive: ...;
}

// documentStore：内容与编辑态
interface DocumentStore {
  documents: Map<string /* 小写 key */, Document>;
  upsert / remove / patchContent / setDirty / patchViewState: ...;
}
```

**为什么拆开**：tab 的增删改会高频触发 tab 栏重渲染；文档内容变更（每次按键）绝不能引起 tab 栏重渲染。拆 store 是最省事的隔离手段。

### 5.2 编辑器内容不进 store 的原则

**编辑器内核持有内容的权威副本**（TipTap 的 `editor.state.doc`、CM6 的 `EditorState`、Excalidraw 的 scene）。`documentStore.content` 是**防抖后的镜像**，用途只有两个：保存时取值、切 tab 卸载编辑器时保底。

**禁止**把 store 的 content 当受控值回灌给编辑器 —— 那会造成光标跳动与输入卡顿。

同步节奏：

| 内核 | 回调 | 防抖 |
|---|---|---|
| TipTap | `onUpdate` | 500ms → 写 store；800ms → 自动保存 |
| CM6 | `updateListener` | 300ms → 写 store（不自动保存） |
| Excalidraw | `onChange` | 300ms → 写 store；800ms → 自动保存 |

### 5.3 设置的跨窗口一致性

`settingsStore` 是唯一需要跨窗口同步的 store。规则：

- **写入只允许通过 `invoke('save_settings')`**，本地先乐观更新
- 收到 `nb://settings-changed` 广播时**全量替换**（不做字段级合并，避免顺序问题）
- 广播的发起窗口也会收到自己的广播，用 `revision` 字段（单调递增）去重

## 6. 性能设计

### 6.1 首屏与懒加载

强制动态 `import()` 的重模块：

| 模块 | 触发时机 | 体积量级 |
|---|---|---|
| `katex` + CSS | 文档中出现第一个公式且进入视口 | ~280KB |
| `mermaid` | 出现第一个 mermaid 块且进入视口 | ~1.1MB |
| `lowlight` + `highlight.js` | 首帧渲染完成后（double-rAF） | ~700KB |
| `@excalidraw/excalidraw` | 打开第一个 `.excalidraw` | ~2MB |
| `@codemirror/lang-*` | 打开对应语言文件 | 各 ~30–120KB |
| `sectionWorker` | 大文档进入分段模式 | — |

**首屏只包含**：React + Shell + explorer + TipTap 核心。目标首屏 JS ≤ 600KB（gzip 后）。

### 6.2 视口懒渲染（NFR-202）

```
observeElementNearViewport(el, callback)
  ├─ IntersectionObserver，rootMargin: '800px 0px'
  ├─ root = closest('[data-editor-viewport-root]') ?? 文档级 fallback
  ├─ ★ 按 root 复用 observer（WeakMap<Element, ObserverEntry>）
  │     不是每个元素一个 observer —— 一篇文档几百个代码块会拖垮性能
  └─ 一次性触发：命中后立即 unobserve + 删回调
```

门控三类重活：代码块高亮、KaTeX 渲染、Mermaid 渲染。

**Mermaid 额外需要全局串行队列** —— `mermaid.render()` 并发调用会互相污染内部状态。队列 + 陈旧守卫（渲染完成时检查节点是否还在文档里）。

### 6.3 代码高亮的视口裁剪

`viewportHighlight.ts` 是一个 ProseMirror 插件，只对视口 ±2000 position 内的代码块产 `Decoration.inline`：

- `posAtCoords` 求可见范围 → `doc.nodesBetween` → `lowlight.highlight` → 扁平化 hast
- rAF 批处理，`setMeta('addToHistory', false)`（不进撤销栈）
- 对 `lastDoc` / `lastRange` 记忆化，避免空转
- **单块 > 20,000 字符直接跳过**；`highlightAuto`（无语言标签）仅对 ≤ 5,000 字符的块

### 6.4 大文档分段（NFR-203/204）

```
文档超阈值且用户选择「仍要使用可视化编辑」
  │
  ├─ Worker: sectionDocument(text)
  │     ├─ markdown-it 只做块级 token 解析求安全边界
  │     ├─ 只在完整块边界切（不切开代码围栏/表格/frontmatter）
  │     ├─ 目标 24,000 字符/段，硬上限 64,000
  │     └─ ★ 回传时把 source 字段抹成 ''（调用方本来就持有原文，避免大字符串跨线程拷贝）
  │
  └─ SectionedEditor
        ├─ @tanstack/react-virtual，overscan: 2
        ├─ defaultRangeExtractor 保证活动段始终在渲染范围内
        ├─ ★ 同时只有 1 个真 TipTap 实例（活动段）
        └─ 其余段：markdown-it 渲染只读 HTML
```

**编辑活动段后的回写**：活动段的 Markdown 文本替换回原文的对应区间，重算受影响段的边界。

## 7. 安全设计

| 项 | 措施 |
|---|---|
| **文件系统范围** | 不用编译期 `fs:scope: ["**"]`。启动时 scope 为空，用户通过对话框/命令行选定路径后动态授权该路径及其子树（NFR-604） |
| **CSP** | 显式设置，不用 `null`。`script-src 'self'`；`style-src 'self' 'unsafe-inline'`（CSS 变量注入需要） |
| **Markdown 渲染** | 禁用 raw HTML 执行。非活动段的只读预览走 markdown-it 且 `html: false` |
| **Mermaid** | `securityLevel: 'strict'`（**不用 note-gen 的 `'loose'`**，NFR-605） |
| **KaTeX** | `throwOnError: false` + `trust: false` |
| **网络** | 不注册 `tauri-plugin-http`。CSP 的 `connect-src 'none'` |
| **withGlobalTauri** | `false`（note-gen 与 TMD 都设了 `true`，我们不需要） |
| **capabilities** | `windows: ["nb-main", "nb-*"]`；权限逐条列举，不用通配 |

| 来源 | 协议 | 可以怎么用 | 移植清单 |
|---|---|---|---|
| **note-gen** | GPL-3.0 | ✅ 可直接复制代码（NoteBoard 同为 GPL-3.0） | 编辑器扩展装配、自研 KaTeX/Mermaid 节点、大纲、四层大文档机制、视口懒渲染、viewport lowlight 插件 |
| **TMD** | MIT | ✅ 可直接复制（MIT 单向兼容 GPL），需保留版权声明 | `globals.css` 的三套主题 CSS 变量、blockquote/表格/alerts 样式 |
| **Excalidraw** | MIT | ✅ 作为 npm 依赖使用 | — |

**移植纪律**（NFR-703）：

1. 每个移植文件顶部加注释块：来源仓库、原始路径、commit、协议、改动摘要
2. `LICENSE` 为 GPL-3.0 全文；新增 `THIRD-PARTY-NOTICES.md` 列出 TMD 的 MIT 声明
3. **不移植的东西要明确**：note-gen 的工作区模型、SQLite 层、`store.json` 全局单例 tab 状态（必须改成 per-window，见 [ADR-010](05-ADR/ADR-010-状态管理与跨窗口同步.md)）、appDataDir 硬编码资产目录、中文目录名 `画布资源/`、`fs:scope: ["**"]`

**note-gen 里明确的负面参考**（照抄会踩坑）：

| 问题 | 我们怎么做 |
|---|---|
| 37 种扩展名全路由到 Markdown 编辑器，`.sql`/`.json` 被当 MD 解析往返 | 按 `DocumentKind` 严格分派，代码类走 CM6 |
| 只装 `@codemirror/lang-markdown`，源码模式下 `.json` 得到 Markdown 高亮 | 装五个语言包，按扩展名加载 |
| `.hljs-*` 硬编码 GitHub 亮色，暗色主题下 token 颜色不变 | 全部走 `--hljs-*` 变量，三套主题各自定义 |
| 资产目录硬编码 appDataDir，工作区不可整体拷走 | 图片落在文档同目录 `assets/` |
| 三套白名单互不一致（`MARKDOWN_EXTENSIONS` / `OPENABLE_EXTENSIONS` / 索引层） | 单一真相源 `core/docKind.ts`，Rust 从同一份 JSON 生成 |
| `tab` 状态存全局 `store.json`，天然单窗口 | per-window store + Rust registry |
