# NoteBoard 开发路线图

> **这份计划的核心约定：从阶段 0 到阶段 15 连续开发，中途不停下等人工测试。**
> 每个阶段的出口是一道**自动化验收门**（`pnpm gate:N`），机器判定通过即进入下一阶段。
> 人工验收只在阶段 15 发生一次。

---

### 0.1 为什么是这个顺序

| 原则 | 体现 |
|---|---|
| **风险前置** | 阶段 0 先把唯一的不确定性（`dragDropEnabled`）实测掉；阶段 6 的多窗口/建窗死锁排在 Markdown 之前 |
| **地基先行** | 主题系统（阶段 2）在任何 UI 之前 —— 所有组件都消费 Token，反过来做会返工 |
| **先易后难打通闭环** | 代码编辑器（阶段 4）比 Markdown 简单得多，用它最早打通「打开→编辑→保存」全链路 |
| **最复杂的放后面** | 大文档四层机制（阶段 11）依赖 Markdown 编辑器已稳定 |

### 0.2 自动化验收门的构成

每道门 `pnpm gate:N` 依次跑：

```
① pnpm typecheck          tsc --noEmit，零错误
② pnpm lint               eslint + clippy，零警告
③ pnpm test:unit          该阶段新增的单元测试全绿
④ pnpm test:e2e -- --grep "@gateN"    该阶段的 E2E 用例全绿
⑤ pnpm test:contract      前后端契约一致性
⑥ pnpm gate:budget        体积与性能预算不超标
```

**任一项失败即阻塞，不进入下一阶段。** CI 与本地跑同一套命令。

E2E 用 **WebdriverIO + tauri-driver**（Tauri 官方推荐的 Windows 方案，基于 Microsoft Edge WebDriver）。

### ⚠️ 三项技术验证（这是本阶段的重点）

#### 验证 A：`dragDropEnabled: false` 下 `dataTransfer.files` 是否可用（1 h）

**背景**：[tauri#15138](https://github.com/tauri-apps/tauri/issues/15138) 报告者称在 `false` 下外部文件的 `e.dataTransfer` 是 "blocked/empty"。这与预期（应能读到 `File` 但拿不到路径）不符。

**方法**：最小页面加 `ondrop` 监听，打印 `e.dataTransfer.files.length` 与 `file.name` / `await file.text()` 的前 100 字符，从资源管理器拖一个 `.md` 进去。

**两个分支，都已预先决定，不需要再问人**：

| 结果 | 处理 |
|---|---|
| `files` 可用 | 实现 [FR-104](01-需求规格说明.md) 的降级版：读内容 → 「未命名文档」新 tab → 保存走另存为。同理实现 FR-313 的图片拖入。 |
| `files` 为空 | **FR-104 与 FR-313 的拖入部分整条取消**，在需求文档标注「已验证不可行」。四条替代打开路径（双击 / 打开方式 / 拖到 exe / 应用内对话框）不受影响。 |

#### 验证 B：Windows 建窗死锁（2 h）

**背景**：`WebviewWindowBuilder::build()` 在同步 command 或事件回调中调用会挂死（wry#583）。

**方法**：写两个 command，一个同步直接建窗（对照组，应复现挂死），一个 `std::thread::spawn` 建窗。再在 single-instance 回调里各试一次。

**通过标准**：切线程版全部正常；对照组能复现挂死（证明我们理解正确，而不是碰巧没触发）。把结论写成 `src-tauri/src/window/manager.rs` 顶部的注释红线。

#### 验证 C：文件关联 + 单实例链路（3 h）

**方法**：配 `fileAssociations`（`md`）→ `pnpm tauri build` → 装 NSIS 包 → 双击 `.md`。已运行时再双击第二个。

**通过标准**：
- 双击能启动并把路径传进来（`args_os().skip(1)`）
- 已运行时不启第二个进程，argv 通过 `WM_COPYDATA` 到达第一个实例，`argv[0]` 是 exe 自身路径
- 确认「右键 → 打开方式」**不出现** NoteBoard（NSIS 不写 `OpenWithProgids`），从而确认阶段 14 必须写 `installerHooks`

## 附录 A · 并行与关键路径

单人开发是串行的，但若有第二个人，可并行的切分：

```
主线（关键路径）：0 → 1 → 2 → 3 → 4 → 5 → 6 → 7 → 8 → 11 → 15
                                              ↘ 9
支线（可并行）：       2 → 10（画板，依赖主题 + 外壳）
                      1 → 12（设置，依赖 Rust settings + 主题）
                      1 → 13（健壮性，依赖 Rust fsio）
```

阶段 9（大纲）、10（画板）、12（设置）、13（健壮性）都可以在主线推进的同时并行。两人协作时总工期可压到约 50 天。

## 附录 B · 移植 note-gen 的操作纪律

阶段 7/8/9/11 会大量移植 note-gen 代码。每次移植：

1. **不整文件搬。** `tiptap-editor.tsx` 是 229KB 单文件，AI 相关代码与编辑器逻辑交织。做法是：先跑通最小扩展集，再逐个加扩展。
2. **文件头必须写来源块**（原始路径、commit、协议、改动摘要）。CI 会检查。
3. **主动剔除**：AI 补全/建议/diff 预览、`sync/` 目录、SQLite 层、`store.json` 全局单例 tab 状态、appDataDir 硬编码资产、中文目录名、`fs:scope: ["**"]`、`securityLevel: 'loose'`、`withGlobalTauri: true`、`csp: null`、8 个零引用的死扩展。
4. **魔法值照抄不改**（`rootMargin: 800px`、`±2000 position`、`overscan: 2`、`24000/64000`、`20000`、`5000`、LRU 200），但在代码注释里标注「来自 note-gen 的经验值，非推导值」。
