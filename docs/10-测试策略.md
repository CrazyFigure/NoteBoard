# NoteBoard 测试策略

> **这份策略是「连续开发不中途人工测试」这个约定能成立的唯一前提。**
> 如果自动化覆盖不足，那个约定就变成了「无验证地一路往下写」——那是灾难。

---

## 1. 分层与配比

```
                        ┌───────────────┐
                        │  人工验收  1 次 │  阶段 15，唯一一次
                        └───────────────┘
                    ┌───────────────────────┐
                    │  E2E（WebdriverIO）    │  ~120 用例
                    │  真实 Tauri 窗口       │
                    └───────────────────────┘
              ┌─────────────────────────────────┐
              │  集成测试（Rust + Vitest）        │  ~80 用例
              │  IPC 往返 / 文件系统 / 窗口管理    │
              └─────────────────────────────────┘
        ┌───────────────────────────────────────────┐
        │  单元测试（Vitest + cargo test）            │  ~350 用例
        │  纯逻辑 / 序列化 / 主题 / 路径 / 切分         │
        └───────────────────────────────────────────┘
```

| 层 | 工具 | 跑在哪 | 单次耗时目标 |
|---|---|---|---|
| 单元（前端） | Vitest + jsdom | Node | ≤ 20 s |
| 单元（Rust） | `cargo test` | Node | ≤ 30 s |
| 集成（Rust） | `cargo test --test integration` + 真实临时目录 | Node | ≤ 60 s |
| 契约 | Vitest（读 `build.rs` 产物） | Node | ≤ 5 s |
| E2E | **WebdriverIO + tauri-driver** | 真实 Windows 桌面 | ≤ 12 min |
| 视觉回归 | Playwright 截图对比（仅主题） | 真实窗口 | ≤ 3 min |

**E2E 用 WebdriverIO + tauri-driver**（Tauri 官方在 Windows 上的推荐方案，底层是 Microsoft Edge WebDriver）。不用 Playwright 驱动应用本体——它不支持 Tauri 的 WebView2 会话；但用它做**纯截图对比**是可以的（对已启动窗口截图）。

## 2. 必须被测试锁住的东西

按「出了问题最伤用户」排序。**这一节就是测试用例的优先级表。**

### 2.1 数据不丢（最高优先级）

| 场景 | 层 | 断言 |
|---|---|---|
| 手动保存类文档脏时关 tab | E2E | 必然弹拦截；「取消」后内容与脏态完好 |
| 手动保存类文档脏时关窗口 | E2E | 批量拦截；「取消」后窗口与全部内容完好 |
| 写盘失败（只读 / 占用 / 磁盘满） | 集成 + E2E | 返回对应 `WriteError`；**内存内容不变**；有明确提示 |
| 原子写中途失败 | Rust 单元 | 原文件字节级完好；无残留 `.nb-tmp-*` |
| 跨窗口迁移中途建窗失败 | E2E | 源窗口保持原状；内容完好；有错误提示 |
| 强杀进程后重启 | E2E | 草稿恢复入口出现；恢复的内容与杀进程前一致 |
| 自动保存类文档在失焦/切 tab/关闭时 | E2E | 必然落盘（对比磁盘字节） |
| 外部删除文件后继续编辑并保存 | E2E | 走另存为；内容不丢 |

### 2.2 不偷偷改用户文件

| 场景 | 层 | 断言 |
|---|---|---|
| **打开 md → 切 visual → 切 source → 不变脏**（不变式 I-14） | E2E | tab 无脏圆点；磁盘 mtime 未变 |
| Markdown 序列化往返 | 单元 | 一组棘手样本往返后与基线一致 |
| `.sql` / `.json` 打开保存后字节不变（未编辑时） | E2E | 字节级比对 |
| CRLF 文件保存后仍 CRLF | 集成 | 字节级比对 |
| GBK 文件保存后仍 GBK | 集成 | 字节级比对 |
| UTF-8 BOM 保留 | 集成 | 首三字节仍是 `EF BB BF` |
| **`.excalidraw` 的 `viewBackgroundColor` 不随主题改变** | E2E | 切主题后文件内容字节不变 |
| 分段模式下编辑活动段后回写 | 单元 + E2E | 只有被编辑区间变化，其余字节不变 |
| 块边界切分不落在代码围栏/表格/frontmatter 内 | 单元 | 对 4 个样本断言**所有**切点 |

### 2.3 跨窗口一致性（不变式 X-1 ~ X-7）

| 不变式 | 层 | 断言 |
|---|---|---|
| X-1 / X-2 同一文件全局只开一次 | E2E | 窗口 B 打开 A 已开的文件 → 聚焦 A 的 tab，B 不新建 |
| X-3 主题跨窗口一致 | E2E | A 改主题 → B 的 `data-theme` 同步 |
| X-4 迁移过程内容至少一处完整 | E2E | 注入建窗失败 → 内容仍在 A |
| X-6 Rust 与前端文档集一致 | 集成 | 手工制造不一致 → `reconcile` 后一致 |
| X-7 窗口关闭后注销文档 | E2E | 关 A → B 能打开原属 A 的文件 |

### 2.4 配色（用户明确在意的部分）

| 场景 | 层 | 断言 |
|---|---|---|
| 三套主题 × 正文类 Token ≥ 4.5:1 | 单元 | 遍历断言，含 17 个 `--hljs-*` |
| 三套主题 × 指示类 Token ≥ 3:1 | 单元 | 遍历断言 |
| 三套主题的 Token 键集合完全一致 | 单元 | 集合相等 |
| 代码块与行内代码实际渲染色 | E2E | `getComputedStyle` 取色与规范值比对 |
| 代码块在三套主题下的视觉 | 视觉回归 | 截图对比（同一段代码 × 3 主题） |
| CM6 语法高亮随主题变化 | E2E | 取 `.tok-keyword` 的计算色 |
| 组件未直接引用色板层 | ESLint 规则 | `features/` `app/` 下禁止 `var(--accent-[0-9]` |

### 2.5 大文档不卡死

| 场景 | 层 | 断言 |
|---|---|---|
| 阈值判定正确 | 单元 | 各阈值边界；提前 return |
| 1MB md 打开 | E2E + 性能 | 走 source 模式 + 横幅；可交互 ≤ 2s |
| 5MB md 进分段模式 | E2E + 性能 | 可交互 ≤ 3s；DOM 中只有 1 个 `.ProseMirror` |
| 86MB 文件 | E2E | 读盘**前**弹确认框 |
| 视口外的公式/图表/代码块未渲染 | E2E | DOM 中是占位符 |
| Worker 回传不含原文 | 单元 | `source === ''` |
| 分段滚动帧率 | 性能 | ≥ 50fps |

## 3. E2E 环境

### 3.1 依赖

```
tauri-driver（Rust，cargo install tauri-driver）
Microsoft Edge WebDriver（版本必须匹配本机 Edge/WebView2）
WebdriverIO + @wdio/local-runner + @wdio/mocha-framework
```

### 3.2 隔离：每个用例一个沙箱

```ts
// e2e/support/sandbox.ts
export async function makeSandbox(fixtures?: Record<string, string>) {
  const dir = await mkdtemp(join(tmpdir(), 'nb-e2e-'));
  // 写入 fixture 文件
  // 用独立的 APPDATA 指向沙箱，避免污染真实配置
  process.env.NOTEBOARD_CONFIG_DIR = join(dir, '.config');
  return { dir, cleanup: () => rm(dir, { recursive: true, force: true }) };
}
```

**关键**：Rust 侧读配置目录时必须支持环境变量覆盖（`NOTEBOARD_CONFIG_DIR`），否则 E2E 会互相污染、也会污染开发者的真实配置。这是一个**必须在阶段 1 就实现**的可测试性设计。

### 3.3 多窗口测试

`tauri-driver` 的会话默认绑定一个 webview。多窗口测试需要切换句柄：

```ts
const handles = await browser.getWindowHandles();
await browser.switchToWindow(handles[1]);
```

**阶段 6 的第一件事就是把这套多窗口测试脚手架跑通** —— 否则后面所有多窗口用例都写不了。

### 3.4 稳定性纪律

| 反模式 | 正确做法 |
|---|---|
| `await browser.pause(1000)` | `await expect(el).toBeDisplayed({ timeout: 5000 })` |
| 靠 CSS 类选元素 | 用 `data-testid` |
| 断言「界面上有某文字」 | 断言状态 + 断言磁盘内容 |
| 一个用例测五件事 | 一个用例一个断言主题 |

**禁止使用固定 `pause`。** 所有等待都必须是条件等待。CI 上任何 flaky 用例（3 次重跑中有 1 次失败）必须当作 bug 修，不允许加重试掩盖。

## 4. 各阶段的测试重点

| 阶段 | 测试重点 | 特别注意 |
|---|---|---|
| 0 | 三项技术验证的结论要**写成测试**（尤其建窗死锁的对照组） | 对照组「应该挂死」的测试要有超时保护 |
| 1 | Rust 单元测试密度最高的一个阶段 | 原子写、编码探测、路径规范化 |
| 2 | 对比度 + Token 完整性 | 这两条测试会一直保护到项目结束 |
| 3 | 折叠把手的悬浮隐藏（三档 opacity） | 需要移动鼠标，用 `performActions` |
| 4 | 第一条完整闭环 | 断言磁盘字节，不只断言界面 |
| 5 | 纯跟随的 root 切换逻辑 | 同目录 / 跨目录 / null 三种情况 |
| 6 | 多窗口脚手架 + 迁移失败注入 | 本阶段测试比实现更难写 |
| 7 | **往返保真** | 这是 `gate:7` 的核心，样本要够狠 |
| 8 | 视口懒渲染的「未渲染」断言 | 断言占位符存在，而非渲染结果不存在 |
| 9 | 双向滚动同步 | 滚动后需等 debounce（50ms/100ms）+ 条件等待 |
| 10 | Excalidraw 互操作性 | 用官方 `loadFromBlob` 反向验证 |
| 11 | 块边界正确性 | 断言**所有**切点，不抽样 |
| 12 | 排版四项的即时生效 + 跨窗口 | `getComputedStyle` 取实际值 |
| 13 | 故障注入 | 只读文件、占用文件、强杀进程 |
| 14 | 全新环境安装 + 文件关联 | 需要干净 VM 或容器 |
| 15 | 全量回归 + 长稳 | |

## 5. 往返保真测试样本（阶段 7 的核心）

`test/fixtures/roundtrip/` 下每个样本一个文件，全部要往返一致：

| 样本 | 考察点 |
|---|---|
| `basic.md` | 全部基础语法 |
| `nested-list.md` | 混合缩进（2/3/4 空格）、有序无序混嵌、列表内代码块 |
| `trailing-space.md` | 行尾空格（Markdown 硬换行语义） |
| `setext.md` | `===` / `---` 下划线式标题 |
| `nested-quote.md` | 多级引用嵌套、引用内列表、引用内代码块 |
| `table-align.md` | 表格对齐符 `:---` `:---:` `---:`、单元格内 `\|` 转义、中文列宽 |
| `fence-tricky.md` | 代码围栏内含 `#` / `- ` / `> ` / `\|`、`~~~` 围栏、围栏内围栏、无语言标签 |
| `raw-html.md` | 内嵌 `<div>` `<br>` `<details>` `<img>` |
| `math.md` | `$...$` / `$$...$$` / `\(...\)` / `\[...\]`、公式内 `_` 与 `*` |
| `task-list.md` | `- [ ]` / `- [x]` / 嵌套任务 |
| `alerts.md` | 5 种 GitHub Alerts |
| `mermaid.md` | mermaid 块内含特殊字符 |
| `link-image.md` | 引用式链接、行内链接、图片、链接标题、相对路径 |
| `frontmatter.md` | YAML frontmatter |
| `cjk.md` | 中文标点、中英混排、全角符号、emoji |
| `hard-cases.md` | 空标题、只有分割线、连续空行、文件首尾空行 |

**测试形式**：

```ts
describe.each(SAMPLES)('往返保真：%s', (name) => {
  test('解析 → 序列化 → 与基线一致', () => {
    const src = readFixture(name);
    const baseline = readFixture(`${name}.baseline`);   // 首次运行生成并人工审阅后固化
    const doc = parseMarkdown(src);
    expect(serializeMarkdown(doc)).toBe(baseline);
  });

  test('二次往返幂等', () => {
    const once = serializeMarkdown(parseMarkdown(readFixture(name)));
    const twice = serializeMarkdown(parseMarkdown(once));
    expect(twice).toBe(once);       // ★ 比与原文一致更重要
  });
});
```

> **「二次往返幂等」比「与原文一致」更重要。** 序列化必然会规范化格式，与原文完全一致是不现实的。但**第二次往返必须不再变化** —— 否则每次切换模式文件都在变，基线机制也救不了。

## 6. 性能测试

`test/perf/` 下用 E2E 环境实测并断言 NFR 指标。

```ts
test('NFR-101 冷启动到可编辑 ≤ 1.5s', async () => {
  const t0 = Date.now();
  await launchApp(['--', sandboxFile('10kb.md')]);
  await expect($('[data-testid="editor-ready"]')).toBeExisting({ timeout: 5000 });
  expect(Date.now() - t0).toBeLessThan(1500);
});
```

| NFR | 指标 | 测法 |
|---|---|---|
| 101 | 冷启动 ≤ 1.5s | 进程启动 → `editor-ready` 标记出现 |
| 102 | 热启动新 tab ≤ 300ms | 调 single-instance 回调 → tab 出现 |
| 103 | 新窗口 ≤ 800ms | `Ctrl+Shift+N` → 新窗口 ready |
| 104 | 输入延迟 p95 ≤ 32ms | 1MB 文档内连打 200 键，取 `performance.now()` 差值分布 |
| 105 | tab 切换 ≤ 150ms | 切换 → 编辑器 ready |
| 106 | 主题切换 ≤ 100ms | 切换 → `data-theme` 变化 + 首帧绘制 |
| 107 | 10MB md 可交互 ≤ 3s | 打开 → 可输入 |
| 108 | 单窗口内存 ≤ 200MB | 任务管理器采样（`tasklist` 解析） |
| 109 | 1000 条目目录 ≤ 500ms | `read_dir` 命令耗时 |
| 110 | 安装包 ≤ 30MB | 文件大小 |

**性能测试在 CI 上只作为告警**（CI 机器性能不稳定），在阶段 15 用固定基准机做正式验收。这一点要写清楚，避免 CI 因性能抖动红掉而被人加 `--skip`。

## 7. 体积预算门

```
gate:budget 检查项：
  首屏 JS（gzip）              ≤ 600 KB
  首屏 CSS（gzip）             ≤  60 KB
  katex 不在首屏 chunk
  mermaid 不在首屏 chunk
  excalidraw 不在首屏 chunk
```

**每个阶段都跑这道门** —— 体积失控通常是某次不小心的静态 import 造成的，越早发现越好定位。

## 8. 视觉回归（仅主题）

只对主题配色做截图对比，**不对整个界面做**（整界面截图对比在活跃开发期维护成本太高）。

| 快照 | 内容 |
|---|---|
| `code-block-{theme}.png` | 固定一段含各类 token 的代码，在代码块中渲染 |
| `inline-code-{theme}.png` | 含行内代码的段落 |
| `cm-{lang}-{theme}.png` | CM6 中的 sql / json / yaml / xml 各一段 |

**基线更新必须是显式操作**（`pnpm test:visual --update`）并在 PR 中人工审阅截图差异。

## 9. CI 流水线

```yaml
# .github/workflows/ci.yml（要点）
runs-on: windows-latest

jobs:
  fast:                      # 每次 push，≤ 3 min
    - typecheck
    - lint (eslint + clippy)
    - test:unit
    - test:contract
    - gate:budget

  e2e:                       # 每次 push，≤ 15 min
    - setup tauri-driver + edge webdriver
    - build (debug)
    - test:e2e
    - test:visual

  package:                   # 仅 main 分支与 tag
    - build (release)
    - 全新环境安装验证
    - 文件关联验证
    - upload artifact
```

### 9.1 分支保护

`main` 分支要求 `fast` 与 `e2e` 全绿才能合并。

### 9.2 flaky 治理

E2E 失败时自动重跑 1 次并**标记为 flaky**（不是静默通过）。每周汇总 flaky 列表，超过 2 次的用例必须修。

## 10. 不测什么

明确不投入测试成本的地方，避免过度工程：

| 不测 | 理由 |
|---|---|
| 第三方库内部行为（TipTap 的编辑逻辑、Excalidraw 的绘图） | 信任上游，只测我们的集成点 |
| 整界面的像素级视觉回归 | 活跃开发期维护成本 > 收益 |
| 每个快捷键的独立用例 | 抽样测代表性的（每类一个），全表靠 `shortcuts.ts` 的注册表结构测试 |
| Excalidraw 的全部图元类型 | 测「能画、能存、能读、中文正常」即可 |
| highlight.js 的 37 种语言 | 测 5 种代表性的；语言包本身信任上游 |
| Rust 侧对 OS API 的封装（`trash`、`font-kit`） | 冒烟即可 |
| 多语言（只有中文） | 无 |
| macOS / Linux | 范围外（OUT-111） |
