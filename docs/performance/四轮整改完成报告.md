## 反例修复明细

### C01 · 历史组合并丢组边界（R3-01）✅

**根因**：`stagePendingVisualSnapshot`/`stagePendingSourceSnapshot` 展开新 snapshot 时，`isNewGroup` 被同组第二笔输入的 `false` 覆盖——第二组的"新组"标记丢失，物化以 `false` 调用 `recordDocumentChange`，第二组被并进第一组。

**修复**（`visualSnapshot.ts`）：暂存快照增加**稳定组身份**（`groupId`——首次暂存生成、同组后续事务保留）与"相对已提交历史是否新组"的元信息；`stage` 只允许同组后续事务**替换组末 doc/Text、revision、末端选区**，`isNewGroup`、`groupStartBefore`、`groupId` 一律保持首事务值。visual 与 source 两模式同步修复。

### C02 · 共享物化钩子被其它实例注销（R3-01）✅

**根因**：`registerHistoryMaterializeHook` 用 `Set<(docKey) => void>` 按**函数值**存取——两个实例注册同一 `flushPendingSourceSnapshot` 只存一份；任一实例卸载的 disposer `delete` 掉它，仍挂载实例失去导航前物化屏障。

**修复**（`documentHistory.ts`）：钩子注册表改为**按注册身份条目**（`MaterializeHookEntry { id, hook }` 数组）——同一函数多次注册产生多个独立条目；disposer 按条目身份（`indexOf(entry)`）只删除自己的注册。

### C03 · 旧 pending 绕过会话屏障（R3-03）✅

**根因**：pending 只按 docKey 索引、无会话身份；物化直接 `recordDocumentChange`/`setContent` 绕过 `submitCapturedContent`。旧 source pending 在同路径重开后物化，覆盖新正文。

**修复**（`visualSnapshot.ts`）：**两种模式的 pending 都捕获会话代际**（首次暂存时 `getSessionGeneration`）；`flush` 在产生任何副作用前校验代际——失效（同路径重开）则无副作用丢弃（返回 null）。

### C04 · 另存为覆盖同窗口目标（R3-04）✅

**根因**：Rust 同 owner 幂等 register 返回 `ok`（IPC 契约无 `already-open(self)` 分支），前端未自查目标标签——目标已在本窗口打开时照常写盘并迁移身份。

**修复**（`saveDocument.ts` saveAs）：**第 0 步同窗口冲突前端自查**——`useWindowStore.getTab(selectedPath)` 已存在即中止（零写盘、不覆盖目标正文、不产生重复 key 标签）；同 owner 的 `already-open` IPC 分支保留为跨窗口防线。

### C05 · 写盘失败不释放新取得归属（R3-04）✅

**修复**：授权结果记录 `newlyOwned`；事务主体包入 try/finally——**finally 按本次新取得的授权释放**（`unregisterDocument(label, selectedPath)`），覆盖写盘失败、快照失败、迁移失败全部路径；事务成功后 `newlyOwned=false`（授权随身份迁移兑现，不误释放）。

### C06 · 对话框期间源关闭重开（R3-04）✅

**根因**：会话身份捕获在 `ensureWritableContent` 之后（首个 await 后）——对话框期间重开的新会话给了新代际，旧事务校验"合法"。

**修复**：`originalGeneration` 捕获**移至函数第一行（任何 await 之前）**；并在加载 await 后、flush await 后、授权 await 后、写盘 await 后**逐点校验**——源会话已换代即中止（返回 false，不写盘不迁移）。

### C07 · 注销等待期间的新输入丢失（R3-04）✅

**修复**：`remove(originalKey)` **之前**重新读取权威镜像（`getContent(originalKey)`）——drain/unregister await 期间的输入进入 store 镜像，读取后成为 `finalContent`（新会话的最终内容，保持 dirty）。

### C08 · 旧关闭注销重开的新归属（R3-05 + R3-03）✅

**根因（双）**：(1) `disposeTabLifecycleAsync` 注销无条件发出；(2) 会话代际表在重开时不换新 token（旧条目因 closing 抑制释放，documents 重建分支带 `has` 检查跳过推进）。

**修复**：(1) 关闭事务捕获 `closeGeneration`，注销前校验**代际未推进**——drain 期间同路径重开则跳过注销（后端只校验窗口 label，无法区分新旧会话——前端按代际条件注销）；(2) `documents` 订阅对 key 从无到有**无条件分配新 token**（`advanceSessionGeneration`）——重开的新会话代际必然大于关闭代际，旧事务自然失效。

### C09 · 公开关闭接口不停止接纳（R3-05）✅

**根因**：停止接纳（closing）只在私有同步 `disposeTabLifecycle` 中；公开 `disposeTabLifecycleAsync` 只有 drain→unregister——`performWindowClose` 直接调用后者，旧会话仍可接纳写任务。

**修复**（`documentSession.ts` + `windowStore.ts`）：新增 **closing 状态**（`closingGenerations: docKey → 关闭时代际`）：`beginClosing`（幂等）在任何 await 前执行；`enqueueDocumentWrite` 拒绝 closing 的旧会话任务（`isClosing = 当前代际 ≤ 关闭代际`——**同路径重开（代际推进）自动恢复接纳**，关闭后的旧会话永久拒绝）；`writeDocumentWithBarrier` 对 closing 优雅返回 false（不抛异常）。`disposeTabLifecycleAsync` 公开入口第一步即 `beginClosing`——独立可用即完整。

### C10 · Drawio 导出超时仍批准回收（R3-06）✅

**根因**：flush 的导出超时回退"非空旧镜像"返回成功——无最新内容证明却 `suspendEditorInstance` 返回 true。

**修复**（`DrawioEditor.tsx`）：导出超时/未就绪/请求冲突一律**返回 null（失败）**——不回退旧镜像；无最新内容证明即不回收（保守保留实例）。

### C11 · 迟到 XML 回包覆盖 autosave 正文（R3-06）✅

**根因**：export 事件处理器无条件 `setContent(msg.data)`；超时后的旧回包（无在途请求）也写正文。

**修复**：导出请求持有**唯一 requestId**（单调递增）；回包**只被当前在途请求消费**（`pendingExportRef.current?.requestId === requestId` 匹配）——超时作废后的迟到回包无人消费、不写正文；同时修复 message effect 的依赖（去掉 `doc?.content`/`isLoaded`——此前每次 autosave 都会 cleanup 终结在途导出；init 的初始 XML 改经 `getState` 读取）。

### C12 · 回收等待 flush 时被新实例接管（R3-07）✅

**根因**：`suspendEditorInstance` 只从启动时捕获的 capabilities 对象读 revision，flush 返回后不重新验证注册表。

**修复**（`editorSuspension.ts`）：flush 是异步屏障——**返回后重新校验**：(1) 注册表当前实例仍是同一 `instanceId`（新实例接管 → 旧回收作废）；(2) 迁移保护未进入；(3) `canSuspend` 仍通过（flush 期间进入 IME 等）。任一失败返回 false。

### C13 · 目标 unknown 状态解除写保护（R3-08）✅

**根因**：`adoptTransferredDocument` 的 unknown 分支仍 `exitTransfer`——prepare 与 query 双失败时目标可编辑（与源侧"unknown 保持保护"不对称）。

**修复**（`windowManager.ts`）：unknown 分支**保留迁移保护**（不 `exitTransfer`）——双方均不能因"未知"恢复写入；权威终态事件（committed/aborted 迟到）或对账到达时再解锁/清理。

### C14 · source 首开保存旧镜像（R3-02）✅

**根因（双）**：(1) Markdown 能力注册被 `if (editor)` 包住——source 首开（无 TipTap 实例）注册表无能力；(2) `saveDocument` 的 `flushDocument` 返回 null 时直接回退旧镜像——未物化的 source pending 被跳过。

**修复**：(1) `TipTapEditor` 能力注册拆为**模式无关注册**（挂载即注册，source 首开即有——内部按当前模式动态分派 CM/TipTap）；visual 实例就绪时**换代注册**（新 instanceId——旧实例迟到 flush 被拒）。(2) `saveDocument` 在无实例快照时**先物化 pending**（source/visual 分别尝试）——未物化输入是正文权威，不得被旧镜像覆盖。另补真实 TipTapEditor source 宿主测试 3 例（`test/editor-md/sourceFirstCapabilities.test.tsx`：注册完成、flush 物化、模式切换注册稳定）。

### C15 · 脏态更新重新挂载已回收实例（R3-07）✅

**根因（双）**：(1) `[tabs]` effect 的"新增"分支每次把**全部非懒标签**加回 mountedEditorKeys——dirty/viewMode 等属性更新触发重渲染时已回收标签全部重新挂载；(2) 收敛批次逐项 suspend 反复改 `keepAliveKey` 且 `previous` 不在 removable——切换后残留 3 个实例。

**修复**（`AppShell.tsx`）：(1) 新增 **`everMountedRef` 曾挂载集合**——"新增"分支只挂载**从未挂载过**的标签（真正首次打开）；已回收的后台标签不因属性更新重挂载（重新激活/懒加载完成经 `[activeKey]` effect 回集合）；(2) 收敛批次重构：**previous 与后台候选同批次逐项验证**（previous 也是候选——切走的标签同样可回收），批次结束统一确定保活者（最后一个成功项），提交时重读最新 activeKey/keep。
