### N01 (P0) 迁移中止被误判为提交成功（B08）✅

- **终态判别**：`waitForTransferOutcome` 返回值从布尔改为 `TransferOutcome = 'committed' | 'aborted' | 'unknown'`。超时路径中 `abortTransfer` 成功返回 `aborted` → `settle('aborted')`（修复 `settle(aborted.state === 'aborted')` 即 `settle(true)` 的布尔混淆）；**abort 抢占失败返回 `committed` → 按提交成功清理源**（不因"中止尝试"误删）。
- **只有权威 committed 清理源**：aborted 保留正文/历史/视图并解锁；**unknown 保留全部数据且保持迁移保护**（`finally` 不 `exitTransfer`），注册 `scheduleTransferReconcile` 对账——事件（可能迟到）与 5 秒低频查询（上限 60 秒）到达权威终态后按对应语义收尾；源/目标不会同时恢复写入。

- **settle 清理全部句柄**：轮询 interval 与 30 秒 timeout 一并清除（修复"成功提前 settle 后 timeout 仍执行查询"）。
- **完整迁移屏障**（N01 步骤 5）：顺序改为 `enterTransfer（保护+阻断关闭竞争）→ blur（IME 组合输入先落地）→ flush 权威内容 → 捕获 revision/历史/视图 → begin`。迁移是正文出口，前置 `ensureWritableContent`（N02）；无权威正文（镜像未知）直接中止。

### N02 懒恢复读取失败后写空正文（B01）✅

- **共享加载 Promise**：`loadingLazyTabs` 从 Set 改为 `Map<key, Promise<LazyLoadResult>>`；`loadRestoredTab` 返回 `loaded / failed / stale / no-lazy` 判别结果。并发保存/激活等待同一次读取，不再把"正在加载"当完成。
- **返回值不证明交付**：`openDocument` 返回 opened/focused/cancelled 后必须验证本 key 的会话 `content != null` 才清除懒标记（focused 场景正文在别处，本标签保留 lazy 可重试）。
- **统一正文出口屏障 `ensureWritableContent`**：保存（saveDocument）、另存为（saveAs 直达入口）、迁移（moveToNewWindow）统一前置调用。只有"已加载且有可写正文"才继续；null/失败/失效一律中止。全部 `?? ''` 补空路径清除——`authoritativeContent == null` 时中止保存；`refreshDirtyAfterWrite` 对未知正文保守保持 dirty（不误清关闭保护）。空字符串作为合法正文（用户清空）与未知（null）严格区分。

### N03 另存为先覆盖目标后检查占用（B02/B03）✅

`saveAs` 重构为事务：**授权 → 快照 → 写盘 → 提交身份迁移**。

1. **授权先于写盘**：对话框返回后先 `registerDocument(label, target, kind)`——目标被其它窗口占用（`already-open` 且 owner≠self）**或本窗口其它标签占用**（owner==self 同样中止，避免重复标签/历史串线）、注册 IPC 异常——一律中止，**零写盘**（B02 通过；`writeDocument` 未被调用）。原"写盘成功后才查占用"的顺序消除。
2. **对话框返回后重新捕获快照**：不再使用打开对话框前的旧正文——对话框期间的合法编辑（含清空为 `''`）随另存为写入（B03 通过：最终写盘参数为 `''`、目标会话 content 为 `''`）。
3. **写盘期间新编辑保留在会话内**：身份迁移前再次 flush 捕获 `lateContent`——新输入成为新会话镜像（`finalContent`），基线=实际写盘内容（`updateBaseline`），dirty 由 flush-and-compare 自动保持（新编辑受关闭保护）；**不再在删除源会话后补捞**（原补写链删除）。
4. **写入失败不迁移**：`result.ok === false` 时直接返回——权威内容、dirty、历史和原身份全部保留（不执行 moveDocumentHistory/migrateSession/remove）。
5. **原路径等于目标**：规范化身份比较（`normalizePath` + 小写）后相同 → 走普通 `saveDocument` 语义。
6. **身份迁移统一**：历史（moveDocumentHistory）、会话版本（migrateDocumentSession，含 revision 迁移）、写队列（drain 后迁移）、Rust 归属（unregister 旧 key）、文档对象、标签（updateTabPath）、基线（updateBaseline）、暂存清理（onDocumentSaved 带内容证明）。
7. **"保存并关闭"用实际新 key 继续**：saveAs 成功记录 `lastSaveIdentityMove`（from→to）；`handleSaveAndClose` 经 `takeLastSaveIdentityMove` 用迁移后的新 key 检查脏态并纳入关闭列表（不再按已失效的原 key 断言）。

### N04 实例代际未替代会话代际（B04/B05/B11）✅

`documentSession.ts` 建立独立于路径的**会话代际**（`sessionGenerations`，单调递增）：

- **推进时机**：(1) `disposeDocumentSession`（会话终结即作废全部在途任务）；(2) documents Map 中 key 从无到有（同路径新会话建立——经 zustand 订阅实现，避免 documentStore 反向依赖）；(3) `migrateDocumentSession`（另存为：旧 key 作废、新 key 换代）。`instanceId` 回归"同一会话内的编辑器挂载代际"，不再兼任会话身份。
- **统一校验**：所有异步任务捕获调用时的代际，在 await 返回后、产生副作用前重新校验——`flushDocument`（flush 期间换代 → 迟到快照作废返回 null）、`submitCapturedContent`（可选 `sessionGeneration` 参数，旧会话提交丢弃；编辑器注册空窗不再无条件接纳任意快照，B04 通过）、`queuedAutoSave` / `writeDocumentWithBarrier`（排队与 I/O 返回后双重校验，B05 通过：旧自动保存在新会话后执行被跳过，最终写盘仅 `new-session-text`）。
- **写队列语义**（N04 步骤 3）：`disposeDocumentSession` 不再删除队列指针——新同路径会话的写任务串接在旧队列之后（**不越过未完成的旧磁盘写入**）；未开始的旧任务由任务内代际校验取消（执行即跳过）；队列尾部自清理防泄漏。B05 接线调整说明：原测试接线在"新任务排队等待旧 I/O 放行、而 unblock 排在 await 之后"会循环等待——改为并行等待（`const newWrite = ...; unblock(); await Promise.all([gate, oldSave, newWrite])`），**行为断言不变**（`writeDocument` 调用序列 `['new-session-text']`），且比原接线更完整地覆盖了"新任务排队不越过"语义。
- **条件清理**：`removeDocumentIfSessionMatches(key, generation)`——关闭路径的清理携带关闭时的代际，同路径已重开（代际推进）时跳过（B11 通过）。windowStore 全部关闭路径改为**同步条件删除**（原动态 import 异步清理删除）。
- **flush 返回契约收敛**（N04 步骤 5）：`flushDocument` 代际失效返回 null；调用方（saveDocument/saveAs/moveToNewWindow）对 null 不再回退任意旧镜像——结合 N02 屏障，null 快照不得写盘。
- **revision 随身份迁移**（N04 步骤 6）：`moveDocumentRevision(fromKey, toKey)`——另存为后新 key 的真实内容版本连续，`savedRevisions`/`mirroredRevisions` 的迁移才有真实版本可比。
- 适配器（markdown/code `editorCapabilities.ts`）创建时捕获会话代际，flush 提交携带。

### N06 ACK 持续失败反复执行同一请求（B09）✅

- **processedRequests**（consumer 代际内）：drain 处理请求前查表——**已处理过的 requestId 只重试 ACK，绝不重新执行打开副作用**（处理结果先记录再 ACK）。
- **ACK 有上限退避**：立即一次 + 100/300ms 退避重试；同时处理返回 false 与抛异常两种失败。预算耗尽（3 次失败）→ 退出本次 drain（pending 保留在 Rust 队列），**受控定时重试**（5 秒后 requestDrain，可被新事件提前）——不再无限续拉同一页。B09 两个分支（reject/false）通过：process 恰好执行 1 次。
- **正常分页续拉保留**：R07 的非空页主动续拉与空页竞态保障不变（40 请求测试与空列表竞态测试继续通过）。
- **epoch 捕获**：drain 运行者捕获启动时的 `bootEpoch` 与 `consumerId`，每个 await 后校验——dispose/换代后旧运行者停止（不读取可变全局 consumerId 为旧请求确认）。`resetBootCoordinatorForTest` 递增 epoch 作废挂起 drain，防跨测试泄漏。
