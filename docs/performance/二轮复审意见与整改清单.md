## N01 · P0：迁移中止被误判为提交成功（原 R06）

位置：[windowManager.ts:514](C:/Software/WorkSpace/NoteBoard/src/features/window/windowManager.ts:514)，尤其第 552 行；源删除路径在[第 490 行](C:/Software/WorkSpace/NoteBoard/src/features/window/windowManager.ts:490)。后端中止逻辑：[commands.rs:301](C:/Software/WorkSpace/NoteBoard/src-tauri/src/window/commands.rs:301)。

**反例 B08 已复现：**源有未保存正文 → begin 成功 → 30 秒内一直 preparing → 超时 query 仍 preparing → `abortTransfer` 成功返回 aborted。代码执行 `settle(aborted.state === 'aborted')`，即 `settle(true)`。上层把 true 当成 committed，关闭源标签并移除正文。测试实际结果为 `{ result: true, content: undefined }`，正确结果应为 `{ result: false, content: 'only-unsaved-copy' }`。

Rust 成功 abort 会清空迁移 payload，并向对方窗口发送 aborted。因此该错误不能靠“后端留着一份迁移数据”兜底。发生时仍可能有自动暂存，但当前逻辑没有证明它已经保存了这次正文。

整改步骤：

1. 立即纠正 aborted 分支，随后将内部结果改成 `committed / aborted / pending-or-unknown` 的判别结果，避免再用一个布尔值同时表达“操作成功”和“迁移提交成功”。
2. 只有权威 committed 才允许清理源会话；aborted 必须保留源正文、历史和视图状态。commit 与 abort 抢占时，以后端终态为准。
3. abort 被拒不能直接当失败并解锁源：可能刚刚 committed，需要重新查询。query 也失败时，保留数据并保持迁移保护，提供重试对账；源、目标均不能因为“未知”而同时恢复写入。
4. `settle` 同时清除轮询和超时句柄，处理销毁、晚到响应与重复事件。当前成功提前 settle 后，30 秒 timeout 仍会执行查询。
5. 完成“保护输入 → 处理 IME 尚未提交内容 → flush → 捕获 revision/历史/视图 → begin”的完整屏障。当前代码在捕获 payload 后才 blur；blur 不是会话写保护，也不能保证没有组合输入提交或程序命令继续修改。
6. 补齐所有可迁移类型的真实视图捕获与恢复。当前 Markdown 能力对象没有 `captureViewState`，`capabilities?.captureViewState?.() ?? null` 不能证明 Markdown 视图已迁移。`expected_revision` 在 Rust 中被保存，但目前没有对应的实际版本校验，不能把字段存在当成冲突保护。

验收：B08 转绿；增加 committed 事件丢失、commit 响应丢失、abort 被 committed 拒绝、双方查询失败、目标重载、IME 输入中迁移。每步检查正文、历史、视图、所有权、写权限；任何时刻不能同时存在两个有写权限的会话。真机组合验证仍必需。

**B09 两种分支均已复现：**list 始终返回同一个待确认请求；ACK 抛异常或返回 false。处理完非空页后无条件续拉，同一个 processor 被执行 3 次。测试在第 4 次 list 主动抛错作为断路器，避免运行无限循环；生产代码不存在这个测试断路器。若后端持续返回同一非空页，循环将继续。报告所述“仍失败下次 drain 再处理”与代码不符。

整改步骤：

1. 在当前有效 consumer 代际内记录 requestId 的处理结果；处理成功但 ACK 失败，重试确认结果，不能重新执行打开副作用。
2. 同时处理 ACK 的 false 与异常。重试用有上限、可取消的退避；达到本次预算就退出当前 drain，保留 pending，等待下一次有效唤醒或受控定时重试。
3. 正常非空分页仍主动续拉，保留已修好的 40 请求测试和空页竞态保障。
4. drain 捕获 consumer/boot epoch，每次 await 后检查；dispose 后停止旧运行者，不能继续读取可变的全局 consumerId 为旧请求确认。

验收：B09 两个用例转绿；增加 ACK 偶发失败后恢复、处理成功但响应丢失、consumer 换代、dispose 时 pending list 返回、多页中一个失败。检查每个 requestId 的实际打开次数和 IPC 次数上界，不能只检查队列最后为空。
