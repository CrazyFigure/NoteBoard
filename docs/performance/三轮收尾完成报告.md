## 各项完成明细

### 1. N01 后半：expected_revision 后端对账校验 ✅

- **Rust** `prepare_transfer_complete` / `prepare_transfer_inner` 新增 `actual_revision: Option<u64>` 参数：目标窗口从载荷读取的修订版本与源捕获的 `expected_revision` **对账——不一致（载荷在接纳途中被替换/过期 peek）按中止处理并清空载荷**，不再把字段存在当成冲突保护。
- **前端** `ipc.prepareTransferComplete(label, transferId, actualRevision)`；`adoptTransferredDocument` 携带 `doc.revision` 回报。
- 新增 Rust 测试 `prepare_aborts_on_revision_mismatch`：不匹配 → Aborted + 载荷清空 + 所有权不切换；匹配照常提交。

### 2. N05 步骤 5：prepare reservation 生命周期 ✅

- **`PendingPrepare` 状态结构**（state.rs）：`pending_prepares` 从"读盘期间去重标记"扩展为完整生命周期——**在途（reserved=false）→ 注册预约（reserved=true，读盘完成保留，等待 register 兑现）→ 兑现/释放**。
- **空窗消除**：`prepare_document` 读盘完成且结果将被注册（Text/Image/Unsupported）时**不再移除标记，转为预约**——"prepare 返回到前端 register 之间"的归属空窗内，并发第二请求仍按 `AlreadyOpen` 激活（不双开）。
- **兑现与清理**：`register_document` 成功时兑现预约；`unregister_document` 成功时释放；`unregister_window`（窗口销毁）清理该窗口全部在途与预约。
- **TTL 惰性过期**（30s）：前端崩溃不注册时由下次访问惰性清理（读取点检查，无需后台定时器）；**在途读盘不过期**。`live_pending_prepare` 统一读取口。
- 新增 4 个 Rust 测试：TTL 内存活 / 过期惰性清理 / 在途不过期 / 窗口销毁清理。
- **前端 5×60ms 重试保留**（职责变化说明）：它兜底的是 closeTab 异步 unregister 迟到的竞态（非 prepare 空窗——空窗已由预约消除），保留是正确行为。

### 3. N05 步骤 2：统一异步关闭协调器 ✅

- `windowStore` 导出 **`disposeTabLifecycleAsync(key): Promise<void>`**（可等待）——顺序固定：**停止接纳（markClosed + 会话终结推进代际 + 条件删除文档，同步完成）→ 排空该文档在途写队列 → 按真实窗口身份注销 Rust 归属**。
- `closeTab` 等全部关闭路径：同步部分立即生效（store 一致性），异步部分 fire-and-forget（幂等）。
- `performWindowClose` 改为逐标签 `await disposeTabLifecycleAsync`（删除原独立的 drain 循环 + unregister 循环）——窗口整体关闭的清理序列可被调用者等待。
- 反例 B06/B07 断言保持（注销身份/次数），等待时机适配新顺序（注销在排空后异步发出）。

### 7. S13/J2：保历史组的合并序列化（重做完成）✅

按计划 J 节要求重新实现（一轮 R02 回退的是"时间窗合并丢组"的错误方案；本轮实现的是**按历史组边界**的正确方案）：

- **纯适配器** `serializeMarkdownFromDoc(manager, schema, doc)`（serialize.ts）：对捕获的不可变 ProseMirror 文档快照序列化——`removeRedundantMarkdownEscapes` 参数化（参考文档=快照而非 `editor.state.doc`）；转义器临时替换同步独占、finally 恢复（J 节要求）。**7 个 roundtrip fixture 与 `serializeMarkdown(editor)` 输出逐字等价**（真实 TipTap 实例测试）；**快照独立性测试**：捕获后继续编辑，序列化仍返回捕获时刻内容。
- **visual 热路径**（VisualKernel onUpdate）：只捕获 `transaction.doc` 不可变引用（**O(1)，零全文工作**）+ revision + 组信息——**新历史组开始（undoDepth 增大）时立即物化上一组末端**（跨组节点全部保留，不因合并丢组——R02 反例保持通过）。
- **source 热路径**（CM updateListener）：同样只暂存不可变 Text 引用；每键 `toString()` 全文工作消除。
- **物化入口**（`visualSnapshot.ts`）：500ms 防抖、组边界、以及 **documentHistory 导航/读取钩子**（undo/redo/getCurrent/synchronize/serialize 五个入口先物化——`registerHistoryMaterializeHook` 多实例集合）；flush/save/切模式/迁移导出均先物化。
- **dirty 快速路径**（J 节要求）：有未物化变化即保守标脏（受保护——不出现"实际改了但暂时干净"的关闭漏保）；物化时与基线精确比较重算（改回原文最终清脏）。
- **capabilities.flush** visual/source 分支先物化暂存（提交携带会话代际，N04 语义保持）。
- **测试**（9 例）：纯适配器等价 5 + 快照独立 + 转义器恢复（真实 TipTap）；热路径零全文工作（4 次输入 1 次序列化）+ 组内合并 + 跨组保留 + undo 前物化 + 防抖物化（mock 内核执行真实 onUpdate）。
- **诚实口径**：输入热路径的全文工作已消除（每键 O(1) 引用捕获）；序列化成本转移到组边界/防抖/导航物化点。
