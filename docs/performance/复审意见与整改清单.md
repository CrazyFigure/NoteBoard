## R01 · P0：未加载恢复标签会覆盖或误删原暂存副本

位置：[closedWindowSession.ts:135](C:/Software/WorkSpace/NoteBoard/src/features/session/closedWindowSession.ts:135)、[stagingManager.ts:31](C:/Software/WorkSpace/NoteBoard/src/features/staging/stagingManager.ts:31)、[stagingManager.ts:148](C:/Software/WorkSpace/NoteBoard/src/features/staging/stagingManager.ts:148)。

恢复流程为带 stagedPath 的标签创建 `content: ''`，标 dirty，并将原暂存路径登记到 stagedPaths。后台暂存随后选中它；无编辑器时 syncDocumentContent 原样返回占位文档，collectDocuments 就把空串与原 targetPath 交给 stashDocuments。对于未命名笔记，该路径可能正是唯一恢复副本。

复现：会话中有 `sourcePath=null, stagedPath=only-copy.md` → 恢复停留 Home，不点击标签 → 触发正常暂存。独立测试观察到一次向原 targetPath 写入空内容的调用。实际桌面启动已注册暂存管理器，800ms 调度、5 秒兜底或失焦都可能进入此路径。

另一个风险是 `registerRestoredStagedPath` 用空字符串表示“未知内容”，而 `onDocumentSaved` 又将 `!record.content` 视为“已被保存覆盖”的证明，可能删除尚未读取/并不相同的恢复副本。已命名文件原计划是恢复原路径并另外保留暂存修改，目前也被错误地统一标成 dirty，占位内容因此进入写入链。

**修改要求：**

1. 把 `unloaded` 与“已加载的空文档”建模为不同状态；未知内容不能用空串代替，也不能参加正文写入/暂存重写。
2. 未加载的恢复条目保留原暂存引用。关闭、暂存、保存前按操作语义加载所需内容，或者只持久化引用，不覆盖原文件。
3. 暂存清理以已确认的内容/版本为证明；未知内容必须保留。分开处理命名原文件与未命名暂存恢复，保持原计划的原路径优先规则。
4. `clearSession()` 目前在只建立内存描述符后调用；需先把恢复事务/引用可靠落盘，保证此后异常退出仍可再次找到未加载条目。

验收：未命名与已命名各有一份暂存，恢复 Home 后停留、失焦、关闭、点击、保存、进程异常结束，原副本不会被空内容覆盖或无证明删除。新增“真实恢复 + 真实暂存收集”的组合测试，不能仅断言 lazySource 和 dirty 字段存在。

## R02 · P1：Markdown 新的 pending 机制丢历史，并与模式切换脱节

位置：[VisualKernel.tsx:100](C:/Software/WorkSpace/NoteBoard/src/features/editor-md/VisualKernel.tsx:100)、[VisualKernel.tsx:183](C:/Software/WorkSpace/NoteBoard/src/features/editor-md/VisualKernel.tsx:183)、[TipTapEditor.tsx:477](C:/Software/WorkSpace/NoteBoard/src/features/editor-md/TipTapEditor.tsx:477)、[editorCapabilities.ts:112](C:/Software/WorkSpace/NoteBoard/src/features/editor-md/editorCapabilities.ts:112)。

pendingChangeRef 只有一个槽。当 500ms 内出现两个原生历史组时，第二组覆盖第一组；最终只对最新 editor 状态记录一次历史。复审测试产生 `base → base-first → base-first-second` 两组，再冲刷，撤销直接回到 base，跳过应保留的 base-first。

更直接的编辑风险：可视化输入尚未到 500ms 时切源码，toggleViewMode 优先取旧的 `getCurrentDocumentHistoryContent`，然后清定时器，**没有先 flush pending**。源码视图可能显示旧内容。undo/redo 入口也没有统一先接纳 pending，立即撤销与正常等 500ms 后撤销行为不一致。

**修改要求：**按原计划 J2 保存每个历史组的不可变末端快照，合并只能发生在同组；若尚未实现，先恢复原有正确历史记录方式，不能把历史语义降级记作 S13 通过。切模式、undo/redo、保存、迁移、回收共用确定的 pending 屏障；无 pending 必须 no-op，源码模式不能冲刷不再权威的 visual 模型。

验收：两个不连续位置的快速编辑、连续输入中暂存、立即切源码、立即撤销、500ms 前后操作结果等价；保留原分组、选区、跨模式与 201 节点语义。不能用减少序列化次数的单一测试代替历史保真验证。

## R11 · P1/P2：字体启动门槛仍存在，“按 face”实际上按整族加载
