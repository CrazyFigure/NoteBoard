## 2. 文件关联与启动入口（只读注册表检查）

- `HKCU\Software\Classes\.md` 默认值 → `NoteBoard.Markdown`；同类 ProgID 共 8 个：`NoteBoard.{Board,Image,Json,Markdown,Sql,Text,Xml,Yaml}`。
- `NoteBoard.Markdown\shell\open\command` → `C:\Software\NoteBoard\noteboard.exe "%1"`：**exe 直接收路径参数，无脚本启动器**，与计划 P0-1 的判断一致。
- ⚠️ `HKCU\...\FileExts\.md\UserChoice` 的 ProgId 为 `Markdown`，且该 ProgID 的 open command 不存在（HKCU/HKLM 均未找到）。这意味着用户当前 .md 双击的实际归属取决于 Windows 对无效 UserChoice 的回退行为——**实施者后续现场采集时必须先确认双击 .md 实际启动的是哪个程序**，否则测量的不是 NoteBoard。这不是代码问题，属用户环境状态。
- 无 App Paths 注册项；安装器为 NSIS（uninstall.exe 存在）。

## 4. 诊断埋点（spans 基础设施）

默认完全关闭；启动前设置环境变量 `NOTEBOARD_PERF_SPANS=1` 开启。未开启时所有采集路径只做一次原子布尔读，不写盘、无 IPC。

| 层 | 模块 | 记录点 |
| --- | --- | --- |
| Rust | `src-tauri/src/perf/mod.rs`（新） | process_entry（main 第一行）、setup_start/end、window_ready、create_window 区间、close 前 flush |
| Rust 命令 | `src-tauri/src/perf/commands.rs`（新） | `record_web_spans`、`dump_perf_spans` |
| Web | `src/core/perf/perfMarks.ts`（新） | js_entry（附 html 引导差值）、settings_init_done、window_boot_done、session_restore_done、listeners_subscribed、shell_visible_proxy、root_first_frame_raf |
| Web 引导 | `index.html` | `__nbHtmlTs`：head 解析最早点，覆盖入口依赖求值前的盲区 |
| 上报 | `src/core/perf/reportWebSpans.ts`（新） | boot / window-close 两个里程碑批量上报 |

- 输出：`%TEMP%\noteboard-perf\spans-<pid>-<ts>.json`，批量一次性写入；Rust 轴（相对 process_entry 的单调时钟）与 web 轴（performance.now）**分轴保存，不做跨进程直接相减**；上限 1024 条（Rust）/ 256 条（web），超出只累计 dropped。
- 记录内容只有名称/时长/label/描述属性，**无正文、无完整私人路径**。
- 单元测试：`test/core/perfMarks.test.ts`（4 例）、`src-tauri/src/perf/mod.rs` 内嵌 2 例，均通过。
- 局限：进程强杀（任务管理器结束）时最后一批 web spans 可能未落盘；`editor_interactive`、`document_painted` 等里程碑在 S03/S05 编辑器改造落地时接线。

## 5. 最小宿主对照（P0-4 交付物）

`tools/perf-host-min/`：独立最小 Tauri crate（tauri 2.11 同版本、默认 release profile、无插件、无业务依赖），与主应用一致的「初始隐藏 → JS 就绪后显示」窗口策略。构建：

```
cargo build --release --manifest-path tools/perf-host-min/Cargo.toml
```

运行后输出 `%TEMP%\noteboard-perf\minimal-host.json`（process_entry / setup_end / js_ready / first_frame 分轴记录），关闭窗口即退出、不写任何用户数据目录。**现场采集步骤见 §6-3。** 编译验证结果见实施进度 S01 记录。

## 6. 待验证清单（需要用户/现场采集，本实施未执行）

1. **真实启动时延**：安装版 0.2.7+（含本次埋点）后，设置 `NOTEBOARD_PERF_SPANS=1` 从资源管理器双击测试文件，采集 §性能验收口径定义的 5 类场景各 ≥30 次（真正重启冷启动 ≥5 次），p50/p95 及失败率。采集时先按 §2 的提醒确认 .md 双击实际启动的是 NoteBoard。
2. **内存**：主进程 + 归属 UDF 的 WebView2 进程组的 Private Bytes / Working Set / JS heap / DOM 数 / 编辑器实例数；启动峰值、首屏可编辑、空闲 30s/5min、20 混合标签、关闭回落、30 轮开关循环。
3. **最小宿主对照**：同机同缓存条件下，先跑 `tools/perf-host-min` Release 版双击启动 ≥30 次，再同条件跑主应用，差值即应用增量。
4. **字体链路耗时**：字体包已安装 / 未安装两种状态下 `get_font_pack_status`（全量 SHA-256）与 `list_system_fonts`（PowerShell 子进程）的实际耗时（S06 改造的 before 证据）。
5. **watcher 占位行为**（S14 前实测）：`watch_dir/unwatch_dir` 当前实现的真实行为登记。
