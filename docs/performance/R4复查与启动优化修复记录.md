## 本轮发现与处理

| 问题 | 根因与处理 | 状态 |
| --- | --- | --- |
| 失败重试后仍停在加载页面 | 资源重建替换 entry，但订阅者仍在旧 entry；Host 的 subscribe 只依赖 kind，不会自动迁到新 entry。改为按类型维护稳定订阅，不随请求重试丢失 | 修复中 |
| Markdown 首开携带无用高亮运行时 | codeBlockView 只用语言名称规范化，却导入初始化全部语法的 lowlight 模块；扩展装配还向不消费 lowlight 的普通 CodeBlock 注入实例。分离轻量语言元数据，去掉无效初始化，保留实际消费者 | 修复中 |
| Markdown 为剪贴板解析依赖表格通用模块 | 将原样的纯 TSV/CSV 解析抽到共用轻量模块，保留原导出兼容，避免 Markdown 首开牵入整个共享块 | 修复中 |
| 欢迎页离开后仍预取无关编辑器 | 已排程的空闲回调未清理，打开其他类型后仍加载 Markdown/code。补取消及卸载保护，不改变已有欢迎页预取策略 | 修复中 |
| Drawio 回包字段及关联判断错误 | 官方 XML export 返回 xml 和原始请求 message；当前只看 data，且以“迟到名额”假定每个请求必然按序返回。改为真实请求标识匹配，支持缺失、乱序、重复回包 | 修复中 |
| 另存为正文补齐后，撤销历史仍缺最后一笔输入 | 历史在 await 注销前已经移到新 key，之后的 pending 物化又写回旧 key 历史。将历史迁移放到 pending 物化之后、删除旧文档之前；新增正文与历史末端同时一致的反例 | 修复中 |

Drawio 协议依据：[官方嵌入协议](https://www.drawio.com/docs/reference/embed-mode/)、[官方 EditorUi.js](https://github.com/jgraph/drawio/blob/dev/src/main/webapp/js/diagramly/EditorUi.js) 的 XML export 分支（`msg.message = data`、`msg.xml = this.getFileData(true)`）。原报告“协议没有请求关联手段”的判断不成立。

**2026-09-08 用户已明确确认：优先切换速度，已打开的编辑器保留到关闭，暂停后台非必要工作，接受内存随打开数量增长。**已移除 AppShell 切换回收批次，非懒恢复标签始终保持稳定宿主；恢复描述符仍在首次激活后才创建内核。后台 Markdown 浮动菜单及未执行的 Mermaid/PlantUML 预览任务暂停，内容同步、保存、暂存和关闭保护不暂停。

原 C15 的“两实例”验收与这次明确选择冲突：正式测试改为四文档多轮往返实例不变、脏态不重建、关闭只释放目标；原始复审证据不改。不可再将原 C15 的数量失败解释为新策略的实现缺陷。
