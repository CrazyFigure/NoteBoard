# ADR-013：范围边界

**状态**：✅ 已定
**日期**：2026-08-17

---

## 背景

需求原文是「编辑区域的功能实现完全参考 note-gen」。但 note-gen 的**核心不是编辑器，是 AI**：

- `anydoc = "=0.1.8"`（docx/pdf/xlsx/pptx/epub/csv → md）
- `xcap`（截图）、`windows 0.58` 的 `Media_Ocr`（OCR）
- `jieba-rs`（中文分词，为检索服务）
- SQLite + 向量检索、AI 会话历史
- `reqwest_dav`（WebDAV 同步）、`tauri-plugin-http`
- `streamdown`（AI 对话流式渲染）
- 编辑器内的 `ai-completion.tsx` / `ai-suggestion.ts` / `agent-diff-preview-extension.ts`
- 网页剪藏（`turndown` + `@mozilla/readability`）

「完全参考编辑区」这个限定词很关键 —— 用户要的是编辑体验，不是 note-gen 这个产品。

同时 note-gen 的组织模型也与 NoteBoard 冲突：它有「工作区」概念，笔记/记录/画布三分类导航，资产目录硬编码在 appDataDir。

## 决策

**明确排除以下内容，并在实现中主动抵抗范围蔓延。**

| 编号 | 不做 | 理由 |
|---|---|---|
| [OUT-101](../01-需求规格说明.md) | 一切 AI 功能 | note-gen 的核心，但与「记事本替代品」定位冲突；引入后需联网 + 密钥管理，直接违反 NFR-601（无网络） |
| OUT-102 | 云同步 / WebDAV / Git 同步 | 单机应用 |
| OUT-103 | 账号、登录、订阅 | 同上 |
| OUT-104 | 「工作区」概念、笔记库、强制目录结构 | 与 FR-701 单根纯跟随冲突；用户明确说「不是 NoteGen 的导入或者打开工作区」 |
| OUT-105 | 笔记/记录/画布三分类导航 | 用户明确要求混排（FR-703：「我都放在一起的」） |
| OUT-106 | 网页剪藏、OCR、截图 | 范围外 |
| OUT-107 | 插件系统 | 首版不做 |
| OUT-108 | 跨窗口拖拽 tab | 见 [ADR-006](ADR-006-窗口与Tab模型.md) |
| OUT-109 | 分栏预览 | 双模式已覆盖；note-gen 也没有 |
| OUT-110 | 结构化图表画板（流程图/思维导图/看板） | 画板定位为自由手绘白板，见 [ADR-008](ADR-008-画板引擎与文件格式.md) |
| OUT-111 | macOS / Linux | 首版仅 Windows，但代码不刻意写死平台假设 |
| OUT-112 | 多语言界面 | 仅简体中文 |
| OUT-113 | 打印 / 导出 PDF | 首版不做（导出 PNG/SVG 见 FR-508） |
| OUT-114 | SQLite | 见 [ADR-011](ADR-011-持久化方案.md) |
| OUT-115 | 脚注 `[^1]` | note-gen 也不支持；优先级低 |
| OUT-116 | 协同编辑 | 单机应用 |

### 「无网络」是硬约束（NFR-601）

- **不注册 `tauri-plugin-http`**
- CSP 显式设 `connect-src 'none'`
- 唯一例外：用户主动点击「检查更新」（首版可以连这个都不做）

这条约束的价值在于它是**可验证的**：抓包应该看不到任何请求。它同时也是一道防止 AI 功能偷偷回来的闸门 —— 任何 AI 功能都需要联网。

### 从 note-gen 移植时要主动剔除的东西

移植代码时会连带看到这些，必须删掉：

| 移植文件里的 | 处理 |
|---|---|
| `ai-completion.tsx` / `ai-suggestion*.ts` / `agent-diff-preview-extension.ts` | 不移植 |
| `tiptap-editor.tsx` 里的 AI 相关扩展注册与快捷键 | 删除 |
| `sync/` 目录（conflict-dialog、history-sheet、pull-button…） | 不移植 |
| `smart-file-link.tsx` 中依赖笔记索引的部分 | 简化为纯相对路径链接 |
| `store.json` 的全局单例 tab 状态 | 改为 per-window（见 [ADR-010](ADR-010-状态管理与跨窗口同步.md)） |
| 资产目录硬编码 `appDataDir()` | 改为文档同目录 `assets/` |
| 中文目录名 `画布资源/` | 改为 ASCII |
| `fs:scope: ["**"]` 全盘放开 | 改为运行时动态授权（NFR-604） |
| `mermaid` 的 `securityLevel: 'loose'` | 改为 `'strict'`（NFR-605） |
| `withGlobalTauri: true` | 改为 `false` |
| `security.csp: null` | 改为显式 CSP |
| 死代码（`@antv/infographic`、`markdown-input-rules.ts`、8 个零引用的 TipTap 扩展） | 不移植 |

### note-gen 的三处「历史包袱」不要抄

1. **资产目录绑死 appDataDir** —— 只有笔记跟随工作区，`screenshot/` `image/` `recordings/` `canvas-thumbnails/` 全部硬编码在 appDataDir。这让「整个工作区可拷贝」不成立。NoteBoard 所有资产都在用户目录内。
2. **三套互不一致的扩展名白名单** —— `MARKDOWN_EXTENSIONS`（37 项）/ `OPENABLE_EXTENSIONS`（2 项）/ 索引层（只认 `.md`）。NoteBoard 用单一真相源 `core/docKind.ts`。
3. **`fs:scope: ["**"]`** —— 为支持任意工作区直接放开整盘读写。安全上很激进。

## 被否方案

### 保留 AI 功能，做成可选

否决：

1. 用户没要求。需求原话限定在「编辑区域」。
2. 引入后需要密钥管理、网络层、错误处理、成本提示，是一整个子系统。
3. 破坏 NFR-601 这条可验证的硬约束。
4. 首版就背上一个大包袱。

### 保留工作区概念作为可选模式

否决：用户明确说「不是 NoteGen 的导入或者打开工作区」。而且它与 [ADR-007](ADR-007-资源管理器语义.md) 的单根纯跟随语义直接冲突 —— 两种模型并存会让资源管理器的行为无法用一句话说清。

### 做导出 PDF

否决（暂缓）：note-gen 的实现是开一个隐藏窗口加载 `/print` 路由再打印，工作量不小。首版不做，记为 OUT-113。导出 PNG/SVG（画板）保留，因为那是 Excalidraw 自带能力。

## 代价

1. **NoteBoard 会显得「功能少」。** 这是刻意的 —— 定位是「一个能当记事本用的笔记软件」，不是全能工作台。
2. **移植 note-gen 代码时要花额外精力剔除 AI 相关部分。** `tiptap-editor.tsx` 是 229 KB 单文件，AI 相关代码与编辑器逻辑交织在一起，剔除时要小心不要拆坏。
   - 对策：移植时**先跑通不含 AI 的最小扩展集**，再逐个加扩展，而不是整文件搬过来再删。
3. **将来若要加 AI，需要重新引入网络层与 CSP 放宽**，那时 NFR-601 要作废并新开 ADR。

## 什么情况下该重新考虑

- 用户明确要求 AI 功能
- 首版发布并稳定后，作为独立的大版本特性重新评估
