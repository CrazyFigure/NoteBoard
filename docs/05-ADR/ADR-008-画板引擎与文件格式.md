# ADR-008：画板引擎与文件格式

**状态**：✅ 已定
**日期**：2026-08-17

---

## 背景

需求：「笔记软件 + 画板功能」，「还要适配几个画板的格式」。

note-gen 的画板实测：

- 引擎是 **`@xyflow/react ^12.11.2`（React Flow）** —— 不是自由手绘白板，而是**结构化节点图**
- 全仓 grep `excalidraw|tldraw|fabric|konva` = **0 命中**
- 7 种项目类型：`blank` `flowchart` `mindmap` `timeline` `quadrant` `kanban` `swot`
- 25 种节点类型（16 个流程图形状 + 9 个功能节点），配套 `elkjs`（自动布局）、`perfect-freehand`（手绘笔迹）、`recharts`（图表节点）
- **默认不存文件，存在 SQLite 表 `canvases` 里**（`content` 字段存 `JSON.stringify(CanvasDocument)`，另有 `undoStack`/`redoStack` 各存最近 50 快照）
- 导出文件扩展名 `.canvas.json`（双扩展名），格式为 `CanvasPortableFile { format: 'notegen-canvas', version: 1, title, canvasType, document, exportedAt }`
- 画布内插图存到工作区的 **`画布资源/{uuid}.{ext}`**（硬编码中文目录名）
- 缩略图存 `appDataDir()/canvas-thumbnails/{id}-v4.png`

用户被问「画板用哪个引擎」时，明确选择 **Excalidraw / `.excalidraw`**。

## 决策

**引擎 Excalidraw（`@excalidraw/excalidraw`，MIT）；文件格式 `.excalidraw`（原生 JSON），一个画板 = 一个文件。**

### 1. 文件是唯一存储，不用数据库

`.excalidraw` 文件直接躺在用户目录里，和 `.md` 混排在同一棵资源管理器树中（FR-703）。**不存 SQLite**（见 [ADR-011](ADR-011-持久化方案.md)）。

这是与 note-gen 最大的分歧，也是「文件优先」定位的直接结果：用户能把整个笔记目录拷到 U 盘带走，画板跟着走。

### 2. 保持 Excalidraw 原生文件结构（FR-509）

写盘时使用 Excalidraw 官方的序列化结构：

```json
{
  "type": "excalidraw",
  "version": 2,
  "source": "https://github.com/CrazyFigure/NoteBoard",
  "elements": [ /* ExcalidrawElement[] */ ],
  "appState": { "viewBackgroundColor": "...", "gridSize": null },
  "files": { /* 内嵌图片的 BinaryFiles */ }
}
```

**硬约束（NFR-506）**：保存的 `.excalidraw` 必须能被 excalidraw.com 正常打开。

**不加自定义顶层字段。** note-gen 的 `CanvasPortableFile` 那种自定义信封（`format: 'notegen-canvas'`）会让文件只有本应用能读。我们要的是相反的效果。

如果确实需要存 NoteBoard 私有元数据，放在 `appState` 下的命名空间键（Excalidraw 会保留未知的 `appState` 字段），而不是顶层。

### 3. 不自定义图元类型

沿用 Excalidraw 的 `ExcalidrawElement`，一个自定义类型都不加。任何自定义图元都会破坏第 2 条的互操作性。

### 4. 主题联动（FR-507）

Excalidraw 只有 `theme: 'light' | 'dark'` 两档，而我们有三套主题：

| NoteBoard 主题 | Excalidraw `theme` | 额外处理 |
|---|---|---|
| 晨光 | `'light'` | 覆盖 CSS 变量对齐清白+蓝 |
| 琥珀 | `'light'` | **覆盖 CSS 变量对齐暖象牙+陶土**（关键差异点） |
| 墨夜 | `'dark'` | 覆盖 CSS 变量对齐深蓝 |

晨光与琥珀都映射到 `'light'`，两者的视觉差异 100% 靠覆盖 Excalidraw 自己的 CSS 变量实现（画布底色、工具栏、面板、选中框）。具体变量清单在 [主题与设计规范](../06-主题与设计规范.md) §7。

`viewBackgroundColor` 需要特殊处理：它**存在文件里**。若跟随主题改写它，会导致「换个主题打开同一个文件，文件内容被改了」。
**决策**：`viewBackgroundColor` 保持文件中的原值不动；主题只影响画布**外**的 UI（工具栏、面板、边框）。新建画板时按当前主题写入初始值。

### 5. 中文支持（FR-506）

Excalidraw 默认字体不含中文，需要配置字体回退。实现要点写在 [路线图](../09-开发路线图.md) 阶段 6。

### 6. 自动保存

`SavePolicy = 'auto'`（见 [ADR-005](ADR-005-保存策略.md)）：`onChange` → 300ms 防抖写 store → 800ms 防抖写盘。

### 7. ViewState 必须保住画板视口

`BoardViewport = { scrollX, scrollY, zoom }`。切 tab 再切回来、迁移到新窗口，视口不能跳回原点。

## 被否方案

### React Flow（note-gen 的选择）

否决：

1. 它是**结构化节点图**，不是自由手绘白板。用户要的是「画板」，语义更接近白板。
2. 需要自研 25 种节点类型、自动布局、导出、撤销栈——note-gen 在这上面投入了 13 个 lib 文件 + 一整套 store + SQLite 表。
3. 它的存储天然依赖数据库（撤销栈存表），与「文件优先」定位冲突。
4. 用户明确选了 Excalidraw。

### tldraw

否决：交互确实更现代顺滑，形状系统更强，但：

1. **v2/v3 的商用授权有水印条款需要确认**，法务不确定性
2. 与 note-gen 无关，无参考代码
3. 用户选了 Excalidraw

### 两个都支持（按扩展名分派）

否决：功能最全但打包体积 +3–4 MB，且两套画板的工具栏/主题都要分别适配晨光与琥珀，工作量约翻倍。

### 自研 Canvas 画板

否决：手绘平滑、图元变换、文本编辑、撤销栈、导出——这些是几年的工作量。

## 代价

1. **`@excalidraw/excalidraw` 体积约 2 MB**，必须动态 `import()`，首次打开 `.excalidraw` 有一次加载延迟。
2. **Excalidraw 只有明暗两档主题**，晨光与琥珀的区分要靠 CSS 变量覆盖，这部分是我们自己维护的适配层，Excalidraw 升级时可能需要跟着调。
3. **无法打开 note-gen 的 `.canvas.json`。** 若将来需要，可以写一个单向导入器（React Flow 节点 → Excalidraw 图元），但形状语义不完全对应，会有损。不在首版范围。
4. Excalidraw 的 React 版本要求需与我们的 React 19 对齐，升级时要留意。

## 什么情况下该重新考虑

- 用户实际需要的是流程图/思维导图（结构化节点），而非自由手绘
- 需要打开 note-gen 的画布文件
