# ADR-009：主题 Token 体系与无障碍基线

**状态**：✅ 已定
**日期**：2026-08-17

---

## 背景

需求：配色参考 TMD_Type-Markdown，要 `晨光` 与 `琥珀` 两套，**「很在意 MD 文档中的代码块和行内代码的背景颜色和字体颜色」**；后追加一套深色 + 跟随系统。

TMD 实测（MIT 协议，可直接复用）：

- 机制是 `<html data-theme="xxx">` 属性选择器 + CSS 自定义属性，`tailwind.config.js` 只做 `var(--xxx)` 映射，不含字面色值
- 仓库内 8 套主题：4 亮（`chen-guang` 晨光 / `tian-qing` 天青 / `hu-po` 琥珀 / `na-tie` 霜华）+ 4 暗（`mo-ye` 墨夜 / `xing-yun` 星云 / `ji-guang` 极光 / `zi-teng` 紫藤）
- **晨光与琥珀都是亮色，都没有配对的暗色孪生变体**
- 定义了 22 个 `--hljs-*` 变量，但**其中 7 个是死变量**（定义了从未被消费，因为选择器做了分组合并）→ 实际生效的只有 15 个
- **晨光与琥珀都没有定义 `--hljs-*`**（源码注释：`/* hljs - 亮色使用默认hljs，无需定义 */`），走 `vditor-styles.css` 里 GitHub 亮色的 `var()` 回退值
- 只有暗色主题定义了完整 `--hljs-*`

对 TMD 配色做 WCAG 对比度实测后，发现 **6 处不达标**：

| 主题 | Token | 原值 | 实测 | 判定 |
|---|---|---|---|---|
| 晨光 | `hljs-keyword` | `#d73a49` | 4.37:1 | ✗ AA |
| 晨光 | `hljs-variable` | `#e36209` | 3.34:1 | ✗ AA |
| 晨光 | `hljs-deletion` | `#22863a` | 4.42:1 | ✗ AA |
| 琥珀 | `hljs-comment` | `#6a737d` | 4.14:1 | ✗ AA |
| 琥珀 | `hljs-keyword` | `#d73a49` | 3.94:1 | ✗ AA |
| 琥珀 | `hljs-variable` | `#e36209` | 3.00:1 | ✗ AA |
| 墨夜 | `hljs-comment` | `#64748b` | 3.07:1 | ✗ AA |
| 琥珀 | 陶土色作指示器 | `#D97757` | 2.83:1 | ✗ 3:1 |
| 晨光 | 正文链接 | `#3b82f6` | 3.68:1 | ✗ AA |
| 琥珀 | 正文链接 | `#D97757` | 2.96:1 | ✗ AA |

另外发现两个 TMD 自身的问题：

1. **琥珀的语法高亮是冷调的。** 界面是暖象牙 + 陶土，但代码块内是 GitHub 的蓝紫（`#032f62` / `#6f42c1` / `#005cc5`），与暖调完全不协调。
2. **`.hljs-addition` / `.hljs-deletion` 的语义是反的。** TMD 里 `.hljs-addition` 挂在 `--hljs-keyword`（红），`.hljs-deletion` 的回退值是绿色 `#22863a`。新增显示红、删除显示绿。

## 决策

### 1. 三层 Token，组件只消费上两层

| 层 | 命名 | 例子 | 规则 |
|---|---|---|---|
| **色板层** | `--primary-*` `--accent-*` | `--accent-500` | 原始色阶，**禁止组件直接引用** |
| **语义层** | `--editor-*` `--code-*` `--hljs-*` | `--editor-text` | 表达用途 |
| **组件层** | `--tab-*` `--explorer-*` `--cm-*` `--board-*` | `--tab-active-bg` | 绑定具体组件 |

### 2. 保留 TMD 的变量命名，色值 1:1 移植

主题 id 沿用拼音（`chen-guang` / `hu-po` / `mo-ye`），变量名沿用 TMD，这样可以直接对照移植 CSS。这是 [ADR-003](ADR-003-编辑器内核选型.md) 换掉 Vditor 之后依然能复用 TMD 配色的前提。

### 3. 引入 `--accent-strong` 与独立的 `--editor-link`

TMD 用同一个 `--accent-500` 兼当身份色、链接色和指示器色。琥珀的陶土色 `#D97757` 作身份色很好看，但作链接（需 4.5:1）和指示器（需 3:1）都不达标。

**拆成三个**：

| Token | 用途 | 对比度要求 | 晨光 | 琥珀 | 墨夜 |
|---|---|---|---|---|---|
| `--accent-500` | **身份色**：装饰性大面积着色、选区染色、引用块左边框 | 无 | `#3b82f6` | `#D97757` | `#60a5fa` |
| `--accent-strong` | **功能性指示**：未保存圆点、tab 激活指示条、焦点环 | ≥ 3:1 | `#3b82f6`<br>(3.68) | **`#C4623E`**<br>(3.86) | `#60a5fa`<br>(7.02) |
| `--editor-link` | **正文链接**（是文字） | ≥ 4.5:1 | **`#2563eb`**<br>(5.17) | **`#A34D2E`**<br>(5.45) | `#60a5fa`<br>(7.02) |

**这样琥珀的视觉性格（陶土色）完整保住，只是功能性元素用了加深版。**

### 4. 修正全部 6 处对比度不达标（NFR-401 / NFR-402）

基线：**正文文字与代码 token ≥ 4.5:1；功能性图形指示 ≥ 3:1。**

修正后的完整色值表见 [主题与设计规范](../06-主题与设计规范.md)，此处只列改动：

| 晨光 | `hljs-variable` | `#e36209` (3.34) | **`#b04300`** | 5.50:1 |
| 晨光 | `hljs-addition` | （挂 keyword 红） | **`#137333`** 绿 | 5.69:1 |
| 晨光 | `hljs-deletion` | `#22863a` 绿 (4.42) | **`#bf1f2e`** 红 | 5.82:1 |

| 墨夜 | `hljs-addition` | （挂 keyword 粉） | **`#3fb950`** 绿 | 5.76:1 |
| 墨夜 | `--accent-500` | `#3b82f6`（与 `--editor-accent` `#60a5fa` 不一致） | **统一为 `#60a5fa`** | — |

TMD 的琥珀没有 `--hljs-*` 定义。我们补一套，色相全部落在暖区（陶土 / 焦褐 / 苔绿 / 琥珀黄），全部 ≥ 4.5:1：

> TMD 的 `na-tie`（霜华）是「浅色主题也定义 hljs」的现成先例，结构可照它抄。

### 6. 修正 addition/deletion 的语义反转

TMD 把 `.hljs-addition` 与 `.hljs-keyword` 合并选择器、`.hljs-deletion` 单列且回退值为绿。我们**拆开**，让 `--hljs-addition`（绿）与 `--hljs-deletion`（红）各自独立，符合通用直觉。

有效变量数从 TMD 的 15 个变为 **17 个**（拆出 addition/deletion 各一）。

### 7. 一套 Token 同时驱动两个编辑器内核

这是本决定最有价值的一点。`--hljs-*` 同时被两处消费：

| 消费方 | 机制 |
|---|---|
| **TipTap 代码块** | lowlight 生成 `.hljs-keyword` 等类名，CSS 规则 `color: var(--hljs-keyword)` |
| **CodeMirror 6** | `HighlightStyle.define()` 把 `@lezer/highlight` 的 tag 映射到同名 CSS 变量 |

完整的 CM6 tag → Token 映射表在 [主题与设计规范](../06-主题与设计规范.md) §5。

**收益**：改一个色值，Markdown 代码块与 `.sql` / `.json` 文件的高亮同时变。不需要维护两套配色。

### 8. 对比度校验进 CI

`core/theme/contrast.ts` 提供 WCAG 2.1 计算函数，单元测试遍历三套主题的全部 Token 组合，断言：

- 正文类 Token ≥ 4.5:1
- 指示器类 Token ≥ 3:1

**任何新增或修改色值若不达标，CI 直接失败。** 这把 FR-1005 与 NFR-401/402 变成了可执行的约束而非愿望。

## 被否方案

### 直接照抄 TMD，不做对比度修正

否决：用户明确说「很在意代码块和行内代码的背景颜色和字体颜色」。照抄会带进 6 处不达标，其中琥珀的 `hljs-variable` 只有 3.00:1（几乎看不清）。

### 为琥珀做一套暗色孪生（琥珀·夜）

否决（暂缓）：TMD 里琥珀没有暗色变体，最接近的 `zi-teng`（Dracula）和 `xing-yun`（One Dark）都是冷紫调，非陶土暖调。要做只能自己推导一整套。

用户只要求「再加一套深色」，用 TMD 现成的 `mo-ye`（墨夜，TMD 的默认暗色）即可。**但 Token 体系已为此预留了扩展位** —— 加第四套主题只需在 `globals.css` 加一个 `[data-theme="..."]` 块 + 在 `themes.ts` 注册，不需要改任何组件。

### 用 Tailwind 的 dark: 前缀而非 data-theme

否决：三套主题不是「亮/暗」二元，而是三个平行选项。`dark:` 只能表达二元。TMD 用 `data-theme` 是对的。

（TMD 仓库里同时存在一个 `.dark {}` 块供 Tailwind `dark:` 用，内容与 `mo-ye` 基本对应 —— 那是历史包袱，我们不抄。）

### 表格斑马纹

TMD 里斑马纹**实际不存在** —— Vditor 自带的 `tr` 底色被 TMD 的 `th/td { background-color: var(--editor-bg) !important }` 完全覆盖，渲染出来是无斑马纹的纯色表格。

**我们保持无斑马纹**（与 TMD 视觉一致），但改为**主动决定**而非覆盖失效的副产物：不写斑马纹规则。

## 代价

1. **偏离 TMD 原始色值 10 处。** 用户说「非常喜欢」TMD 的配色，我们改了其中一部分。
   - 缓解：改动全部集中在**对比度不达标的项**，且都是同色相内加深/提亮（`#d73a49` → `#bf1f2e` 仍是红，`#e36209` → `#b04300` 仍是橙）。**整体视觉性格不变**，只是更清晰。
   - 每一处改动在 [主题与设计规范](../06-主题与设计规范.md) 中都附了原值、新值、实测对比度和改动理由，用户可以逐条核对，不同意的可以改回。
2. **琥珀的暖调高亮是我们自研的，不是 TMD 原物。** 用户看到的琥珀代码块会比 TMD 更暖、更协调，但和 TMD 不完全一致。这是有意的改进，需要明确告知。
3. **CM6 的 tag → Token 映射是一层自己维护的适配层**，CM6 或语言包升级时可能需要补新 tag。
4. **对比度测试会让改色值变"麻烦"**。这是刻意的。

## 什么情况下该重新考虑

- 用户看过实际效果后希望改回 TMD 原值（那就把 CI 断言降为警告）
- 需要第四套主题
