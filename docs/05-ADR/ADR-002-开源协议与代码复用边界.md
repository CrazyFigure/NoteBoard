# ADR-002：开源协议与代码复用边界

**状态**：✅ 已定
**日期**：2026-08-17

---

## 背景

需求是「编辑区域的功能实现**完全参考** note-gen」。调研确认了 note-gen 的协议：

- **GNU General Public License v3.0（GPL-3.0-only）**，纯 GPLv3，**无 classpath exception**，**不是 AGPL**
- `LICENSE` 为 674 行标准 GPLv3 全文，`Copyright (C) 2025 codexu, https://notegen.top/.`
- `package.json` 无 `license` 字段；GitHub API `license.spdx_id = "GPL-3.0"`
- 全仓 grep `classpath` = 0 命中

GPL 是传染性协议：把 GPL 代码并入 NoteBoard，NoteBoard 整体必须以 GPL-3.0 兼容协议发布。

而 note-gen 的编辑区确实有真正的技术资产值得复用：

| 资产 | 规模 |
|---|---|
| `tiptap-editor.tsx` 扩展装配 | 229 KB 单文件 |
| 自研 KaTeX 行内/块级节点（`atom: true` + ReactNodeView + LRU 200） | `math-extension.tsx` 13 KB |
| 自研 Mermaid 节点（懒加载 + 全局串行队列 + 陈旧守卫 + 视口门控） | `mermaid-extension.tsx` 11 KB |
| 大纲（PM doc 遍历、双向滚动同步、就地重命名） | `outline.tsx` 907 行 |
| 四层大文档机制（阈值判定 / 视口懒渲染 / 分段虚拟滚动 / Worker 分段） | 约 8 个文件，含 `section-document.ts` 27 KB |
| viewport lowlight PM 插件（±2000 position 裁剪 + rAF 批处理 + 记忆化） | 9.5 KB |
| 斜杠命令 + 选中浮层菜单 | 29 KB + 31 KB |

自己从零写这些，粗估 6–10 周。

## 决策

**NoteBoard 采用 GPL-3.0-only**，以换取合法直接移植 note-gen 的代码。

配套纪律：

1. **`LICENSE`** 放 GPL-3.0 全文。
2. **每个移植文件顶部**加注释块：
   ```
   /*
    * 移植自 codexu/note-gen（GPL-3.0-only）
    * 原始路径：src/app/core/main/editor/markdown/math-extension.tsx
    * 原始版权：Copyright (C) 2025 codexu, https://notegen.top/
    * 改动摘要：移除 AI 补全钩子；KaTeX 改为按 --hljs-* 主题变量着色；
    *          视口门控改用本项目的 viewportActivation 复用池
    */
   ```
3. **`THIRD-PARTY-NOTICES.md`** 列出所有第三方来源与协议，包括 TMD（MIT）与全部 npm 依赖。
4. **README 的致谢章节**明确写出「NoteBoard 选择 GPL-3.0 正是为了能够合法复用 note-gen 的 GPL 代码」。

### 协议兼容性核对

| 来源 | 协议 | 能否并入 GPL-3.0 项目 |
|---|---|---|
| note-gen | GPL-3.0-only | ✅ 同协议 |
| TMD_Type-Markdown | MIT | ✅ MIT 单向兼容 GPL，需保留 MIT 版权声明 |
| Excalidraw | MIT | ✅ 同上 |
| TipTap 3 | MIT | ✅ |
| CodeMirror 6 | MIT | ✅ |
| highlight.js / lowlight | BSD-3-Clause / MIT | ✅ |
| KaTeX | MIT | ✅ |
| Mermaid | MIT | ✅ |
| markdown-it | MIT | ✅ |
| Tauri | MIT / Apache-2.0 双许可 | ✅ |
| shadcn/ui | MIT | ✅ |
| dnd-kit | MIT | ✅ |
| zustand | MIT | ✅ |

**无协议冲突。** 需要注意的只有：GPL-3.0 与 Apache-2.0 单独看是兼容的（GPLv3 明确兼容 Apache-2.0 的专利条款）；Tauri 是双许可，取 MIT 分支即可完全无虑。

## 被否方案

### MIT + 净室重写（clean-room reimplementation）

即：不看 note-gen 的代码，只参考它的行为与所用的开源库，全部自己写。

**为什么否决**：用户明确选择了 GPL-3.0。此外从工程角度，净室重写要 6–10 周，且实现中的大量细节（KaTeX 的 LRU 缓存尺寸、Mermaid 的串行队列必要性、视口裁剪的 ±2000 position 这个魔法值、Worker 回传时抹掉 source 字符串这个优化）都是 note-gen 踩过坑才有的经验值，重写时会重新踩一遍。

**这条路本身完全合法** —— 接口、行为、架构不受版权保护，使用同样的公开 OSS 库也没问题。如果将来需要转闭源，这是唯一出路。

### LGPL-3.0

否决：note-gen 是 GPL 而非 LGPL，我们无权把它的代码降级为 LGPL 发布。

### 双许可（GPL + 商业）

否决：双许可要求项目方持有全部代码的版权。移植了 note-gen 的 GPL 代码后我们不持有，无法双许可。

## 代价

1. **NoteBoard 必须永久开源。** 分发二进制时必须同时提供完整对应源码（GPLv3 §6）。
2. **不能转闭源，不能出闭源商业版。** 任何基于 NoteBoard 的衍生作品也必须 GPL-3.0。
3. **未来若要移除 GPL 约束，必须把所有 note-gen 血统的代码全部净室重写。** 因此第 3 条纪律（文件头注明来源）不只是礼节，而是将来做这件事时唯一的清单依据 —— **必须严格执行，不能漏标**。
4. 提交前需要人工检查有无未标注来源的移植片段。建议在 CI 加一条检查：`features/editor-md/` 下的文件若不含 `移植自` 或 `原创` 标记，则告警。

## 什么情况下该重新考虑

- 需要商业闭源发行
- note-gen 变更协议（不影响已获得的版本，但影响后续同步上游）
