# ADR-007：资源管理器语义

**状态**：✅ 已定
**日期**：2026-08-17

---

## 背景

需求原文：「在一个窗口中，左侧的目录需要随着 tab 的切换，切换并展示该文件父级的目录」。

同时另一条需求要求能「打开或创建指定文件**或者目录**」。

这两条之间有一个真实冲突：

> 我刚打开 `D:\notes` 目录准备浏览，一点别的 tab（文件在 `C:\project`），树就跳走了。怎么回去？

三种解法被明确提出并交由用户选择：

| 方案 | 描述 |
|---|---|
| A | 多根并存 + 自动聚焦（VSCode 多根工作区风格） |
| B | 单根 + 图钉锁定按钮 |
| C | 单根 + 面包屑 + 后退按钮 |
| D | 单根，纯跟随，不加任何控件 |

**用户先选了「单根，切 tab 即替换」，在被追问冲突后明确选择「就要纯跟随，不加控件」。**

## 决策

**单根、纯跟随、不加任何回退控件。**

精确规则：

```ts
// 激活 tab 变化时
function onActiveTabChanged(doc: Document) {
  const newRoot = doc.dirPath;
  if (!sameKey(explorer.root, newRoot)) {
    explorer.root = newRoot;
    explorer.expanded.clear();     // 不变式 I-16
    explorer.children.clear();
  }
  explorer.revealed = doc.key;      // 无论 root 是否变化都重新定位
}
```

### 一个刻意保留的缓冲

**切到同目录的另一个文件时 root 不变**，只更新 `revealed`，展开状态完整保留。只有跨目录才重建树。

这是「纯跟随」在体验上唯一的缓冲，而且它覆盖了最高频的场景——在同一个笔记目录里的几个文件之间来回切。

### 「打开文件夹」的语义

`Ctrl+K Ctrl+O` 把所选目录设为 `explorerRoot`，**不自动打开任何文件**。此时若当前有激活 tab，用户一旦切 tab，树就会被覆盖——**这是预期行为，不是 bug**。

### 顶部路径显示

树顶部显示当前根的完整路径，过长则中间省略，悬停显示全路径（FR-712）。

**这个路径是纯展示，不可点击。** 不做面包屑跳转——那等于偷偷把方案 C 做了一半，会让「纯跟随」的规则变得含糊。

## 被否方案

### A：多根并存 + 自动聚焦（我的原始推荐）

否决：用户明确不要。

我原本推荐这个方案，理由是「跨目录来回切 tab 时不丢展开状态」。但用户的选择是自洽的——见下面「为什么用户的选择是对的」。

### B：图钉锁定按钮

否决：用户明确不要。引入一个「锁定态」的模式概念，用户需要理解「现在是跟随还是锁定」，且要记住自己有没有锁。对一个「随手打开文件」的工具来说是过度设计。

### C：面包屑 + 后退按钮

否决：用户明确不要。后退按钮意味着要维护一个根目录历史栈，又是一个隐藏状态。

## 为什么用户的选择是对的

追问之后我认为用户的选择比我的原始推荐更好，理由：

1. **规则可完整表述为一句话**：「树永远显示当前文件所在的目录」。没有例外、没有模式、没有隐藏状态。用户永远不会疑惑「为什么树是现在这样」。
2. **冲突场景的实际频率被高估了。** 真实使用中，绝大多数时间是在同一个目录（或其子树）里工作 —— 而这个场景被「同目录不重建」的缓冲完整覆盖了。真正跨盘跨项目来回切 tab 的情况很少。
3. **「想浏览目录」和「想编辑文件」是两个不同的任务模式。** 前者用系统资源管理器更顺手（`Ctrl+Shift+E` 打开系统资源管理器定位当前文件）。硬要在编辑器里做完整的文件浏览器是在错误的地方投入。
4. **零 UI 成本。** 不占空间、不加按钮、不加图标。对一个刻意做窄的工具是加分。

## 代价

1. **跨目录来回切 tab 时，展开状态反复丢失。** 这是唯一的、确定存在的代价。
   - 缓解：`revealed` 定位会自动展开到目标文件的路径链，所以「切过去看不到文件」的情况不会发生 —— 只是**其他**分支的展开状态没了。
2. **「打开文件夹」的效果可能被下一次切 tab 抹掉**，对新用户可能困惑。
   - 缓解：打开文件夹后若当前无激活 tab（欢迎页），树会稳定停在那里——这恰好是「我想浏览一下」的典型场景。
3. 每次 root 变化都要重新 `read_dir` 并重建监听。性能上可忽略（NFR-109：1000 条目 ≤ 500ms），但要注意**切换监听目标**（一个窗口同时只监听一个根）。

## 实现要点

| 要点 | 说明 |
|---|---|
| **不变式 I-16** | `root` 变化时必须清空 `expanded` 与 `children`，否则会显示上一棵树的残留节点 |
| **监听跟随** | root 变化 → `unwatch_dir(旧)` + `watch_dir(新, recursive, delayMs: 500)` |
| **Rescan 降级** | 收到 `nb://explorer-rescan`（notify 缓冲区溢出，16 KiB 硬编码不可配）必须全量重扫，否则漏改动 |
| **自然排序** | 目录在前、文件在后，各自按名称自然排序（`file2.md` < `file10.md`） |
| **按需加载** | 只加载展开节点的子项，不递归预读 |
