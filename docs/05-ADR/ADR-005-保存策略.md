# ADR-005：保存策略

**状态**：✅ 已定
**日期**：2026-08-17

---

## 背景

NoteBoard 同时服务两个对保存期望**相反**的场景：

| 场景 | 期望 | 理由 |
|---|---|---|
| **写笔记**（`.md`、画板） | 自动保存 | 笔记软件的标准行为。note-gen 就是全自动（`autoSave` + `autoSaveDelay`）。写作时按 `Ctrl+S` 会打断思路，忘按则丢内容。 |
| **改配置**（`.sql`、`.json`、`.yaml`） | 手动保存 | 记事本 / VSCode 的标准行为。用它改生产环境的 `.sql` 或 `docker-compose.yml` 时，误触键盘立刻写盘是**危险**的——用户还没决定要不要改。 |

一刀切任何一边都会伤到另一个场景。

## 决策

**按 `DocumentKind` 分流，策略由类型唯一决定，不可按文件单独覆盖。**

| `DocumentKind` | 扩展名 | `SavePolicy` | 行为 |
|---|---|---|---|
| `markdown` | `.md` `.markdown` | **`auto`** | 防抖 800ms 写盘；失焦、切 tab、关窗前立即写 |
| `board` | `.excalidraw` | **`auto`** | 同上 |
| `code` | `.txt` `.sql` `.json` `.yaml` `.yml` `.xml` 及其他 | **`manual`** | 仅 `Ctrl+S`；脏态显示圆点；关闭拦截 |
| `unsupported` | — | — | 不可编辑 |

### 自动保存的四个触发点

```
内容变更 ──► 起 800ms 防抖定时器 ──► 到期写盘
                    │
                    ├── 编辑器失焦        ──► 取消定时器，立即写盘
                    ├── 切换到其他 tab    ──► 同上
                    ├── 窗口失焦          ──► 同上
                    └── 关闭 tab/窗口/应用 ──► 同上（写盘失败则取消关闭）
```

### 手动保存的完整反馈链

| 位置 | 表现 |
|---|---|
| tab | 文件名前实心圆点（`--accent-strong`，对比度 ≥ 3:1） |
| 窗口标题栏 | `* filename.sql — NoteBoard` |
| 状态栏 | 「未保存」文字 |
| 关闭 tab | 拦截对话框：保存 / 不保存 / 取消 |
| 关闭窗口 | 批量拦截对话框，逐文件列出，带全选 |
| 关闭应用 | 逐窗口走上一条 |

### 原子写入（FR-1205，无条件适用于两种策略）

```
① 在目标文件的同一目录下建临时文件（tempfile，前缀 .nb-tmp-）
② 写入全部内容 + flush + sync
③ rename 覆盖目标文件（同目录 rename 在 NTFS 上是原子的）
④ 失败时删除临时文件，保留原文件不动
```

**为什么必须同目录**：跨卷 rename 不是原子操作，会退化成复制+删除。

### 不变式

**I-11（来自 [领域模型](../03-领域模型.md)）：`savePolicy === 'manual'` 且脏的文档，绝不允许在没有用户明确选择的情况下丢弃内容。**

**NFR-1209：写盘失败时保留内存内容不丢失**，弹出明确原因（权限不足 / 磁盘满 / 文件被占用 / 只读属性）。

## 被否方案

### 全部自动保存（note-gen 的做法）

否决：用它改生产环境的 `.sql` 或配置文件时，误触键盘即刻写盘，风险不可接受。note-gen 是纯笔记软件，它的文件都是自己创建的笔记，没有这个问题；NoteBoard 明确要当记事本替代品，会打开用户不打算修改的文件。

### 全部手动 `Ctrl+S`

否决：写笔记时忘按 `Ctrl+S` 会丢内容。「笔记软件」这半个定位要求自动保存。

### 按文件单独设置策略

否决：增加一个用户要理解和管理的概念，收益极低。`DocumentKind` 的分界（笔记 vs 代码）已经和用户的心理模型对齐了。

### 全自动保存 + 版本历史（本地快照）

否决：能解决安全性，但要引入版本存储、diff UI、清理策略——对首个版本是明显的范围蔓延。可作为将来的增强。

## 代价

1. **用户需要理解「有的文件自动存，有的不自动」。** 这是本决定唯一的认知成本。
   缓解：状态栏明确显示当前文件的保存模式（「自动保存」/「未保存」/「已保存」），让规则可见而不需要记忆。
2. **`.md` 也可能是用户不想改的文件**（比如别人项目的 README）。自动保存会在他误触后立刻落盘。
   缓解：提供设置项 [FR-1208](../01-需求规格说明.md)「全部改为手动保存」，让在意的用户可以一键关掉自动保存。
3. **两条保存路径 = 两套测试。** 已在 [测试策略](../10-测试策略.md) 中分别覆盖。

## 什么情况下该重新考虑

- 用户反馈自动保存导致误改 `.md` 文件
- 引入了本地版本历史（那时可以安全地全自动）
