# NoteBoard 术语表

> 本表是 NoteBoard 的**受控词汇**。代码中的类型名、变量名、事件名、UI 文案一律以此为准。
> 同一概念只允许一个名字；表中列出的「禁用叫法」不得出现在代码或文档中。

---

## 使用规则

1. **中文名用于 UI 与文档，英文名用于代码标识符。** 二者一一对应。
2. 发现新概念时，**先加进本表再写代码**。
3. 「禁用叫法」列记录了容易混进来的近义词——多数来自 note-gen 或 TMD，语义与本项目不同。

---

## A. 文件与文档

### 文件 · File
磁盘上的一个真实文件。**只在讨论 I/O、路径、文件系统事件时使用这个词。**

### 文档 · Document
一个已打开文件在内存中的完整状态：内容缓冲、脏标记、编码、行尾符、视图模式、光标与滚动位置、撤销栈。

**文件 ≠ 文档**：文件在磁盘上，文档在内存里。一个文件同一时刻最多对应一个文档（跨所有窗口全局唯一，见 [FR-608](../01-需求规格说明.md)）。

| | 禁用叫法 | 原因 |
|---|---|---|
| ❌ | `Note` / 笔记 | 只指 Markdown，无法涵盖 sql/画板 |
| ❌ | `Article` | note-gen 的叫法，且它混装了 tab 状态 |
| ❌ | `Buffer` | 只指内容，不含元数据 |

### 文档键 · DocumentKey
文档的全局唯一标识：**规范化后的绝对路径**。规范化规则：

1. 转为绝对路径
2. 分隔符统一为 `\`
3. 解析 `.` 与 `..`
4. 盘符大写（`c:\` → `C:\`）
5. 其余部分**保留原始大小写**（用于显示），但**比较时不区分大小写**（Windows 语义）

未落盘的新建文档使用形如 `untitled:1` 的临时键，保存后替换为真实路径。

### 文档类别 · DocumentKind
按扩展名判定的三类，决定用哪个编辑器内核：

| 值 | 中文名 | 扩展名 | 内核 |
|---|---|---|---|
| `markdown` | Markdown 文档 | `.md` `.markdown` | Markdown 编辑器 |
| `code` | 代码文档 | `.txt` `.sql` `.json` `.yaml` `.yml` `.xml` 及其他文本类 | 代码编辑器 |
| `board` | 画板 | `.excalidraw` | 画板编辑器 |
| `unsupported` | 不支持 | 二进制等 | 文件信息页 |

> ⚠️ `DocumentKind` 与「语言」是两件事。`.sql` 和 `.json` 的 `DocumentKind` 都是 `code`，但**语言**（`LanguageId`）不同。

### 语言 · LanguageId
代码编辑器加载哪套语法定义。取值：`markdown` `sql` `json` `yaml` `xml` `plaintext`。

### 脏 · Dirty
文档内容与磁盘不一致。UI 表现为 tab 上的实心圆点与标题栏 `*`。

自动保存类文档（Markdown / 画板）也会短暂进入脏态，但**不显示圆点**——用户不需要知道。

| | 禁用叫法 | 原因 |
|---|---|---|
| ❌ | `Modified` | 与「文件系统 modified 时间」混淆 |
| ❌ | `Unsaved` | 名词化困难 |

### 保存策略 · SavePolicy
由 `DocumentKind` 决定，不可按文件单独覆盖：

| 值 | 适用 | 行为 |
|---|---|---|
| `auto` | `markdown` `board` | 防抖 800ms 自动写盘；失焦、切 tab、关闭前立即写 |
| `manual` | `code` | 仅 `Ctrl+S`；脏态显示圆点；关闭时拦截 |

### 外部变更 · ExternalChange
磁盘上的文件被 NoteBoard 之外的程序改动。三种子类：`modified` `deleted` `renamed`。

## B. 编辑器

### 编辑器内核 · EditorKernel
渲染并编辑文档内容的技术实现。NoteBoard 有三个，**互不共享代码**：

| 值 | 中文名 | 技术 | 服务的 DocumentKind |
|---|---|---|---|
| `tiptap` | Markdown 内核 | TipTap 3 / ProseMirror | `markdown`（visual 模式） |
| `codemirror` | 代码内核 | CodeMirror 6 | `code`，以及 `markdown` 的 source 模式 |
| `excalidraw` | 画板内核 | Excalidraw | `board` |

### 视图模式 · ViewMode
**仅 Markdown 文档有此概念。** 二选一，按文档记忆：

| 值 | 中文名 | 内核 | 说明 |
|---|---|---|---|
| `visual` | 所见即所得 | `tiptap` | 默认。Typora 式，直接编辑渲染结果 |
| `source` | 源码 | `codemirror` | 编辑 Markdown 原文，带 Markdown 高亮 |

| | 禁用叫法 | 原因 |
|---|---|---|
| ❌ | `WYSIWYG` / `IR` / `SV` | Vditor 的三态术语，本项目只有两态 |
| ❌ | `preview` / 预览 | 本项目**没有**只读预览态（[OUT-109](../01-需求规格说明.md)） |

### 视图状态 · ViewState
切换模式、切 tab、迁移窗口时必须保住的瞬时状态：光标位置（或选区）、滚动位置、折叠状态、画板视口（`{x, y, zoom}`）。

**这是数据不丢的关键载体。** 任何「关闭再打开」式的操作都必须显式抓取并恢复 ViewState。

### 段 · Section
大文档被切分后的一个片段。切分只在**块边界**发生（不切开代码围栏、表格、frontmatter）。目标 24,000 字符，硬上限 64,000。

同一时刻**只有一个段是真实的 TipTap 实例**（活动段），其余段渲染为只读 HTML。

### 重节点 · HeavyNode
渲染开销大的 Markdown 元素：图片、代码围栏、数学公式块。用于大文档阈值判定（阈值 160 个）。

### 大纲 · Outline
Markdown 文档的标题层级列表。条目称**标题项 · HeadingItem**，字段：`level`（1–6）、`text`、`pos`（文档内位置）、`id`。

大纲从**编辑器文档树**提取，**不解析 Markdown 原文**。

## C. 窗口与 Tab

### 窗口 · Window
一个操作系统级窗口，对应一个 Tauri `WebviewWindow`。有自绘标题栏，含自己的 tab 栏、资源管理器、编辑区、大纲。

**所有窗口在同一个进程内**（单实例，见下）。

### 窗口标签 · WindowLabel
Tauri 层面的窗口唯一标识，格式 `nb-{序号}`（如 `nb-1`）。

约束：只允许 `a-zA-Z0-9` `-` `/` `:` `_`；**全局唯一，且已关闭窗口的 label 不得复用**（序号单调递增）。

> 主窗口 label 固定为 `nb-main`。capabilities 中用 `nb-*` 通配匹配。

### Tab · Tab
窗口内引用某个文档的一个条目。**Tab 是引用，不是文档本身。**

一个文档全局只有一个实例，但 tab 是窗口内的局部概念。由于 [FR-608](../01-需求规格说明.md) 规定同一文件不重复打开，实际上「一个文档 ↔ 至多一个 tab」，但类型设计上仍保持二者分离。

| | 禁用叫法 | 原因 |
|---|---|---|
| ❌ | `OpenedFile` | 混淆了文档与引用 |
| ❌ | `Editor`（作为名词指 tab） | 与内核混淆 |

### 单实例 · SingleInstance
进程级互斥：无论用户怎么触发打开，**始终只有一个 NoteBoard.exe 进程**。第二次启动会把命令行参数转发给已有进程后自行退出。

> **单实例不限制窗口数量。** 多窗口 = 同一进程内的多个 `WebviewWindow`。这两件事经常被搞混。

### 窗口意图 · WindowIntent
新建窗口时要传给它的初始任务，如「打开这些文件」。

**采用拉取模型**：Rust 侧暂存意图，新窗口前端挂载完成后主动调用命令取走。**不用「建窗后 emit 事件」**——那会因为前端还没注册监听而丢事件。

### 会话 · Session
应用退出时所有窗口与 tab 的快照，用于下次启动恢复（[FR-612](../01-需求规格说明.md)）。

### 草稿 · Draft
未保存内容的崩溃保护副本，周期性写入应用数据目录。正常保存后删除。

## D. 资源管理器

### 资源管理器 · Explorer
左侧面板，展示一棵目录树。

| | 禁用叫法 | 原因 |
|---|---|---|
| ❌ | 文件树 / FileTree | 保留给内部数据结构（`FileTreeNode`） |
| ❌ | 侧边栏 / Sidebar | 指位置不指功能，右侧大纲也是侧边栏 |
| ❌ | 工作区 / Workspace | 本项目**没有**工作区概念（[OUT-104](../01-需求规格说明.md)） |

### 资源管理器根 · ExplorerRoot
目录树当前的根目录，**同一时刻只有一个**。

行为是**纯跟随**：切 tab 时自动变为「当前 tab 文件的父目录」。用户手动「打开文件夹」也会设置它，但之后一旦切 tab 就会被覆盖——这是[刻意的设计](05-ADR/ADR-007-资源管理器语义.md)。

### 定位 · Reveal
在目录树中展开到某个文件并高亮它。切 tab 时自动触发。

## E. 主题与排版

### 主题 · Theme
一整套配色。三个：

| id | 中文名 | 明暗 | 性格 |
|---|---|---|---|
| `chen-guang` | 晨光 | 亮 | 清白底 + 蓝色强调 |
| `hu-po` | 琥珀 | 亮 | 暖象牙底 + 陶土强调 |
| `mo-ye` | 墨夜 | 暗 | 深蓝底 + 亮蓝强调 |

> id 沿用 TMD 的拼音命名，便于对照移植其 CSS。

### 主题模式 · ThemeMode
用户的选择方式：`chen-guang` / `hu-po` / `mo-ye` / `system`。

选 `system` 时，由两个独立设置决定实际主题：`systemLightTheme`（默认 `chen-guang`）与 `systemDarkTheme`（默认 `mo-ye`）。

### 设计令牌 · Token
一个 CSS 自定义属性，如 `--code-inline-bg`。分三层：

| 层 | 命名 | 例子 | 说明 |
|---|---|---|---|
| **色板层** | `--primary-*` `--accent-*` | `--accent-500` | 原始色阶，不直接用于组件 |
| **语义层** | `--editor-*` `--code-*` `--hljs-*` | `--editor-text` | 表达用途 |
| **组件层** | `--tab-*` `--explorer-*` `--cm-*` | `--tab-active-bg` | 绑定具体组件 |

**组件只允许消费语义层与组件层，禁止直接引用色板层。**

### 强调色 · Accent
主题的身份色（晨光 `#3b82f6`、琥珀 `#D97757`、墨夜 `#60a5fa`）。用于装饰性大面积着色与选区染色。

### 强调色·加强 · AccentStrong
从 Accent 加深而来，**专用于需要满足 3:1 对比度的功能性指示**：未保存圆点、tab 激活指示条、焦点环。

> 引入这一层是因为琥珀的陶土色 `#D97757` 只有 2.83:1，直接用作指示器不达标。详见 [ADR-009](05-ADR/ADR-009-主题Token体系与无障碍基线.md)。

### 语法高亮令牌 · HljsToken
形如 `--hljs-keyword` 的 15 个变量，**同时驱动两处**：

1. Markdown 代码块（lowlight 生成 `.hljs-*` 类名）
2. 代码编辑器（CodeMirror `HighlightStyle` 映射到同名变量）

> 这个统一是刻意的：一套颜色，两个内核，改一处两边同时生效。

### 排版设置 · Typography
四项独立设置：字体族（正文 / 等宽分开）、字号（正文 / 等宽分开）、行高、内容宽度。

## F. 画板

### 画板 · Board
`.excalidraw` 文件及其编辑器。

| | 禁用叫法 | 原因 |
|---|---|---|
| ❌ | 画布 / Canvas | `Canvas` 保留给 HTML `<canvas>` 元素与 Excalidraw 内部概念 |
| ❌ | 白板 / Whiteboard | 暗示协作 |

### 图元 · Element
画板上的一个绘图对象。沿用 Excalidraw 的 `ExcalidrawElement` 类型，**不自定义**。

### 画板视口 · BoardViewport
`{ scrollX, scrollY, zoom }`。属于 ViewState 的一部分，切 tab 与迁移窗口时必须保住。

## G. 交互控件

### 折叠把手 · RailToggle
编辑区左右边缘垂直居中的悬浮箭头按钮。平时低透明度，鼠标靠近时显现。

- **左把手**：开合资源管理器。始终存在。
- **右把手**：开合大纲。**仅 Markdown 文档显示。**

| | 禁用叫法 | 原因 |
|---|---|---|
| ❌ | 折叠按钮 / CollapseButton | 它同时管展开与收起 |

### 块把手 · BlockHandle
Markdown visual 模式下段落左侧悬浮的六点（`⠿`）手柄，按住可拖动整块调整顺序。

> 用户原话是「行前八个点」。视觉上是 2×3 或 2×4 点阵，实现取决于 `@tiptap/extension-drag-handle`。文档统一叫「块把手」。

### 斜杠命令 · SlashCommand
在 visual 模式输入 `/` 触发的插入菜单。

### 浮层菜单 · BubbleMenu
选中文本时浮出的格式工具条。
