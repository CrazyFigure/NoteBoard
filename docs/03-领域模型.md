# NoteBoard 领域模型

> 术语一律以 [术语表](02-术语表.md) 为准。本文定义实体、状态机、不变式，以及 **Rust 侧与前端的所有权边界**。
> 这份文档的作用是：**当两个模块对同一份数据的理解不一致时，以此为裁决依据。**

---

## 1. 全局视图

```
┌─────────────────────────────────────────────────────────────────────┐
│  Rust 进程（唯一，单实例）                                            │
│                                                                     │
│   AppState  ── 权威所有者 ──┐                                        │
│   ├─ documents: Map<DocumentKey, DocumentRecord>   ← 文档注册表      │
│   ├─ windows:   Map<WindowLabel, WindowRecord>     ← 窗口注册表      │
│   ├─ intents:   Map<WindowLabel, WindowIntent>     ← 待取意图        │
│   └─ nextWindowSeq: u32                            ← 单调序号        │
│                                                                     │
│   持有：文件系统真相、窗口生命周期、跨窗口唯一性约束                    │
│   不持有：文档内容、撤销栈、光标位置                                   │
└──────────────┬──────────────────────────────┬───────────────────────┘
               │ IPC (command + event)        │
        ┌──────┴───────┐              ┌───────┴──────┐
        │ WebviewWindow│              │ WebviewWindow│   … 任意多个
        │   nb-main    │              │    nb-2      │
        │              │              │              │
        │ WindowStore  │              │ WindowStore  │  ← 每窗口独立
        │ ├─ tabs[]    │              │ ├─ tabs[]    │
        │ ├─ activeTab │              │ ├─ activeTab │
        │ ├─ explorer  │              │ ├─ explorer  │
        │ └─ layout    │              │ └─ layout    │
        │              │              │              │
        │ DocumentStore│              │ DocumentStore│  ← 内容与编辑态
        │ └─ content   │              │ └─ content   │
        │    viewState │              │    viewState │
        │    undo stack│              │    undo stack│
        └──────────────┘              └──────────────┘

        SettingsStore（主题/排版）—— 前端持有，Rust 负责落盘与广播
```

### 1.1 所有权边界（最重要的一张表）

| 数据 | 权威所有者 | 理由 |
|---|---|---|
| 「哪些文件已打开、在哪个窗口」 | **Rust** | 跨窗口唯一性（FR-608）只能在共享层裁决 |
| 「窗口有哪些、label 是什么」 | **Rust** | 窗口是 OS 资源 |
| 「新窗口该打开什么」 | **Rust** | 建窗与前端挂载有时序差，必须由 Rust 暂存 |
| 文件内容（磁盘） | **Rust** | 所有 I/O 走 Rust，前端不直接碰文件系统 |
| 文档内容（内存缓冲） | **前端** | 编辑器内核持有，搬到 Rust 只会增加拷贝 |
| 撤销栈 / 光标 / 滚动 | **前端** | 编辑器内核内部状态，无法序列化 |
| tab 顺序、激活 tab | **前端**（每窗口） | 纯 UI 状态 |
| 资源管理器根与展开状态 | **前端**（每窗口） | 纯 UI 状态 |
| 面板折叠与宽度 | **前端**（每窗口），Rust 落盘 | |
| 主题与排版设置 | **前端**（全局单例），Rust 落盘 + 广播 | 必须所有窗口一致（FR-1004） |

**推论：Rust 不知道文档内容，所以「未保存内容随窗口迁移」（FR-606）必须由前端把内容传过去。** 这条约束贯穿整个设计。

## 2. 实体

### 2.1 DocumentKey — 文档身份

```ts
/** 规范化的绝对路径，或未落盘文档的临时键 */
type DocumentKey = string;   // 'C:\notes\a.md' | 'untitled:3'

/** 规范化：绝对化 → 分隔符统一为 \ → 解析 . 与 .. → 盘符大写 */
function normalizeKey(p: string): DocumentKey;

/** 比较：Windows 语义，不区分大小写 */
function sameKey(a: DocumentKey, b: DocumentKey): boolean;
```

**不变式 I-1**：`documents` 中不存在两个 `sameKey` 为真的键。
**不变式 I-2**：`untitled:N` 中的 `N` 单调递增，进程生命周期内不复用。

> ⚠️ 陷阱：Windows 路径大小写不敏感但**保留**大小写。`C:\Notes\A.md` 与 `c:\notes\a.md` 是同一个文件。所有查找必须走 `sameKey`，禁止用 `===` 或 `Map.get` 直接比较原始路径。实现上用小写路径作 Map 的键，值里存原始大小写。

### 2.2 DocumentRecord — Rust 侧的文档登记

```rust
pub struct DocumentRecord {
    pub key: DocumentKey,            // 规范化路径（原始大小写）
    pub kind: DocumentKind,
    pub owner_window: WindowLabel,   // 当前归属哪个窗口
    pub disk_mtime: Option<i64>,     // 上次由本应用读/写时的 mtime，用于外部变更检测
    pub disk_size: Option<u64>,
    pub encoding: Encoding,          // Utf8 | Utf8Bom | Gbk
    pub eol: Eol,                    // Crlf | Lf
    pub is_dirty: bool,              // 前端上报，Rust 仅缓存以便退出时统一拦截
}
```

**不变式 I-3**：`owner_window` 必须存在于 `windows` 中。窗口关闭时，其名下所有 `DocumentRecord` 必须被移除或改归属。

### 2.3 Document — 前端侧的文档

```ts
interface Document {
  key: DocumentKey;
  kind: DocumentKind;
  language: LanguageId;             // 仅 kind === 'code' 时有意义
  displayName: string;              // 文件名（含扩展名）
  dirPath: string;                  // 父目录绝对路径，供资源管理器跟随用

  /** 内容。三种 kind 的载荷类型不同 */
  content: DocumentContent;

  savePolicy: SavePolicy;           // 由 kind 推导，只读
  isDirty: boolean;
  encoding: Encoding;
  eol: Eol;

  viewMode: ViewMode;               // 仅 markdown 有意义，按文档记忆
  viewState: ViewState;

  /** 外部变更标记 */
  externalChange: ExternalChange | null;
  /** 文件已被删除，保存需走另存为 */
  isDetached: boolean;
  /** 大文档判定结果，打开时算一次 */
  largeDoc: LargeDocVerdict | null;
}

type DocumentContent =
  | { kind: 'markdown'; text: string }
  | { kind: 'code';     text: string }
  | { kind: 'board';    scene: ExcalidrawScene };

interface ViewState {
  /** 文本类：光标偏移与选区；画板类：null */
  selection: { anchor: number; head: number } | null;
  scrollTop: number;
  /** 画板视口 */
  boardViewport: { scrollX: number; scrollY: number; zoom: number } | null;
  /** 代码编辑器折叠区间 */
  foldedRanges: Array<{ from: number; to: number }>;
}

interface LargeDocVerdict {
  isLarge: boolean;
  chars: number;
  lines: number;
  heavyNodes: number;
  /** 命中了哪个阈值，用于给用户提示 */
  trigger: 'chars' | 'lines' | 'heavyNodes' | null;
}
```

**不变式 I-4**：`savePolicy` 由 `kind` 唯一决定，任何代码路径都不得覆盖它。
**不变式 I-5**：`content.kind === document.kind` 恒成立。

### 2.4 Tab — 窗口内的文档引用

```ts
interface Tab {
  id: TabId;                 // 窗口内唯一，形如 't7'，仅用于 React key 与拖拽排序
  documentKey: DocumentKey;   // 指向文档
  /** 预览态 tab（单击树节点打开）会在打开下一个文件时被复用；双击或编辑后转为固定 */
  isPinned: boolean;
}
```

**不变式 I-6**：同一窗口内不存在两个 `documentKey` 相同的 tab。
**不变式 I-7**：每个 `Tab.documentKey` 必须在本窗口的 `DocumentStore` 中有对应 `Document`。

> **为什么 Tab 与 Document 分开？** 因为「关闭 tab」和「卸载文档」是两件事：关闭 tab 时如果文档是脏的手动保存类，要先拦截；而窗口迁移（FR-606）时文档要跨窗口存活，tab 却要在源窗口消失。

### 2.5 WindowRecord — Rust 侧的窗口登记

```rust
pub struct WindowRecord {
    pub label: WindowLabel,       // 'nb-main' | 'nb-2' | …
    pub seq: u32,                 // 单调序号
    pub is_ready: bool,           // 前端已挂载并完成握手
    pub last_active_at: i64,      // 用于 FR-111「最后活跃的窗口」
}
```

**不变式 I-8**：`windows` 非空（至少一个窗口存活），否则进程应退出。
**不变式 I-9**：`label` 全局唯一且永不复用。

### 2.6 WindowIntent — 建窗时的初始任务

```rust
pub enum WindowIntent {
    /** 空窗口（Ctrl+Shift+N） */
    Empty,
    /** 打开这些文件 */
    OpenFiles { paths: Vec<PathBuf> },
    /** 从别的窗口迁移过来的文档（FR-606），含未保存内容 */
    AdoptDocuments { docs: Vec<TransferredDocument> },
}

pub struct TransferredDocument {
    pub key: DocumentKey,
    /** 未保存内容。None 表示磁盘上就是最新的，新窗口自己读盘即可 */
    pub content: Option<String>,
    pub board_scene: Option<serde_json::Value>,
    pub is_dirty: bool,
    pub view_mode: Option<ViewMode>,
    pub view_state: serde_json::Value,
}
```

**关键设计：拉取模型（Pull Handoff）**

```
① 源窗口                     ② Rust                        ③ 新窗口
   │                            │                              │
   ├─ open_in_new_window ──────►│                              │
   │    (含未保存内容)           ├─ intents[nb-7] = intent      │
   │                            ├─ WebviewWindowBuilder        │
   │                            │    .label("nb-7").build()    │
   │                            │         （另起线程，见下）     ├─ 前端挂载完成
   │                            │                              ├─ take_window_intent()
   │                            │◄─────────────────────────────┤
   │                            ├─ intents.remove("nb-7") ────►│ 拿到 intent
   │◄─ 确认已交接 ───────────────┤                              ├─ 恢复内容与 ViewState
   ├─ 移除本地 tab 与 Document   │                              │
```

**为什么不用「建窗后 emit 事件」**：新窗口的前端在 `build()` 返回时还没执行任何 JS，`emit` 出去的事件没有监听者，直接丢失。这是 Tauri 多窗口最常见的 bug。拉取模型把时序主动权交给新窗口，不存在竞态。

**不变式 I-10**：源窗口**必须等到 Rust 确认交接完成**才移除本地 tab。若新窗口创建失败，源窗口保持原状并提示错误。**在此期间文档在源窗口仍完整可编辑。**

> 🔴 **实现红线**：`WebviewWindowBuilder::build()` 在同步 command 或事件回调中调用会在 Windows 上死锁（wry#583）。必须用 `async fn` command 或 `std::thread::spawn`。**single-instance 回调里建窗尤其危险**——它运行在 `WM_COPYDATA` 同步窗口过程里，同时命中两个条件。

## 3. 状态机

### 3.1 Document 生命周期

```
                    ┌──────────────────────────────────────┐
                    │                                      │
  [请求打开] ──► Loading ──► Clean ◄────── 保存成功 ─────── Dirty
                    │          │                            ▲ │
                    │          │  编辑（含首次输入）───────────┘ │
                 失败│          │                              │
                    ▼          │  ┌── 外部修改 ──► ExternalConflict
                  Error        │  │                    │   │
                               │  │      重新加载 ◄────┘   └──► 保留我的版本
                               │  │          │                      │
                               │  └──────────┘                      ▼
                               │                                  Dirty
                               │
                               ├── 外部删除 ──► Detached ──► 另存为 ──► Clean
                               │
                               └── 卸载 ──► (移除)
```

状态定义：

| 状态 | 含义 | tab 圆点 | 可编辑 |
|---|---|---|---|
| `Loading` | 正在读盘 | 无（显示骨架屏） | ✗ |
| `Error` | 读取失败 | 无（显示错误页） | ✗ |
| `Clean` | 与磁盘一致 | 无 | ✓ |
| `Dirty` | 与磁盘不一致 | **手动策略：实心圆点**；自动策略：无 | ✓ |
| `ExternalConflict` | 磁盘被外部改动，且本地也有改动或需用户确认 | 感叹号图标 | ✓ |
| `Detached` | 磁盘文件已被删除 | 断链图标 | ✓ |

**转换规则**：

| 触发 | 前置状态 | 后置状态 | 副作用 |
|---|---|---|---|
| 打开请求 | — | `Loading` | Rust 登记 DocumentRecord |
| 读盘成功 | `Loading` | `Clean` | 记录 mtime/size/encoding/eol；跑大文档判定 |
| 读盘失败 | `Loading` | `Error` | 显示原因，tab 保留（可重试） |
| 内容变更 | `Clean` | `Dirty` | 自动策略：起 800ms 防抖定时器 |
| 防抖到期 / 失焦 / 切 tab / 关闭前 | `Dirty`（auto） | `Clean` | 原子写盘 |
| `Ctrl+S` | `Dirty`（manual） | `Clean` | 原子写盘 |
| 写盘失败 | `Dirty` | `Dirty` | **保留内容**，弹错误（NFR-301） |
| 监听到外部 modify | `Clean` | `Clean` | **自动重新加载**（本地无改动，无冲突） |
| 监听到外部 modify | `Dirty` | `ExternalConflict` | 提示二选一 |
| 监听到外部 delete | 任意 | `Detached` | tab 保留内容 |

> **注意 `Clean` + 外部 modify 的处理**：本地没改动时**静默重新加载**，不打扰用户。这是记事本替代品该有的行为——你在外面用别的工具改了文件，切回来看到的应该是新内容。

### 3.2 Tab 关闭流程

```
[关闭 tab 请求]
      │
      ├─ 文档非 Dirty ─────────────────────────────► 直接关闭
      │
      ├─ Dirty 且 savePolicy === 'auto' ──► 立即写盘 ──► 关闭
      │                                       │
      │                                    写盘失败 ──► 弹错误，取消关闭
      │
      └─ Dirty 且 savePolicy === 'manual'
            │
            └─► 弹拦截对话框
                  ├─ 保存    ──► 写盘 ──► 关闭（失败则取消）
                  ├─ 不保存  ──► 关闭（丢弃）
                  └─ 取消    ──► 什么都不做
```

**不变式 I-11**：`savePolicy === 'manual'` 且 `Dirty` 的文档，**绝不允许在没有用户明确选择的情况下丢弃内容**。

### 3.3 窗口关闭流程

```
[窗口关闭请求 / tauri://close-requested]
      │
      ├─ preventDefault()  ← 先无条件阻止
      │
      ├─ 收集本窗口所有 manual + Dirty 的文档
      │
      ├─ 为空 ──► 写会话快照 ──► 通知 Rust 注销窗口 ──► 真正 close()
      │
      └─ 非空 ──► 弹批量拦截对话框（逐文件列出，带全选）
                  ├─ 保存选中并关闭 ──► 逐个写盘 ──► close()
                  ├─ 全部不保存      ──► close()
                  └─ 取消            ──► 保持窗口
```

**不变式 I-12**：最后一个窗口关闭 = 应用退出。退出前必须完成会话快照写入与草稿清理。

### 3.4 ViewMode 切换（仅 Markdown）

```
  visual ──────────────────┐
    ▲                      │  ① 抓取 ViewState（光标/滚动）
    │                      │  ② TipTap doc → Markdown 文本（序列化）
    │                      ▼
    │                  [Markdown 文本]
    │                      │
    │                      │  ③ 装载进 CM6
    │                      │  ④ 光标偏移映射：PM position → 字符偏移
    │                      ▼
    └──────────────────  source
        ① 抓取 ViewState
        ② CM6 文本（就是 Markdown 原文，无需转换）
        ③ Markdown 文本 → TipTap doc（解析）
        ④ 字符偏移 → PM position
```

**不变式 I-13**：`visual → source → visual` 往返后，Markdown 文本必须与原文语义等价。序列化不稳定的构造（如非标准 HTML 块）必须在往返测试中被覆盖。

**不变式 I-14**：切换模式**不产生 Dirty**。如果序列化结果与磁盘内容不同，说明序列化有损，这是 bug，不是用户改动。

> ⚠️ 这条不变式很容易被违反：TipTap 的 Markdown 序列化会规范化空格、列表标记、强调符号。如果打开一个文件、切一次模式就变脏，用户会以为软件在偷偷改他的文件。**处理办法**：进入 visual 模式时记录「规范化后的基线文本」，脏判定与基线比较而非与磁盘原文比较；`Ctrl+S` 时若内容等于基线则跳过写盘。

### 3.5 大文档判定与降级

```
[读盘完成]
    │
    ├─ 单趟 charCodeAt 扫描（不建 AST）
    │    · 字符数 > 200,000 ？
    │    · 行数 > 4,000 ？
    │    · 重节点数 > 160 ？（统计 ![ 、``` 、~~~ 、$$ 、\( 、\[ 、<img）
    │
    ├─ 全部未命中 ──► 正常 visual 模式
    │
    └─ 任一命中 ──► 以 source 模式打开 + 顶部横幅
                     「这是一个大文档（{n} 字符），已用源码模式打开以保证流畅。
                      〔仍要使用可视化编辑〕」
                          │
                          └─► 用户点击 ──► 分段虚拟滚动模式（NFR-203）
```

**不变式 I-15**：大文档判定必须是 O(n) 单趟扫描且提前 return，不得先解析 Markdown。

## 4. 聚合与关系

```
AppState (Rust)
 ├── 1..* WindowRecord
 │         └── 0..* DocumentRecord   (owner_window 外键)
 └── 0..* WindowIntent               (label 外键，取走即删)

WindowStore (前端，每窗口一个)
 ├── 0..* Tab              ──引用──► Document (documentKey)
 ├── 1    ExplorerState
 └── 1    LayoutState

DocumentStore (前端，每窗口一个)
 └── 0..* Document
            ├── 1 DocumentContent
            ├── 1 ViewState
            └── 0..1 LargeDocVerdict

SettingsStore (前端，全局单例，跨窗口同步)
 ├── 1 ThemeSettings
 └── 1 TypographySettings
```

### 4.1 ExplorerState

```ts
interface ExplorerState {
  /** 当前根，纯跟随语义：切 tab 时被覆盖 */
  root: string | null;
  /** 展开的目录集合。root 变化时清空 */
  expanded: Set<string>;
  /** 高亮定位的文件 */
  revealed: DocumentKey | null;
  /** 已加载的树节点缓存，key 为目录绝对路径 */
  children: Map<string, FileTreeNode[]>;
  showHidden: boolean;
}

interface FileTreeNode {
  path: string;
  name: string;
  isDir: boolean;
  /** 仅文件有 */
  kind?: DocumentKind;
  size?: number;
  mtime?: number;
}
```

**不变式 I-16**：`root` 变化时必须清空 `expanded` 与 `children`。否则会显示上一棵树的残留节点。

**纯跟随的精确规则**（FR-702）：

```ts
// 激活 tab 变化时
function onActiveTabChanged(doc: Document) {
  const newRoot = doc.dirPath;
  if (!sameKey(explorer.root, newRoot)) {
    explorer.root = newRoot;
    explorer.expanded.clear();
    explorer.children.clear();
  }
  explorer.revealed = doc.key;   // 无论 root 是否变化都要重新定位
}
```

> 注意：切到同目录的另一个文件时 **root 不变**，只更新 `revealed`，展开状态保留。只有跨目录才重建。这是「纯跟随」在体验上唯一的缓冲。

### 4.2 LayoutState

```ts
interface LayoutState {
  explorerVisible: boolean;      // 默认 true
  explorerWidth: number;         // 180–480，默认 260
  outlineVisible: boolean;       // 默认 true
  outlineWidth: number;          // 200–480，默认 280
  statusBarVisible: boolean;     // 默认 true
}
```

**不变式 I-17**：大纲面板只在 `activeDocument.kind === 'markdown'` 时渲染。`outlineVisible` 为 true 但当前是画板时，**不渲染面板也不渲染右侧把手**，但保留设置值——切回 Markdown 时恢复。

## 5. 跨窗口不变式

这几条是最容易出 bug 的地方，全部需要专门的测试覆盖：

| 编号 | 不变式 | 违反后的症状 |
|---|---|---|
| **X-1** | 同一 `DocumentKey` 在所有窗口中最多存在一个 `Document` 实例 | 两个窗口编辑同一文件，互相覆盖 |
| **X-2** | 打开已在别处打开的文件 → 聚焦那个窗口的那个 tab，不新建 | 同上 |
| **X-3** | 主题与排版设置在所有窗口视觉一致 | 窗口间外观不一致 |
| **X-4** | 文档迁移（FR-606）过程中，内容在源窗口与新窗口**至少一处**完整存在 | 迁移中途失败导致内容丢失 |
| **X-5** | 任一窗口崩溃，其他窗口的文档不受影响 | 连带丢数据 |
| **X-6** | Rust 的 `documents` 与各窗口 `DocumentStore` 的并集一致 | 幽灵文档：Rust 认为开着，界面上找不到 |
| **X-7** | 窗口关闭后，Rust 中其名下 `DocumentRecord` 全部清理 | 之后无法再打开那个文件（被判定为「已在别处打开」） |

**X-6 的保障手段**：前端每次增删 Document 都必须向 Rust 上报；Rust 侧提供 `reconcile_documents(label, keys[])` 命令，前端在窗口 ready 时与定期（30s）调用一次做对账，发现不一致以前端为准修正 Rust。

## 6. 事件契约

### 6.1 Rust → 前端

| 事件名 | 投递范围 | 载荷 | 触发时机 |
|---|---|---|---|
| `nb://open-files` | `emit_to(label)` | `{ paths: string[] }` | 单实例转发（FR-110/111） |
| `nb://external-change` | `emit_to(owner)` | `{ key, changeType, mtime, size }` | 文件监听命中 |
| `nb://explorer-refresh` | `emit_to(label)` | `{ dir: string }` | 目录内容变化 |
| `nb://explorer-rescan` | `emit_to(label)` | `{ root: string }` | 监听溢出（`Flag::Rescan`），需全量重扫 |
| `nb://settings-changed` | `emit` **广播** | `Settings` 全量 | 任一窗口改了设置（FR-1004） |
| `nb://focus-tab` | `emit_to(label)` | `{ key }` | X-2 场景：让目标窗口聚焦某 tab |
| `nb://before-quit` | `emit` **广播** | `{}` | 应用即将退出，各窗口做最后落盘 |

> ⚠️ **Tauri v2 陷阱**：在 `Window` 实例上调 `.emit()` **也是广播**（与 v1 相反）。定向必须显式用 `emit_to(label, ...)`。所有代码审查都要检查这一点。

### 6.2 前端 → Rust（命令）

| 命令 | 签名 | 说明 |
|---|---|---|
| `window_ready` | `(label) -> WindowIntent` | 握手 + 取走意图，合并为一次调用 |

| `write_document` | `(path, content, encoding, eol) -> WriteResult` | 原子写入 |

## 7. 值对象

```ts
type DocumentKind = 'markdown' | 'code' | 'board' | 'unsupported';
type LanguageId   = 'markdown' | 'sql' | 'json' | 'yaml' | 'xml' | 'plaintext';
type SavePolicy   = 'auto' | 'manual';
type ViewMode     = 'visual' | 'source';
type Encoding     = 'utf8' | 'utf8-bom' | 'gbk';
type Eol          = 'crlf' | 'lf';
type ThemeId      = 'chen-guang' | 'hu-po' | 'mo-ye';
type ThemeMode    = ThemeId | 'system';
type WindowLabel  = string;   // /^nb-(main|\d+)$/
type TabId        = string;   // /^t\d+$/
```

### 7.1 扩展名 → DocumentKind / LanguageId 映射

**唯一真相源**，前端与 Rust 必须一致（Rust 侧从同一份 JSON 生成）：

```ts
const KIND_BY_EXT: Record<string, { kind: DocumentKind; language: LanguageId }> = {
  // Markdown
  md:        { kind: 'markdown', language: 'markdown' },
  markdown:  { kind: 'markdown', language: 'markdown' },
  // 画板
  excalidraw:{ kind: 'board',    language: 'plaintext' },
  // 点名支持语法高亮的代码类
  sql:       { kind: 'code',     language: 'sql' },
  json:      { kind: 'code',     language: 'json' },
  yaml:      { kind: 'code',     language: 'yaml' },
  yml:       { kind: 'code',     language: 'yaml' },
  xml:       { kind: 'code',     language: 'xml' },
  // 纯文本（无高亮）
  txt:       { kind: 'code',     language: 'plaintext' },
  log:       { kind: 'code',     language: 'plaintext' },
  ini:       { kind: 'code',     language: 'plaintext' },
  conf:      { kind: 'code',     language: 'plaintext' },
  cfg:       { kind: 'code',     language: 'plaintext' },
  env:       { kind: 'code',     language: 'plaintext' },
};

/** 表外的扩展名：探测内容，可解码为 UTF-8 且无 NUL 字节 → code/plaintext，否则 unsupported */
```

**不变式 I-18**：扩展名比较一律小写。`.MD` 与 `.md` 等价。

## 8. 这套模型抵抗的具体故障

| 故障场景 | 由哪条不变式挡住 |
|---|---|
| 两个窗口打开同一文件，交替保存导致内容互相覆盖 | X-1, X-2 |
| 迁移 tab 到新窗口时新窗口建失败，文档凭空消失 | I-10, X-4 |
| 打开文件时路径大小写不同，被当成两个文件 | I-1, I-18 |
| 切一次编辑模式，文件就被标记为已修改，用户以为软件乱改文件 | I-14 |
| 关闭窗口时未保存的 `.sql` 被静默丢弃 | I-11, I-12 |
| 切 tab 后资源管理器显示上一棵树的残留节点 | I-16 |
| 画板 tab 切走再切回来，视口跳回原点 | ViewState.boardViewport |
| 打开 20MB 的日志文件，界面卡死几十秒 | I-15, NFR-201 |
| 窗口关了但 Rust 还以为文件开着，导致再也打不开 | X-7 |
| 改了主题，只有当前窗口变色 | X-3, `nb://settings-changed` 广播 |
| 写盘失败后内容也丢了 | I-11, NFR-301 |
| 新窗口没收到「要打开哪个文件」，起来是个空窗口 | 拉取模型（§2.6） |
