# NoteBoard 风险登记册

> 按「暴露时机 × 后果严重度」排序。每条都有**触发信号**（怎么知道它发生了）与**已定的应对**（不需要临时决策）。

---

## 评级

| 等级 | 含义 |
|---|---|
| 🔴 高 | 会损坏用户数据，或导致某条 P0 需求做不出来 |
| 🟠 中 | 会显著返工或体验打折 |
| 🟡 低 | 有代价但可接受 |

## R-01 🔴 Markdown 序列化往返有损，用户以为软件偷改文件

| | |
|---|---|
| **暴露阶段** | 7 |
| **成因** | `@tiptap/markdown` 序列化会规范化空格、列表标记、强调符号。打开文件切一次模式，内容就与磁盘不同 |
| **后果** | 用户看到「我什么都没做，软件说我改了文件」。在「记事本替代品」定位下是**信任层面的致命伤** |
| **触发信号** | `gate:7` 的不变式 I-14 测试失败；或往返测试的「二次幂等」失败 |
| **应对（已定）** | ① 进 visual 模式时记录**规范化后的基线文本**；② 脏判定与基线比较，不与磁盘原文比较；③ `Ctrl+S` 时内容等于基线则**跳过写盘**；④ 16 个棘手样本的往返测试作为 `gate:7` 硬门 |
| **兜底** | 若某类构造往返必然失真且无法规范化（如内嵌复杂 HTML），则该文件**强制 source 模式**并在状态栏标注原因，不允许进 visual |

## R-02 🔴 分段虚拟滚动的块边界切错，损坏用户文档

| | |
|---|---|
| **暴露阶段** | 11 |
| **成因** | 切点落在代码围栏、表格、frontmatter 内部；或活动段编辑后回写原文时区间算错 |
| **后果** | **直接写坏用户文件**，且可能在用户没察觉时发生 |
| **触发信号** | `gate:11` 的「所有切点合法」断言失败；回写后字节比对不符 |
| **应对（已定）** | ① 切分只在 `markdown-it` 块级 token 边界发生；② 对 4 个样本（200KB/1MB/5MB/50MB）断言**所有**切点，不抽样；③ 回写逻辑单独单元测试：只有被编辑区间变化，其余字节不变 |
| **兜底** | 分段模式下**先做只读**（仅虚拟滚动 + 只读预览），编辑能力延后到回写逻辑通过全部测试后再开启 |

## R-03 🔴 跨窗口迁移中途失败导致内容丢失

| | |
|---|---|
| **暴露阶段** | 6 |
| **成因** | 源窗口移除了 tab，但新窗口建失败或没取到意图 |
| **后果** | 未保存内容凭空消失 |
| **触发信号** | 注入建窗失败的 E2E 用例失败 |
| **应对（已定）** | **不变式 I-10**：源窗口必须等 Rust 确认交接完成才移除本地 tab。建窗失败或 3s 超时 → Rust 回滚 registry 归属 → 源窗口保持原状 + 提示错误。**在此期间文档在源窗口仍完整可编辑** |
| **兜底** | 迁移前先写一份草稿（`drafts/`），迁移成功后删除 |

## R-04 🔴 Windows 建窗死锁

| | |
|---|---|
| **暴露阶段** | 0（验证 B）/ 6 |
| **成因** | `WebviewWindowBuilder::build()` 在同步 command 或事件回调中调用会挂死（wry#583）。**single-instance 回调尤其危险** —— 它运行在 `WM_COPYDATA` 同步窗口过程里，同时命中两个条件 |
| **后果** | 应用整体挂死，用户只能强杀 |
| **触发信号** | 双击文件后应用无响应 |
| **应对（已定）** | 所有建窗路径走 `async fn` command 或 `std::thread::spawn`。阶段 0 验证 B 已用对照组确认理解正确。写成 `window/manager.rs` 顶部注释红线 + code review 检查项 |
| **兜底** | 集成测试专门覆盖 single-instance 回调建窗，带超时保护 |

## R-05 🟠 `dragDropEnabled: false` 下 `dataTransfer.files` 也不可用

| | |
|---|---|
| **暴露阶段** | 0（验证 A） |
| **成因** | [tauri#15138](https://github.com/tauri-apps/tauri/issues/15138) 报告者称在 `false` 下外部文件的 `e.dataTransfer` 是 "blocked/empty" |
| **后果** | FR-104（拖文件入窗）与 FR-313 的拖入部分整条做不了 |
| **触发信号** | 验证 A 打印出 `files.length === 0` |
| **应对（已定）** | **两个分支已预先决定，不需要再问人**：可用 → 实现降级版（读内容 → 未命名文档 → 另存为）；不可用 → 两条需求整条取消并在需求文档标注「已验证不可行」 |
| **为什么可接受** | 用户原话只要求「资源管理器双击/右键打开」与「应用内打开」。拖文件入窗是我自己加的 P1，不是用户点名的 |

## R-06 🟠 note-gen 代码移植时把 AI 逻辑拆坏

| | |
|---|---|
| **暴露阶段** | 7 / 8 |
| **成因** | `tiptap-editor.tsx` 是 229KB 单文件，AI 补全/建议/diff 预览与编辑器逻辑交织 |
| **后果** | 拆出来的编辑器有隐性依赖，运行时报错难定位；或残留死代码 |
| **触发信号** | 移植后出现指向 AI 模块的 import 错误；或 `gate:7`/`gate:8` 大面积失败 |
| **应对（已定）** | **不整文件搬。** 先跑通不含增强的最小扩展集，再逐个加扩展，每加一个跑一次测试。文件头必须写来源块，CI 检查 |

## R-07 🟠 琥珀的暖调语法高亮不被用户接受

| | |
|---|---|
| **暴露阶段** | 15（人工验收） |
| **成因** | 用户说「非常喜欢」TMD 的配色，但 TMD 的琥珀根本没定义 `--hljs-*`，走的是 GitHub 冷调回退。我们自研了一整套暖调（16 处改动之一） |
| **后果** | 用户觉得「这不是我喜欢的那个琥珀」 |
| **触发信号** | 人工验收时反馈 |
| **应对（已定）** | ① [主题规范 §10](06-主题与设计规范.md) 逐条列出了 16 处改动的原值/新值/理由，用户可逐项核对；② 改回 TMD 原值只需改 `globals.css` 里 16 个值，成本约 1 小时；③ 若改回，把对比度 CI 断言从「失败」降为「警告」 |
| **备选** | 提供设置项「代码高亮配色：暖调（推荐）/ GitHub 经典」，让两套并存。成本约 0.5 天 |

## R-08 🟠 「单根纯跟随」在长期使用中变得难受

| | |
|---|---|
| **暴露阶段** | 15 / 上线后 |
| **成因** | 跨目录来回切 tab 时展开状态反复丢失（[ADR-007](05-ADR/ADR-007-资源管理器语义.md) 已明确记录这是唯一代价） |
| **后果** | 频繁跨项目工作的用户会烦 |
| **触发信号** | 用户反馈 |
| **应对（已定）** | 「同目录不重建」的缓冲已覆盖最高频场景。若仍不够，按成本递增顺序：① 加图钉锁定按钮（方案 B，约 0.5 天）；② 加根目录历史后退（方案 C，约 1 天）；③ 改多根并存（方案 A，约 3 天） |
| **注意** | 用户在被追问后**明确选择了「不加控件」**。改动前应再确认一次 |

## R-09 🟠 WebView2 版本差异导致渲染不一致

| | |
|---|---|
| **暴露阶段** | 15 / 上线后 |
| **成因** | Tauri 依赖用户机器上的 WebView2 Runtime，版本不受我们控制 |
| **后果** | 部分用户看到布局错乱或某特性失效 |
| **触发信号** | 用户反馈某功能在他机器上不工作 |
| **应对（已定）** | ① `vite` 的 `build.target: 'chrome105'` 作为基线，不用前沿 API；② 设 `bundle.windows.minimumWebview2Version`；③ 首启动检测版本过低时提示升级 |

## R-10 🟠 `tauri-plugin-fs` 的 watch 在实际使用中漏事件

| | |
|---|---|
| **暴露阶段** | 5 |
| **成因** | notify 的 Windows backend（`ReadDirectoryChangesW`）缓冲区**硬编码 16 KiB 且无配置项**。事件风暴时溢出，转成 `EventKind::Other` + `Flag::Rescan`（不带路径）。此外 fs 插件源码里 `notify::Error` 被直接丢弃（注释 `// TODO: Should errors be emitted too?`），监听中途出错前端收不到 |
| **后果** | 目录树与磁盘不一致，用户看到过期的文件列表 |
| **触发信号** | 外部批量创建文件后树只更新了一部分 |
| **应对（已定）** | ① **必须处理 `Flag::Rescan`**：收到 `nb://explorer-rescan` 就全量重扫（已写进 [架构](04-技术架构设计.md) §4.6）；② 切换资源管理器根时重建监听；③ 网络盘可能完全无事件 → 降级为轮询（NFR-504） |
| **兜底** | 资源管理器顶部提供手动刷新按钮 |

## R-14 🟡 E2E 测试 flaky，拖慢开发节奏

| | |
|---|---|
| **暴露阶段** | 3 起 |
| **成因** | 用固定 `pause` 等待、靠 CSS 类选元素、多窗口句柄切换时序 |
| **后果** | CI 频繁红，团队开始加 `--skip`，测试网失效 —— **这会直接摧毁「连续开发不中途人工测试」这个约定** |
| **应对（已定）** | ① **禁止固定 `pause`**，全部条件等待；② 用 `data-testid`；③ flaky 用例自动重跑 1 次但**标记为 flaky 而非静默通过**；④ 每周汇总，超过 2 次的必须修 |

## R-15 🟡 中文输入法在某个内核里有问题

| | |
|---|---|
| **暴露阶段** | 15 |
| **成因** | ProseMirror / CodeMirror / Excalidraw 三个内核各自处理 IME 组合输入，候选窗定位与 composition 事件行为可能不一致 |
| **后果** | 中文输入体验差（候选窗位置错、组合中的字被吞） |
| **触发信号** | 阶段 15 的 NFR-404 验收 |
| **应对（已定）** | 三个内核各自用微软拼音 + 搜狗测一遍。上游都对 IME 有支持，问题多出在我们自己的 `onKeyDown` 拦截上 → 检查所有键盘事件处理是否正确跳过 `isComposing` |

## 已消除的风险

记录在案，避免有人重新提起：

| 原风险 | 为何消除 |
|---|---|
| **跨窗口拖拽 tab 无先例、估工 4–7 周** | 需求已取消，改右键菜单（[ADR-006](05-ADR/ADR-006-窗口与Tab模型.md)）。这是本项目最大的风险消除 |
| **note-gen 是 GPL，不能抄代码** | 用户选择 NoteBoard 也发 GPL-3.0（[ADR-002](05-ADR/ADR-002-开源协议与代码复用边界.md)），移植合法 |
| **`dragDropEnabled` 与块把手冲突不知怎么选** | 已在源码层查清是硬二选一，并已定 `false`（[ADR-014](05-ADR/ADR-014-拖放机制取舍.md)） |
| **Vditor vs TipTap 选型不定** | 已定 TipTap + CM6（[ADR-003](05-ADR/ADR-003-编辑器内核选型.md)），且 CM6 本来就是代码文件的刚需 |
| **画板引擎不定** | 已定 Excalidraw（[ADR-008](05-ADR/ADR-008-画板引擎与文件格式.md)） |
| **是否需要 SQLite** | 已定不用（[ADR-011](05-ADR/ADR-011-持久化方案.md)），数据量 < 100KB |
| **主题配色对比度不达标** | 已实测全部并给出合规替代值（[主题规范](06-主题与设计规范.md)），且进 CI |
