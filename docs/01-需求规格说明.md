> 最后更新：2026-08-17

本文是 NoteBoard 的需求基准。所有编号（`FR-xxx` / `NFR-xxx` / `OUT-xxx`）在其他文档与代码注释中被直接引用，**编号一经分配不再复用，废弃的需求保留编号并标注「已废弃」**。

## 1. 产品定位

NoteBoard 是一个 **Windows 桌面单机应用**，把三类编辑能力合进一个窗口：

1. Markdown 笔记（所见即所得，Typora 式体验）
2. 代码 / 配置文本文件（真语法高亮）
3. 自由手绘画板

### 1.1 一句话定位

> **一个能当记事本用的笔记软件。**

这句话决定了所有有争议的设计取向：

| 取向 | NoteBoard 的选择 | 与 note-gen 的差别 |
|---|---|---|
| 打开文件的方式 | 双击文件即开，文件是第一公民 | note-gen 需要先建/选工作区 |
| 组织方式 | 就是文件系统本身 | note-gen 有「笔记 / 记录 / 画布」三分类 |
| 窗口 | 多窗口，像记事本 | note-gen 单窗口 |
| 数据归属 | 全在用户自己的目录里 | note-gen 部分资产硬编码在 appDataDir |
| 智能 | 无 | note-gen 核心是 AI |

### 1.2 目标用户与典型场景

单人本地使用，无协作、无账号、无云。三个必须都顺手的场景：

- **S1 写笔记**：新建 `.md`，插公式、画流程图、拖段落调顺序，右侧看大纲。写完不用管保存。
- **S2 改配置**：资源管理器里双击一个 `docker-compose.yml`，改两行，`Ctrl+S`，关窗。要有语法高亮和错误提示。
- **S3 画草图**：新建 `.excalidraw`，画个架构图，和笔记放同一个目录里。

## 2. 功能需求

### 2.1 文件打开与创建（FR-100）

| 编号 | 需求 | 优先级 |
|---|---|---|
| **FR-101** | 从系统资源管理器**双击**已关联的文件类型，用 NoteBoard 打开该文件。 | P0 |

| **FR-103** | 把文件**拖到 NoteBoard.exe 图标上**打开。 | P1 |
| **FR-104** | ⚠️ **已降级**。把文件拖进窗口时，**无法取得真实磁盘路径**（Windows 平台硬约束，见 [ADR-014](05-ADR/ADR-014-拖放机制取舍.md)）。降级行为：读取内容并以「未命名文档」新建 tab，保存时走另存为。**若实测发现 `dataTransfer.files` 在该配置下为空，则本需求整条取消。** | P2 |
| **FR-105** | 应用内 **打开文件**（`Ctrl+O`）：系统文件选择对话框，支持多选，每个文件一个 tab。 | P0 |
| **FR-106** | 应用内 **打开文件夹**（`Ctrl+K Ctrl+O`）：把所选目录设为资源管理器根，**不自动打开任何文件**。 | P0 |
| **FR-107** | 应用内 **新建文件**（`Ctrl+N`）：在当前资源管理器根目录下创建。需要选择类型（Markdown / 文本 / 画板）与文件名。 | P0 |
| **FR-108** | 在资源管理器的目录节点上右键 → 新建文件 / 新建文件夹，在该节点下创建。 | P0 |
| **FR-109** | 冷启动带参数（`NoteBoard.exe "D:\a.md"`）时打开该文件；带目录参数时设为根。 | P0 |
| **FR-110** | **单实例**：应用已在运行时，FR-101/102/103/109 一律**转发给已有实例**，不启动第二个进程。 | P0 |
| **FR-111** | 转发到已有实例时，**在最后活跃的窗口里新开 tab 并把该窗口置前**（不新开窗口）。 | P0 |
| **FR-112** | 打开不存在的路径时给出明确错误提示，不崩溃、不创建空文件。 | P0 |
| **FR-113** | 打开超过 **50 MB** 的文件前弹确认框（继续 / 取消 / 以只读源码模式打开）。 | P1 |
| **FR-114** | 打开二进制文件或非受支持类型时，显示文件信息页（大小、修改时间、路径）+「用系统默认程序打开」「打开所在目录」两个动作，**不尝试渲染内容**。 | P1 |

### 2.2 受支持的文件格式（FR-200）

| 编号 | 需求 | 优先级 |
|---|---|---|
| **FR-201** | **Markdown**：`.md` `.markdown` → Markdown 编辑器（双模式）。 | P0 |
| **FR-202** | **纯文本**：`.txt` → 代码编辑器，无语法高亮。 | P0 |
| **FR-203** | **SQL**：`.sql` → 代码编辑器 + SQL 语法高亮。 | P0 |
| **FR-204** | **JSON**：`.json` → 代码编辑器 + JSON 高亮 + **语法错误提示** + 代码折叠。 | P0 |
| **FR-205** | **YAML**：`.yaml` `.yml` → 代码编辑器 + YAML 高亮 + 语法错误提示 + 折叠。 | P0 |
| **FR-206** | **XML**：`.xml` → 代码编辑器 + XML 高亮 + 标签匹配 + 折叠。 | P0 |
| **FR-207** | **画板**：`.excalidraw` → 画板编辑器。 | P0 |
| **FR-208** | 上述之外的文本类扩展名（`.log` `.ini` `.conf` `.env` 等）→ 代码编辑器，无高亮，仍可正常读写。 | P1 |
| **FR-209** | 未知扩展名但内容是文本（UTF-8 可解码且无 NUL 字节）→ 同 FR-208。 | P2 |
| **FR-210** | 编码支持：读取时自动识别 UTF-8（含 BOM）/ GBK；**保存时保持原编码不变**，并在状态栏显示当前编码。 | P1 |
| **FR-211** | 行尾符支持：识别 CRLF / LF；**保存时保持原行尾符不变**，状态栏显示。新建文件默认 CRLF。 | P1 |

> **范围说明**：语法高亮只做 FR-203~206 点名的四种语言（外加 Markdown）。这是刻意收窄的范围，理由见 [ADR-004](05-ADR/ADR-004-代码类文件的语言支持范围.md)。

## 3. 非功能需求

### 3.1 性能（NFR-100）

| 编号 | 指标 | 目标 |
|---|---|---|
| **NFR-101** | 冷启动到可编辑（打开一个 10KB 的 md） | ≤ 1.5 s |

| **NFR-103** | 新开窗口 | ≤ 800 ms |
| **NFR-104** | 输入延迟（按键到字符上屏），1MB 文档内 | ≤ 32 ms（p95） |
| **NFR-105** | tab 切换 | ≤ 150 ms |
| **NFR-106** | 主题切换 | ≤ 100 ms，无可见闪烁 |
| **NFR-107** | 打开 10MB Markdown 不卡死（可回落源码模式） | 可交互 ≤ 3 s |
| **NFR-108** | 单窗口常驻内存（1 个中等文档） | ≤ 200 MB |
| **NFR-109** | 目录树加载 1000 个条目的目录 | ≤ 500 ms |
| **NFR-110** | 安装包体积 | ≤ 30 MB |

### 3.2 大文档策略（NFR-200）

采用四层机制，逐层生效，详见 [ADR-012](05-ADR/ADR-012-大文档性能策略.md)：

| 编号 | 层 | 内容 |
|---|---|---|
| **NFR-201** | ① 阈值回落 | 超过 200,000 字符 / 4,000 行 / 160 个重节点 → 默认以源码模式打开并提示 |
| **NFR-202** | ② 视口懒渲染 | `IntersectionObserver`（`rootMargin: 800px`）门控代码高亮、KaTeX、Mermaid |
| **NFR-203** | ③ 分段虚拟滚动 | 按块边界切段（目标 24,000 字符/段，上限 64,000），虚拟滚动，同时只有 1 个真编辑器实例 |
| **NFR-204** | ④ Worker 分段 | 分段解析放进 Web Worker，回传时不带原文字符串 |

### 3.3 可靠性（NFR-300）

| 编号 | 需求 |
|---|---|
| **NFR-301** | **绝不静默丢失用户内容。** 任何异常路径下，内存中的编辑内容必须可恢复或有明确提示。 |
| **NFR-302** | 崩溃恢复：非正常退出后重启，提供上次未保存内容的恢复入口（草稿缓存）。 |
| **NFR-303** | 单个 tab 内的渲染错误（Mermaid/KaTeX/画板）不得影响其他 tab 或窗口。 |
| **NFR-304** | 单个窗口崩溃不得导致其他窗口丢失数据。 |
| **NFR-305** | 磁盘写入全部走原子写入（FR-1205）。 |

### 3.4 无障碍与可用性（NFR-400）

| 编号 | 需求 |
|---|---|
| **NFR-401** | 所有正文文字与其背景对比度 ≥ **4.5:1**（WCAG AA）。**含代码块内全部语法高亮 token。** |
| **NFR-402** | 所有功能性图形指示（未保存圆点、tab 指示条、焦点环、边框）对比度 ≥ **3:1**（WCAG 1.4.11）。 |
| **NFR-403** | 全部主要功能可纯键盘操作，焦点顺序合理，焦点环可见。 |
| **NFR-404** | 中文输入法（微软拼音 / 搜狗）在两种编辑器内正常工作，包括候选窗定位与组合输入。 |
| **NFR-405** | 界面文案全中文，无未翻译的英文残留。 |
| **NFR-406** | 支持 Windows 显示缩放 100%/125%/150%/175%/200%，含多显示器混合缩放。 |

### 3.5 兼容性（NFR-500）

| 编号 | 需求 |
|---|---|
| **NFR-501** | Windows 10 1809 (17763) 及以上，x64。 |

| **NFR-503** | 路径支持中文、空格、`#`、`&` 等特殊字符；支持长路径（≥260 字符）。 |

### 3.6 安全（NFR-600）

|---|---|
| **NFR-601** | 无任何网络请求。应用完全离线可用。**唯一例外**：用户主动点击「检查更新」。 |

## 4. 明确的范围外

以下内容**不做**，且在实现中要主动抵抗范围蔓延：

| 编号 | 不做什么 | 理由 |
|---|---|---|
| **OUT-101** | 一切 AI 功能（AI 写作、AI 问答、截图转笔记、向量检索、RAG） | note-gen 的核心，但与「记事本替代品」定位冲突；引入后需要联网与密钥管理，破坏 NFR-601 |
| **OUT-102** | 云同步 / WebDAV / Git 同步 / 多端 | 单机应用 |
| **OUT-103** | 账号、登录、订阅 | 同上 |
| **OUT-104** | 「工作区」概念、笔记库、强制目录结构 | 与 FR-701「单根纯跟随」冲突 |
| **OUT-105** | 「笔记 / 记录 / 画布」三分类导航 | 用户明确要求混排（FR-703） |
| **OUT-106** | 网页剪藏、OCR、截图 | 范围外 |
| **OUT-107** | 插件系统 | 首个版本不做 |
| **OUT-108** | 跨窗口拖拽 tab | 见 FR-613 / [ADR-006](05-ADR/ADR-006-窗口与Tab模型.md) |
| **OUT-109** | 分栏预览（编辑与预览左右对照） | 双模式已覆盖需求，见 [ADR-003](05-ADR/ADR-003-编辑器内核选型.md) |
| **OUT-110** | 结构化图表画板（流程图/思维导图/看板节点图） | 画板定位为自由手绘白板（Excalidraw），非 note-gen 的 React Flow 节点图 |
| **OUT-111** | macOS / Linux 支持 | 首个版本仅 Windows。但代码中不刻意写死平台假设。 |
| **OUT-112** | 多语言界面 | 仅简体中文 |
| **OUT-113** | 打印 / 导出 PDF | 首个版本不做（导出 PNG/SVG 见 FR-508） |
| **OUT-114** | 数据库（SQLite） | 元数据量小，JSON 文件足够，见 [ADR-011](05-ADR/ADR-011-持久化方案.md) |
| **OUT-115** | 脚注 `[^1]` | note-gen 也不支持；优先级低，留待后续 |
| **OUT-116** | 协同编辑 | 单机应用 |
