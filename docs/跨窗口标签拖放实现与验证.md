# 跨窗口标签拖放

## 实现范围

- 标签栏内保留原有排序；鼠标越出标签栏 8px 后接入系统拖放，减少水平排序时误拆窗。
- 在应用窗口外松手创建新窗口；拖到其他 NoteBoard 窗口合并，标签栏按落点插入，正文区域追加。
- 拖走最后一个标签后关闭空源窗口；取消、目标关闭或迁移失败时保留源内容。
- 覆盖普通文本、Markdown、图表、图片、插件只读查看、懒恢复标签和文本对比工具。
- 保留正文、磁盘基线、脏态、编码/换行、撤销历史及已有编辑器能够捕获的视图状态。文本对比通过专用内存快照交接两侧文本、历史、选区及视图选项。
- 网页端和移动端保持原有窗口内排序，不调用桌面多窗口接口。

## 技术路线

跨窗口手势不能仅依靠 DOM 排序或全局窗口坐标：Tauri 的原生文件拖放会接管系统事件，Wayland 也不提供通用全局定位能力。实现采用系统拖放识别实际目标，再复用既有 transferId 文档交接协议。

1. 系统拖动只携带随机临时票据；名称摘要用于界面反馈，正文不广播。
2. Windows 使用 OLE，松手时仅向本进程窗口投递；macOS 使用 AppKit，限制为应用内接收。保留在 `src-tauri/vendor/drag` 的上游 2.1.1 源码和许可证，仅作所需原生适配。
3. Linux 使用 GTK 私有 MIME 和局部坐标；从真实鼠标移动事件取得 Wayland 输入串行号。原有文件 URI 拖放继续独立工作，不向外部应用提供标签票据的文件 URI。
4. 源进入迁移保护，结束组合输入、flush 权威正文并排空既有保存；准备期间不接纳新的自动保存。
5. 目标建立保护中的标签并确认接管；只有后端 committed 后源才移除数据。未知终态继续保留数据、锁定并对账。
6. 新窗口启动或已有窗口重新加载时补拉待接收记录，避免仅依靠唤醒事件。

Windows 的新窗位置按物理像素处理，macOS 按逻辑点处理并修正 Retina 的纵坐标换算。Linux 新窗位置由窗口管理器或合成器分配，不承诺与 Edge 完全相同。

## 界面反馈

跟随鼠标的主题标签卡片、源标签淡出、目标窗口描边、插入位置线和接收标签短入场动画。窗口内排序的布局、尺寸和滚动保持原样；系统减少动画设置会关闭新增过渡。

Windows 的 `DoDragDrop` 会同步运行嵌套消息循环。若直接在 Tauri 的主线程任务回调中启动，Tao 0.35.3 会缓存重入的代理事件，导致接收窗口直到松手才显示反馈。现在通过一次性 Win32 计时器从独立原生消息回合启动，先归还 Tao 事件处理器，使悬停事件和票据识别 IPC 在拖动期间实时处理。计时器回调先清除自身，再启动原有拖放；启动失败仍保留源标签。macOS 的异步 AppKit 会话和 Linux 的真实鼠标事件启动方式保持不变。

## 磁盘变更误报修复

干净文档也必须恢复原磁盘基线，不能以编辑器规范化后的 LF 快照替代原文；交接前排空源保存，防止目标把源的迟到保存识别为外部修改。磁盘核对按与脏态一致的换行归一规则比较，迁移完成后重新监听，真实文字修改仍会触发冲突保护。

## 验证与边界

- 相关前端回归：126 项通过，涵盖迁移终态、失败保留、关闭保护、未保存内容、CRLF 误报、真实外部修改、文本对比的真实 MergeView 撤销恢复及反馈定位。
- Rust：窗口和交接测试 16 项通过，新增真实 Tao 消息循环回归，在同一事件链路对照旧方式的延迟与新方式的实时投递；本地 OLE 适配的应用内/外投递边界测试 2 项通过。
- TypeScript、定向 ESLint、Windows Rust 检查及前端生产构建通过；生产构建保留了原有大体积 chunk 和静态/动态导入提示。
- macOS arm64 原生拖放适配与本地依赖通过交叉类型检查；Linux x86_64 原生模块使用真实 Tauri/GTK Rust API 通过交叉类型检查。未链接对应系统库，未构建或运行这两个平台的完整安装包。
- Windows 基本拆分/合并、磁盘误报修复已由用户手动验证。随后反馈的目标窗口悬停无反馈已修复启动调度并通过事件循环回归；本次最终原生悬停手势尚待用户复测。
- 自动化桌面工具限制拖动终点在源窗口范围内，未据其模拟结果宣称完整跨窗口真机通过。

发布前仍需在 Windows、macOS、Linux X11/Wayland 真机验证：跨显示器/混合缩放、Esc 取消、目标在拖动期间关闭、桌面松手不生成票据文件，以及各类编辑器的视图恢复。
