- 修复 Markdown 编辑器 heading/列表/代码块等格式"改了又失效"的严重 bug。根因双重：
  1. `@tiptap/markdown` 扩展**从未在 `extensions/index.ts` 注册**（package 装了但没 import），导致 `editor.storage.markdown` 为 undefined。
  2. `serialize.ts` 原作者访问了 **错误的 API**：`editor.storage.markdown.getMarkdown()`。`@tiptap/markdown` 实际把 `getMarkdown` 注入到 **Editor 实例**上（通过 `declare module '@tiptap/core'` 的 `interface Editor` 增强），`storage.markdown` 是 `{ manager: MarkdownManager }`，没有 `getMarkdown` 字段。结果永远是 undefined → 静默回退到 `editor.getText()`，所有 markdown 语法丢失。
  - 修复 `extensions/index.ts`：追加 `Markdown` 扩展（放在所有自定义节点之后注册）。
  - 修复 `serialize.ts`：`serializeMarkdown` 改用 `editor.getMarkdown()`；`parseMarkdown` 显式声明 `contentType: 'markdown'`；扩展未注册时 console.error 而非静默回退。
  - 新增 `test/editor-md/serialize-roundtrip.test.tsx`：真实 TipTap Editor 往返集成测试，覆盖 H1/H2/H3、有序/无序列表、代码围栏、粗体/斜体、setext 标题、引用块、分割线。此前 `serialize.test.ts` 只测 BaselineManager 纯逻辑，用 mock 把 serialize 结果当成原样，所以漏挂扩展也能过——这正是 bug 没被拦住的原因。
  - 全套 134 测试通过，无回归。
  - 经验：TipTap 3 的 `@tiptap/markdown`，`getMarkdown` 是 Editor 实例方法，不是 storage 字段。
- 修复上一轮改动引入的回归：点击"新建 MD 文档"整窗白屏。
  - 根因：`parseMarkdown(editor, '')` 走 `setContent('', {contentType:'markdown'})`，`@tiptap/markdown` 的 `parse('')` 返回 `{type:'doc',content:[]}`，违反 doc schema 的 `block+` 约束 → `RangeError: Invalid content for node doc` → React 挂载崩溃白屏。新建文档初始内容正是空串。
  - 修复 `serialize.ts` 的 `parseMarkdown`：空白内容守卫，直接 `editor.commands.clearContent(false)`。
  - 复现方法（jsdom 单测无法复现，vitest 有环境伪影）：esbuild 打包 Node+jsdom 冒烟脚本 `scripts/smoke-editor.ts`（注意 `@sereneinserenade/tiptap-search-and-replace` 需 `--alias` 指到其 ESM dist，否则 interop 报错）。
  - vitest.config.ts：测试模式跳过 `@vitejs/plugin-react`（其对被内联依赖注入 preamble 在 vitest 报 "can't detect preamble"，导致无法测试含 React NodeView 的模块链）；tsconfig `jsx: react-jsx` 下 esbuild 接管 JSX 即可。
  - 回归测试：`serialize-roundtrip.test.tsx` 新增空内容解析用例。全套 135 测试通过。
